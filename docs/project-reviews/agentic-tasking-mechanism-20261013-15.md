# 项目回顾：基于任务池的 AI 编程助理自主协作机制（2026-10-13 至 2026-10-15）

## 1. 项目背景

近两天，作为王二狗（协调器），我尝试协调 atomcode（qwen3.8-27b）和 copilot 两个 AI 编程助理完成代码任务。最初采用“协调器主动派发任务”模式，但在实践中出现了多个问题，随后改进为**任务池 + 执行者自主领取**的机制。

## 2. 问题诊断

### 问题 1：值班系统（duty-tick）未生效
- duty-tick.sh v4 已写好，但 systemd timer 仍在跑 v3 旧版本
- 修复：重启 duty-wang.timer，确认 v4 已加载

### 问题 2：atom session 断开后 pending 队列不继承
- atom 重启后 session 丢失，bridge 有 8+ pending 任务但没人处理
- 新 session 不继承旧 session 的 pending 队列
- 策略：让 atom 完成当前任务后自然消费 pending

### 问题 3：copilot 注入链路不稳定
- copilot-inject.sh 最近多次超时/失败
- bridge 队列积压 10 个 pending 任务
- copilot 会话 57271ae1 被长期占用，注入后无新回执

### 问题 4：任务池规则未触达执行者
- 通知发了，但 atom/copilot 不知道新规则
- 执行者不会主动读任务池
- 修复：通过 bridge 直接发送消息到 atom 新 session，并在 inbox 写明规则

### 问题 5：空闲阈值太激进
- 原 15 分钟改为 3 分钟，但执行中时会被频繁打断
- 修复：改为"执行者'无任务'状态 >3 分钟 → 提醒领任务；'执行中'不计时"

## 3. 机制改进

### 3.1 任务池（TASK_POOL.md）
创建 `.ai/TASK_POOL.md`，包含：
- 执行者状态表（atomcode、copilot）
- 功能包任务池（C-1~C-10）
- 造活区任务池（F-1~F-10，包括测试补课、文档、工具链、技术债、质量扫描）
- 领取规则与报告流程

### 3.2 值班脚本（duty-tick.sh v4）
- 核心：协调器持续造活 → 往任务池加活 → 执行者主动领 → 协调器验收
- 空闲阈值：3 分钟（仅针对"无任务"状态）
- 输出格式：≤15 行极简日志
- 不主动派发（除非执行者空闲 >3 分钟）

### 3.3 新规则确立
| 角色 | 职责 |
|------|------|
| **协调器（我）** | 持续造活 → 往任务池加活 → 验收回执 → 升级阻塞 |
| **执行者（atom/copilot）** | 完成当前 → 读任务池领下一棒 → 写 outbox/ 回执 |
| **高哥（你）** | 只处理"阻塞升级"，其余不打扰 |

## 5. 流程循环（值班 v4）

```
每 3 分钟：
1. 检查执行者状态（active/idle/blocked）
2. 验收 outbox/ 回执
3. 造活：从项目里找新任务加入任务池
4. 执行者无任务 >3 分钟 → 提醒领任务
5. 阻塞 → 升级给高哥
```
