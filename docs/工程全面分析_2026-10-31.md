## 三、大文件红线的处置论证

### 3.1 为什么不能一刀切

红线（>400 行须 `LINES-EXEMPT`）是**防「治理后反弹」的纪律工具**，不是行数 KPI。
但 400 行对两类结构天然不合理：

- **动作分发 + 回调聚合**（`shell.rs`）：99 个 `SHIFT_ACT` 分支、13 个面板注册表、
  三类 CEF 回调（Load/Display/Request），拆开的正确维度是「动作域」而非「行数」，
  且必须先抽 `ShellState` 访问层，属独立工程。
- **单字符串内嵌页**（`toolbar.rs`）：HTML/CSS/JS 是一个字符串，跨文件拼接会让
  「所见即所改」失效，维护成本反而上升。

因此处置原则：**能真拆的真拆，结构性大文件写清理由豁免并登记拆解计划**。

### 3.2 本批次实际拆分（全部经编译/测试验证）

| 文件 | 原 | 现 | 做法 |
|---|---|---|---|
| `engine/cef/shell.rs` | 4968 | 4968 | `LINES-EXEMPT` + 拆解计划（按动作域，需先抽 `ShellState`） |
| `engine/cef/toolbar.rs` | 2416 | 2416 | `LINES-EXEMPT`（单字符串内嵌页） |
| `cef_cmd.rs` | 503 | **389** | 拆出 `cef_cmd/cef_boot.rs`（子进程判定/缓存目录）、`cef_cmd/toolbar_data.rs`（书签/下载 JSON） |
| `engine/cef/newtab.rs` | 495 | **191** | HTML 抽成 `newtab_page.html`，`include_str!` 引入 |
| `engine/cef/browser.rs` | 466 | **388** | 拆出 `browser/browser_inject.rs`（含 4 单测）、`browser/events.rs`、`browser/ops.rs` |
| `db/downloads.rs` | 453 | **256** | 测试外移 `downloads_tests.rs` |
| `app/bootstrap.rs` | 446 | **396** | 拆出 `bootstrap/fatal.rs`、`bootstrap/stdio.rs` |
| `useragent.rs` | 420 | **223** | 测试外移 `useragent_tests.rs` |
| `import_browser/passwords.rs` | 402 | **345** | 测试外移 `passwords_tests.rs` |

**拆测试模块的坑（记录防重犯）**：外移目标文件里**只放模块体**，
不要保留 `#[cfg(test)] mod tests { … }` 外层包裹——否则会变成
`mod tests { mod tests { … } }`，`use super::*` 指向空模块，编译报几十个「找不到符号」。
原文件侧用 `#[cfg(test)] #[path = "xxx_tests.rs"] mod tests;` 引入。

**取舍说明**：`shell.rs` 本轮没拆是**理性克制**，不是偷懒——4968 行里 1148 行是测试，
拆完仍 3820 行，仍要豁免；而真正按域拆需要先把 13 个面板的 setter/push 收敛成
一个 `Panel` trait，改动面覆盖 99 个分支，必须单独排期 + 真机验收。

## 四、P1-5 方案：CEF 路径的 AI 能力补齐（核心）

### 4.1 根因（不是「没写」，是「接口焊死在 WebKit 类型上」）

```
engine/content.rs:257   extract_snapshot_async(wv: &webkit2gtk::WebView, tx: Sender<Result<Snapshot, String>>)
api/handlers/page/util.rs:47  wv.with_webview(move |pwv| engine::webview::eval_js_with(&pwv.inner(), …))
api/handlers/page/read.rs:85  wv.with_webview(...)
```

CEF 的 `Browser` 拿不到 `webkit2gtk::WebView`，所以**整条 AI/API 链路在 CEF 路径无法复用**。
关键事实：`engine/agent.rs:129 build_action_js()` 是**纯字符串模板**，
`SNAPSHOT_JS` 也是纯字符串，安全白名单（密码框拒绝/人工确认）是纯逻辑层。
**真正缺的只是「注入 JS 并回收结果」这一层抽象。**

### 4.2 分步方案

**步 1（1~2 天，收益最大）：抽 `PageEval` trait**

```rust
pub trait PageEval {
    /// 在页面主框架执行 JS，结果异步回传（实现方决定线程模型）
    fn eval(&self, js: &str, cb: Box<dyn FnOnce(Result<String, String>) + Send + 'static>);
}
```

- WebKit 实现：包一层 `with_webview` + `eval_js_with`（现有逻辑照搬）。
- CEF 实现：`browser.main_frame().execute_java_script(code, url, 0)` + CEF 的
  result callback（`CefStringVisitor`）→ oneshot 回传。`browser/ops.rs` 已留 `eval_js` 位置。
- 改 `extract_snapshot_async` 签名为 `&dyn PageEval`。
- **一次改动同时解锁**：AI 快照、Agent click/fill/read/submit、open API 的
  `page/read`、`page/content`、`page/shot` 系列。

**验收**：CEF 构建下 `SNAPSHOT_JS` 返回合法 `Snapshot` JSON（标题/正文/链接数/表单数）；
Agent 四动作在 CEF 页面执行成功；密码框拒绝用例回归。

**步 2（1 天）：CEF 翻译**

`toolbar.html` 加翻译入口 → `SHIFT_ACT:translate` → 注入已有 `context_translate.js`
→ 调 `translate.rs`（纯 HTTP，引擎无关）→ 译文回填 + 翻译记忆（DB 已有
`engine:<engine>:<target>` 命名空间隔离）。

**步 3（2~3 天）：CEF 的 AI 对话面板（明确取舍）**

**先做 `toolbar.html` 内的轻量对话面板**（HTML/JS + 现有 opencode 代理），
不把 `AISidebar.vue` 塞进 CEF。理由：CEF 界面是单字符串内嵌、无构建管线，
硬塞 Vue 等于引入第二套前端体系；用户要的是「AI 能力在 CEF 可用」，
不是像素级一致。等 CEF 单栈稳定后再评估 Vue 复用。

**步 4（架构级，需立项）：补进规划文档**

open API 的 CEF 支持在原规划里**根本没写**，是规划自身的漏洞。
应作为 M5 立档：`api/` 层通过 `PageEval` + 一个 `EngineHandle` 抽象
（`navigate`/`eval`/`snapshot`/`close`）同时支持两套引擎。

### 4.3 方案自我修正（论证）

- **原想法「把 Vue 界面塞进 CEF」被否**：成本两周+，且需要给 CEF 引入
  vite 构建产物加载，与「单栈窗口 = 一个 BrowserView + 内嵌 HTML」的现状冲突。
- **原想法「给 CEF 单独写一套快照 JS」被否**：`SNAPSHOT_JS` 已是成熟产物，
  复制一份必然漂移；抽象注入层才是单一事实源。
- **保留风险**：CEF 的 `execute_java_script` 回调在 UI 线程，若在回调里同步等待
  会死锁（WebKit 侧已有同类教训：`content.rs` 注释「绝不能在闭包内 recv_timeout」）。
  CEF 实现必须走 oneshot + 异步回传，禁止阻塞。

## 五、CEF 进 CI 的可行性与成本

- 本机实测 `cargo test --lib --features cef-engine` = **726 通过 / 0 失败**，`clippy` 0 警告，
  说明**代码本身达标**，进 CI 的障碍只在耗时。
- 成本：CEF 冷编译约 15 分钟（`cef-dll-sys` 下载 150MB + cmake 构建 wrapper）；
  加 `Swatinem/rust-cache`（独立 `shared-key: cef-engine`）后，命中缓存约 3~5 分钟。
- 本轮 CI 只加 `fmt + check + test`，**clippy 暂不进**（CEF 冷编 + clippy 在 4 核上近 30 分钟），
  等本 job 稳定一轮再加，避免一次把 CI 拖成 25 分钟。
