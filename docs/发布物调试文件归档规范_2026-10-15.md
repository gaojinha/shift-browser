# 发布物调试文件归档规范（B-06 风险 R4 · 归档纪律）

> 日期：2026-10-15 · 执行：atomcode · 性质：**可执行规范**（纯增量，不改现有发布流程）
> 定位：B-06 预研风险 R4「归档纪律缺失导致崩溃无法回溯」。B-06 结论：
> **无论拍哪条剥离方案（A/B/C），归档纪律（R4）都建议先行——它独立成立且零风险。**
> 边界：本规范 + `scripts/archive-release-artifacts.sh` 为纯增量——**不改** `package-deb.sh`、
> **不改** `Cargo.toml` 剥离决策（切 `strip="symbols"` / 方案 A·B 是独立拍板项）。
> 发布时先手工跑脚本；把归档并入 `package-deb.sh` 正式步骤是拍板后的后续动作。

## 一、为什么先归档（零风险依据）

- 现状 `panic.log` 是**用户侧唯一崩溃证据源**（P0-4 全局 panic 钩子，把符号化 backtrace 文本直接写给用户，无服务器解析环节）。
- Rust backtrace：函数名来自 `.symtab`，行号来自 DWARF（`.debug_*`）。现 `strip="debuginfo"` → DWARF 已剥，**panic.log 现在就只有函数名、无行号**。
- 若日后切 `strip="symbols"`（方案 A/B）去掉 symtab，panic.log 退化为裸地址（`shift-browser+0x1a2b3c`），用户证据无法定位函数——**除非**用归档副本 + BuildID 离线 `addr2line`/`llvm-symbolizer` 反解。
- **结论：归档必须先于任何剥离。** 归档纪律不依赖剥离决策，零风险，可独立落地。

## 二、归档对象（4 产物 + 清单）

| 产物 | release 路径 | 现状体积（2026-10-15 实测） |
|---|---|---|
| shift-browser（主程序） | `src-tauri/target/release/shift-browser` | 35,105 KB |
| shift-browser-mcp | `src-tauri/target/release/shift-browser-mcp` | 620 KB |
| libshift_browser_lib.so（Tauri lib cdylib） | `src-tauri/target/release/libshift_browser_lib.so` | 2,863 KB |
| libshift_web_extension.so（Web 扩展 cdylib） | `src-tauri/target/release/…resources…`（或 deb 内副本） | 480 KB |

> 4 产物在现 `strip="debuginfo"` 下均保留 `.symtab`（**函数名可解**），`.debug_*`=0（**无行号**）。
> 这就是现状归档内容——足够把 panic.log 裸地址反解到函数名。

## 三、命名与目录结构

`release-artifacts/<version>-<main_buildid>/`
- `version`：取 `src-tauri/tauri.conf.json`（如 `5.8.3`）
- `main_buildid`：主程序 `.note.gnu.build-id`（readelf 读），保证归档与某次构建一一对应
- 例：`release-artifacts/5.8.3-6bed28fd…/`

目录内容：

```
<version>-<main_buildid>/
├── shift-browser
├── shift-browser-mcp
├── libshift_browser_lib.so
├── libshift_web_extension.so
└── MANIFEST.txt
```

## 四、MANIFEST 格式

```
# Shift Browser 发布物归档清单（B-06 R4 · 归档纪律）
version:        5.8.3
main_build_id:  6bed28fd…
git_commit:     <short-hash>
git_date:       <YYYY-MM-DD>
archived_at:    <UTC ISO8601>
rustc:          rustc x.y.z
cargo:          cargo x.y.z
strip_profile:  debuginfo（DWARF 已剥、.symtab 保留 → 函数名可解，行号不可）

# artifact  build_id  bytes  sha256
shift-browser               6bed28fd…  35946752  <sha256>
...
```

字段用途：`main_build_id`/`build_id` 用于把 panic 地址对应到产物；`sha256` 校验完整性；
`git_commit`+`rustc` 用于复现同一次构建。

## 五、存放位置

- **默认**：`release-artifacts/`（仓库根下），自动写入 `.gitignore`——符号/调试文件不进仓库
  （避免 CI 大文件红线卡 + 收窄披露面）。
- **长期留存**（可选，拍板后）：推到制品库/对象存储，以 `<version>-<main_buildid>` 为键。
  本规范只定义本地 gitignored 默认；留存介质是独立拍板项。

## 六、如何使用（离线符号化）

用户回报含裸地址的 panic.log（未来剥离后）：

```
addr2line -e release-artifacts/<version>-<bid>/shift-browser -f -C <地址>
# 或
llvm-symbolizer --obj=release-artifacts/<version>-<bid>/shift-browser <地址>
```

- **现状能力**：可解**函数名**（symtab 在），不可解行号（DWARF 已剥）。
- **若要行号**：切方案 B（重开 DWARF + `.gnu_debuglink`），独立拍板项；归档目录结构兼容
  （同目录加 .debug 文件即可）。

## 七、运行方式

```
bash scripts/archive-release-artifacts.sh            # 归档到 release-artifacts/（默认，自动 gitignore）
bash scripts/archive-release-artifacts.sh /mnt/art   # 指定归档根（自定义根不自动改 .gitignore）
```

前置：release 产物已构建（`scripts/package-deb.sh`，或 `tauri build --release` + `scripts/build-extension.sh`）。

## 八、验收口径（对应 B-06 §5 第 4 条）

1. `release-artifacts/<version>-<main_buildid>/` 含 4 产物，`file`/`readelf` 可读；
2. `MANIFEST.txt` 完整（version / main_build_id / git_commit / sha256 齐全）；
3. `git status` 不出现 `release-artifacts/` 下任何文件（已 gitignore）；
4. 取主程序一个已知符号地址，`addr2line -e <归档>/shift-browser` 能解析出函数名（能力验证）。

## 九、与拍板项的边界（本规范**不**做什么）

| 本规范做 | 拍板项（本规范不做） |
|---|---|
| 归档现状（strip="debuginfo"）产物 | 改 Cargo.toml 为 strip="symbols"（方案 A） |
| 定义目录 / MANIFEST / gitignore | objcopy 分离 + .gnu_debuglink（方案 B） |
| 提供离线符号化用法 | 是否/何时把归档并入 package-deb.sh 正式步骤 |
| 纯增量、零风险、可独立落地 | 改发布流程、剥离决策 |
