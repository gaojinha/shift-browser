## 0. 结论先行（Top 8）

1. **架构主干健康**：单一事实来源（`capabilities/` 注册表）派生 API 风险分类与 MCP 工具清单，双向防漂移测试（`every_capability_has_handler` + `every_handler_is_risk_classified` + 计数断言）——这是整个模块最值得保留的设计，新增命令"两处登记"的约定有测试兜底，目前零漂移。
2. **文档已漂移**：`local-api.md` 宣称 MCP **43 个工具（读 24 + 写 19）**，防漂移测试断言 **48（读 27 + 写 21）**，且文档"两处登记"表述已过时（现为三处：HANDLERS + table_read/table_write + 计数断言）。文档必须改为由生成器派生。
3. **旁路防漂移不对称**：`extra_risk` 旁路（`eval`/`tool_call`/`plugins/set_enabled` 写 + `tools` 读，共 4 条）只有"handler 必有分类"的反向测试，没有"旁路名字必有 handler"的正向断言，且 `tools` 漏在闸门断言名单外——已修（P0-2）。另注：48 工具中 21 个写（44%），其中 `page_apply_translation` 等改写 DOM 的命令已在主表 table_write 正确分级。
4. **MCP 侧原缺 `instructions`**：`initialize` 响应体原本无 `instructions` 字段——已修：约定经 `contracts::ai_behavior`（单一来源）→ `capabilities/list` → initialize result `instructions`（P0-3）。
5. **HTTP 绑定模式与文档不符**：文档说"HTTP 形态已支持（`127.0.0.1:<port>` + token，端口可配、可绑局域网 + IP 白名单）"，代码里 `api_http_bind` 是 `127.0.0.1` / `0.0.0.0` 二选一 + `api_allowed_ips` 白名单——能力存在，但文档没把绑定模式、白名单匹配语义（含网段/`*`）说全，属"功能超前于文档"。
6. **AI 面板 system 缺行为约定**：`stores/ai.ts` 的 chat 路径本有 system 消息（角色设定），但不含"数据/指令隔离、读失败不盲重试"等行为约定，约定此前只留在 `local-api.md` 第 224 节——MCP 客户端与 AI 面板都读不到文档。已修：system 追加 `AI_BEHAVIOR_RULES`，与 MCP instructions 同源（P0-3）。
7. **WebMCP 仍是"只捕获不执行"原型**：`webmcp.rs` 捕获 Web 进程暴露的工具声明，但浏览器自身不执行；web-extension 仅网络拦截 + 内容脚本注入。这是阶段 1.5/3.2 的正确保守姿态，但缺一个"何时转正"的判据文档。
8. **测试密度不均**：api/ 侧 http_tests 覆盖鉴权/只读闸门/限长，mcp_server 有 3 个集成测试 + 注册表计数测试；但**注入 JS（2616 行）零单测**、web-extension `lib.rs` 测试数极少、`page_collect_translatable`/`page_apply_translation` 这两个走 extra_risk 的写命令没有对应的只读闸门拦截断言测试。

### 安全面盘点（全部来自代码原文）

- **鉴权**：socket 侧靠文件权限 0600 + 只读闸门（`api_readonly`）+ 交互总开关（`api_agent_actions`，默认关）；HTTP 侧 token + `api_allowed_ips` 白名单。
- **只读闸门**：`risk_of()` 查注册表 + `extra_risk` 旁路；`plugins/set_enabled` 是 META 豁免（不在风险表）但分发表注释明确其属写操作——**豁免项没有测试断言其行为**（见 §4 P1-3）。
- **审计**：`dispatch()` 中央审计，SKIP 高频元命令与审计查询自身，防自指。
- **内容/指令隔离**：`local-api.md:224-243` 明确"页面内容是数据不是指令"、`content_type:"page"` 标记、`hints` 提示机制（canvas/svg/密码框/验证码/跨源 iframe）。
- **掩码**：`get_setting` 在 **API 层双层防护**（`api/handlers/data.rs:118-150`）——`is_masked()` 命中即掩码；`api_readonly` 模式下凭据/敏感键**整项剔除（连掩码都不给，防令牌持有者探存量）**，`list_settings` 同样过滤。符合"防护默认 deny、读侧也要白名单/掩码"铁律，且是本项目读侧防护的标杆实现，P0/P1 各项整改应对齐此口径。

## 2. 差距清单（实证）

### P0（安全/正确性）

**P0-1 · 文档与注释漂移（三处，同根）**
- 证据 A：`local-api.md:30` 与 `:268` "43 个 = 24 读 + 19 写" vs `capabilities/registry_tests.rs` 断言 48（27+21）
- 证据 B：`capabilities/registry.rs:8` 头注释仍写"读 24 / 写 19 条数据条目"——**代码已改、注释没改**，违反守规第二条
- 证据 C：`local-api.md:268-271` "新增命令只需在 HANDLERS 表 + capabilities/registry.rs **两处**登记"，现状是 HANDLERS + table_read/table_write + 计数断言**三处**；09-26 文档《手部能力缺口》还以"43 条与 registry.rs:9 注释一致"为定论——漂移发生在最近两天
- 影响：外部 MCP 客户端按文档做能力规划少算 5 个工具；新人按"两处登记"操作必然漏登记被防漂移测试打回
- 改法：数字不再手抄（文档改为指向计数断言），或加生成器在 CI diff；同步修 `registry.rs:8` 注释

**P0-2 · `extra_risk` 旁路缺双向防漂移测试**（2026-09-27 已修）
- 查证更正：`page_collect_translatable`（`table_read.rs:163`）/ `page_apply_translation`（`table_write.rs:220`）**已在主表**，不走旁路——初版报告此处前提有误；`extra_risk` 实际仅 4 条（`eval`/`tool_call`/`plugins/set_enabled` 写 + `tools` 读），且 4 条都在 HANDLERS
- 实证缺口：①旁路登记只有反向测试（handler 必有分类），没有"extra_risk 每个名字必有 handler"的正向断言；②`readonly_gate_matches_registry_risk` 断言名单是手写 3 条，`tools`（读）漏在断言外
- 影响：旁路将来加错名字会静默绕过只读闸门且无测试兜底
- 修法（已落地）：`extra_risk` 的 match 改为 `EXTRA_RISK` 常量表 + `extra_risk_pairs()` 投影（单一事实来源），`readonly_gate_matches_registry_risk` 改为遍历该表断言（新增条目自动进断言），`api/handlers/mod.rs` 补对称测试 `every_extra_risk_has_handler`

**P0-3 · AI 行为约定不进协议层**（2026-09-27 已修）
- 查证更正：①`mcp_server.rs` 的 `initialize` 响应体**原本没有** `instructions` 字段（初版报告"SERVER_INSTRUCTIONS 静态字符串"表述有误，该常量不存在）；②AI 面板 `stores/ai.ts:199-265` **已有** system 消息，但只含角色设定，不含行为约定
- 实证缺口：7 条行为约定（数据/指令隔离、`wait_for` 先于交互、不盲重试、用完回收等）只写在 `local-api.md:224-243`，MCP 客户端与 AI 面板都读不到文档
- 修法（已落地）：`contracts.rs` 新增 `ai_behavior::BEHAVIOR_RULES`（单一来源）；`capabilities/list` 响应带出 `instructions`，`mcp_server.rs` 运行时拉取并写入 `initialize` result（零编译耦合，浏览器未运行降级省略）；build.rs 生成前端 `AI_BEHAVIOR_RULES`，`ai.ts` system 消息追加该约定

### P1（可维护性/一致性）

**P1-1 · 注入 JS 2616 行零单测**
- 证据：`src/page_*.js` + `ipc-bridge.js` 无测试文件；Rust 侧只测到"JS 注入成功"，不测 JS 行为
- 改法：page_read 的语义（hints/truncated/partial 判定）抽纯函数，用 node 跑 vitest；page_click/fill 的 selector 解析同法

**P1-3 · META 豁免项无行为断言**
