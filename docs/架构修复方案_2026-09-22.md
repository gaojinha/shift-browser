## P0-1 · newtab 模板外置（推荐先做）

### 问题
`newtab.rs` 2265 行，其中 **1473 行是内嵌 HTML/CSS/JS 模板**（`366-1839` 主模板 + `1861-2060` 世界导航模板）。
启动页任何改动（如这两天的天气卡）都要**重编译 6 分钟**。

### 现状机制
```rust
format!(r#"<!DOCTYPE html>...{ipc_bridge}...{quick_grid}..."#)  // 12 个占位符
```

### 方案
1. 模板抽到 `src-tauri/resources/newtab/index.html`（**独立文件**）
2. Rust 侧改 `include_str!("../resources/newtab/index.html")` + **占位符替换**（`{{PLACEHOLDER}}` 风格，避免 `{}` 与 CSS 冲突）
3. 世界导航页同样外置
4. 保留 `generate()` 逻辑，只换模板来源

### 收益
- ✅ 改启动页**不再需要重编译 Rust**（改文件 + 刷新即可，我们这两天就是这么干的）
- ✅ 模板可用 HTML/CSS/JS 工具链（lint/格式化）
- ✅ `newtab.rs` 从 2265 → **约 800 行**

### 风险与验证
- 风险：占位符替换逻辑出错 → 页面渲染异常
- 验证：**逐占位符比对**（改前改后生成的 HTML 逐字节 diff）+ 自家浏览器截图

## P0-2 · 引擎抽象层补全

### 问题
`engine/webview.rs` 仅 117 行；`tabs.rs:16-19` 仍直接 `use webkit2gtk`，并在 **6+ 处**直接调 `WebViewExt` / `WebContext`（下载、导航、UA、证书、Cookie）。
→ 跨平台移植（Windows/Android）无从下手。

### 方案
1. 定义后端 trait（草案）：
```rust
pub trait WebViewBackend {
    fn reload(&self);
    fn go_back(&self) / go_forward(&self);
    fn nav_state(&self) -> (bool, bool);
    fn eval_js(&self, js: &str);
    fn set_user_agent(&self, ua: &str);
    fn set_muted(&self, m: bool);
    fn open_inspector(&self);
    // 下载/证书/权限 走事件回调接口
}
```
2. 把 `tabs.rs` 残留的 WebKit 调用**全部下沉**到 `engine/webview.rs`
3. `lib.rs::run()` 里的 GTK 初始化/Cookie/内存治理 → `engine/platform/linux.rs`
4. **本次不改行为**，纯搬家 + 加 trait（零功能变更，易验证）

### 收益
- ✅ 跨平台有明确边界（Windows 只需实现 trait）
- ✅ `tabs.rs` 与引擎解耦

### 风险与验证
- 风险：搬家过程中漏改/错改 → 功能回归
- 验证：**编译 + 全功能冒烟**（标签/下载/前进后退/证书/UA）+ 逐处对照

## P1-1 · tabs.rs 拆分

### 问题
`tabs.rs` 2516 行 = **数据模型** + **GTK 渲染** + **29 个命令**，三类关注点混杂。

### 方案
```
src/tabs/
├── mod.rs        # 导出
├── model.rs      # Tab / TabManager（纯数据 + 状态机）
├── backend.rs    # webview 创建/布局/信号（依赖 engine）
└── commands.rs   # 29 个 #[tauri::command]（门面）
```
- 保持 `tabs::xxx` 路径不变（`pub use` 转发），**前端零改动**
- 分步搬：先 `model.rs` → 再 `commands.rs` → 最后 `backend.rs`

### 收益
- ✅ 单文件从 2516 → 各 300-800 行
- ✅ 数据逻辑可单测（不依赖 GTK）

### 风险与验证
- 风险：`pub use` 转发遗漏 → 编译失败（**编译期即可发现**）
- 验证：`cargo check` + 全功能冒烟

## P1-2 · 命令注册 + 契约生成

### 问题
`lib.rs` 手写 ~170 个命令，**三处手工同步**（模块定义 / `generate_handler!` / 前端 `invoke`），拼错运行时才报错。

### 方案（二选一）
| 选项 | 说明 | 评价 |
|---|---|---|
| **A. tauri-specta** | 自动生成 TS 绑定 + 类型 | ⭐ 推荐，一步到位 |
| **B. 各模块自带 commands()** | 宏收敛注册 | 改动小，但不解决 TS 契约 |

**推荐 A**：生成 `src/bindings.ts`，前端 import 类型化命令，**编译期校验**。

### 收益
- ✅ 消除手工同步 bug
- ✅ 前端类型安全

### 风险与验证
- 风险：specta 对复杂类型（如 `serde_json::Value`）支持有限，需逐个适配
- 验证：先**小范围试点**（如 tabs 命令），跑通再全量

## P1-3 · extensions.rs 拆分

### 问题
1982 行塞了 **6 个独立领域**（广告拦截/反指纹/GPC/隐私/扩展/用户脚本）+ 内嵌 JS。

### 方案
```
src/extensions/
├── mod.rs
├── adblock.rs        # 广告拦截
├── antifingerprint.rs# 反指纹
├── gpc.rs            # GPC（已有独立 gpc.rs，合并）
├── privacy.rs        # 隐私盾 + 统计
├── manager.rs        # 扩展管理
└── userscript.rs     # 用户脚本
```

### 风险与验证
- 风险：内嵌 JS 模板搬迁时字符串转义出错
- 验证：编译 + 隐私自检 + 广告拦截实测

## P2-1 · 错误处理治理

### 问题
182 处 `.unwrap()`，密码库 30 处；命令统一 `Result<_, String>` 丢失类型。

### 方案（分步，不激进）
1. **先加护栏**：对 `passwords.rs` / `vault.rs` / `sync.rs` 三个模块开
   `#![deny(clippy::unwrap_used)]`，逐个消除（**不一次全改**）
2. 建立 `AppError`（thiserror）+ 命令边界统一 `map_err`
3. 其余模块**保持现状**（182 处全改风险大、收益递减）

### 风险与验证
- 风险：改动密码库影响登录/解密 → **必须逐函数改 + 单测**
- 验证：现有密码库单测 + 手动登录/保存/读取

## P2-2 · 内嵌 JS 资源化

### 问题
`PRIVACY_JS` / `ADBLOCK_JS` / 翻译脚本内嵌 Rust，无 lint、无测试。

### 方案
- 抽到 `src-tauri/resources/js/*.js`，用 `include_str!` 加载
- 配 ESLint + 焦点单测（如反指纹函数）

### 风险与验证
- 风险：低（纯搬家）
- 验证：隐私自检 + 广告拦截实测

## P3 · 并发 Actor 化（**建议暂缓**）

### 我的判断
- 现状：**单窗口、命令串行**，`std::sync::Mutex` 临界区极小，**实际不阻塞**
- 改 `tokio::sync` 反而引入 async 锁开销
- **触发条件**：开放 API / 多端并发写真正上线时

### 建议
**等并发真上来再改**，现在改是过早优化。**列入观察项，不排期。**
