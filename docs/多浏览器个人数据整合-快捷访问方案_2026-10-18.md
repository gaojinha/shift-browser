# 多浏览器个人数据整合进「快捷访问」——设计方案 v2

> 日期：2026-10-18 ｜ 作者：王二狗 ｜ 状态：**设计稿，P0 已完成**
> **v2 修正说明**：v1 把 Chrome 判成"空的（书签 0 / 密码 0）"是**错的**——只读了 `Default/Bookmarks` 和 `Default/Login Data`，而这两个恰好是 Chrome 154 的**空壳**。真实数据在 `AccountBookmarks` 和 `Login Data For Account`（账号同步存储）里。v2 已修正全量数据，并把"多源探查"提到方案第 6.1 节当**头号风险控制点**。
>
> 目标：把 Chrome / Brave 的个人数据（书签、常用站点、密码、设置）分析清楚，统一整合进 ShiftBrowser 的「快捷访问」栏目及相关模块。

## 0. 一句话结论

数据远比 v1 说的多——**书签 247 条（Chrome 120 + Brave 127）、有效密码 83 条（Chrome 63 + Brave 20）、历史 2833 条**，且**全部可离线解密**（P0 已实测）。
方案不改「快捷访问」底层（仍是 `settings.quick_sites` + 静态 HTML 网格），**在它上面加一层「扫描 → 预览 → 导入/生成」**，按数据类型落到 ShiftBrowser 对应模块。
**核心教训已内建**：导入器必须**遍历多文件源并合并去重**，绝不能只读 `Bookmarks` / `Login Data` 两个空壳文件。

## 4. 技术可行性与红线

### 4.1 能读的（无加密）
- `Bookmarks` / `AccountBookmarks`（JSON）、`History` / `Top Sites` / `Login Data*`（SQLite）、`Web Data`（自动填充）、`Preferences`（搜索引擎/主页）。

### 4.2 加密的（P0 实测：全部可解）

**两把钥匙，按浏览器取对应的 keyring 条目：**

| 浏览器 | keyring label（gnome-keyring） | 实测 |
|---|---|---|
| Chrome | `Chrome Safe Storage` | **63/63 解密成功** |
| Brave | `Brave Safe Storage` | **20/20 解密成功** |

**算法（Chromium `os_crypt_linux.cc` 原文 + 实测验证）：**
1. 密钥密码 = keyring 对应条目的**值本身**（24 字符 base64 串，**不要 base64 解码**）
2. `key = PBKDF2-HMAC-SHA1(password, salt=b"saltysalt", iterations=1, dklen=16)`
3. 密文去 3 字节 `v11`（或 `v10`）前缀 → **AES-128-CBC**，IV = 16 个空格（0x20）
4. PKCS7 去填充 → 明文
（`v10` 同算法，密码为硬编码 `"peanuts"`；本机两把钥匙均为 `v11`。）

**加密书签文件**（`EncryptedAccountBookmarks2` 等）：同为 `v11`，**首块已实测可解**，作兜底源。

> 📌 **解密前提**：当前 Linux 用户会话已解锁 keyring（图形会话下通常已解锁）。

> ⚠️ **安全事实**：v11 可解 ⇒ 同一会话内**任何能读 keyring 的进程都能还原密码**——Chromium Linux 后端的固有弱点（非 Brave 独有）。因此"明文零落盘"是硬要求。

### 4.3 红线（必须守）
1. **绝不记录/输出密码明文**（日志、错误、UI 预览一律只给掩码/条数）。
2. **读源库必须快照且连 `-wal`/`-shm` 一起拷**：浏览器运行时 Chromium 库是 WAL 模式，只复制主文件会读到空/旧数据——**v1 读出 0 的根因之一**。
3. **源路径白名单 + 只读**：仅限已知浏览器配置目录与用户手选文件；不遍历、不猜。
4. 写入前 URL 过 `normalize_quick_site_url`，文本 HTML 转义。
5. 导入是**用户显式动作**，默认全不勾选。

## 6. 详细设计

### 6.1 数据源探查 `scan_browsers()`（★ 核心，v1 根因所在）

**必须做到的四件事**（v1 的教训逐条对应）：

1. **多文件源优先级**（不再只认 `Bookmarks` / `Login Data`）：
   ```
   书签源：AccountBookmarks → Bookmarks.bak → Bookmarks → EncryptedAccountBookmarks2 → EncryptedBookmarks2
   密码源：Login Data For Account → Login Data
   ```
   **多个可用源一律合并、按 URL 去重**（不是二选一）；加密源在前三个都无内容时用同一把钥匙解密兜底。

2. **多 profile 遍历**：`Default` + `Profile 1..N`（本机虽只有 Default，代码留能力）。

3. **WAL 快照读取**：复制 `<file>` + `<file>-wal` + `<file>-shm` 到临时目录再读，读完即删（实测已验证此法能读到 Chrome 运行中的 `Login Data For Account` 69 条）。

4. **按浏览器选钥匙**：Chrome→`Chrome Safe Storage`，Brave→`Brave Safe Storage`（keyring label 硬映射，取不到就该项降级提示"无法解密"，不猜）。

返回结构（只出计数与可用性，**不出内容**）：
```ts
interface BrowserProfile {
  browser: 'chrome' | 'brave' | ...        // 白名单枚举
  profilePath: string
  sources: {
    bookmarks: { files: string[]; count: number; encrypted?: boolean }
    passwords: { files: string[]; count: number; canDecrypt: boolean }
    history:   { count: number }
  }
}
```

### 6.2 快捷访问生成 `generate_quick_sites_from_sources(sources, limit=12)`
- **来源 A（首选）**：`Top Sites` 表（rank/frecency）
- **来源 B（兜底/补充）**：`History` 按域名聚合频次
- **来源 C（可选）**：书签一级目录项
- 规则：同域去重 → 按频次/rank 排序 → **取前 12（高哥定）** → 生成 `[图标, 站名, url]` 三元组（复用 `normalize_quick_site_url`）
- **先预览、后写入**：候选网格可增删，确认才写 `quick_sites`
- 图标优先用浏览器 `Favicons` 表本地图，避免外网请求

### 6.3 书签导入 `import_bookmarks_from_browser(browserId, profilePath) -> usize`
- 解析 `AccountBookmarks` / `Bookmarks`（JSON，递归 `roots`，**忽略 `sync_metadata`/`checksum`**），保留文件夹层级。
- 与现有 `import_bookmarks_from_file` **共用同一写入内核**（同一类判定只许一份实现）。
- 多源合并去重后计数回执。

### 6.4 密码导入（两档都可行）
> **档 2 已被 P0 实测支持，推荐**

- **档 2（推荐，一步到位）**：`import_passwords_from_browser()` → 遍历 `Login Data For Account` + `Login Data` → 内存解密（4.2 算法）→ 逐条 `save_password` 写入自研 vault → **全程不落明文、导入完立即清内存** → 回执只报条数（成功/跳过空密码/失败）。
- **档 1（备选，不依赖 keyring）**：`import_passwords_from_csv(path)`，读浏览器官方导出 CSV → 逐条 `save_password` → 提示删 CSV。
- **档 3（兜底）**：只导"站点+用户名"，密码留待首次登录时由 ShiftBrowser 自己保存。
- 空密码（本机 6 条）直接跳过，不写入。

### 6.5 设置类导入（二期，可选）
搜索引擎（`Preferences` → `default_search_provider`）、主页、自动填充（`Web Data` → `autofill`）。逐项映射，缺失跳过。**不迁 Cookie、不迁扩展。**

### 6.6 导入向导 UI
- 入口：设置 → **数据与同步** 新增卡片「从其他浏览器导入」
- 流程：① 扫描（各浏览器 + 各源可用性与计数）→ ② 勾选（默认全不选）→ ③ 预览（快捷访问候选可增删；书签层级树；密码只报条数）→ ④ 执行 → ⑤ 回执（逐项成败，密码只报数）
- 失败给原因，不静默吞；明文不出现在任何回执里。

## 9. 验收标准

- **四关口**：`cargo clippy --all-targets` 零警告；`cargo test --lib` 全过；前端 `vitest` 全过；`npm run lint` / `npm run build` / `vue-tsc --noEmit` 过。
