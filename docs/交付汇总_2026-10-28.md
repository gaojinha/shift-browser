## 四、今日踩到的三个坑（已写入 `docs/F-CEF-24-交付总结_2026-10-28.md`）

1. **MSRV 1.77.2 不支持 `LazyLock`**（1.80 稳定）→ `Mutex::new` 常量构造 / HashMap 走 `OnceLock`
2. **`wrap_task!` 宏内部递归用裸名** → 必须 `use cef::wrap_task;`，写 `cef::wrap_task!` 报"找不到宏"
3. **`multi_threaded=1` 后 CEF 回调不在 GTK 主线程** → `glib::*_add_local` / GTK widget 跨线程调必 panic（`main context already acquired`），统一走 `gtk_ui()`

## 五、遗留

- **F-CEF-31 已修**（附件导航），但普通 URL 导航到国内不可达域名（如 `example.com`）时 CEF DevTools 端口也会无响应，属网络层等待，未深挖
- **下载进度真机验证不完整**：面板刷新逻辑已接，但只在附件下载路径观察到「下载开始」，面板上的实时进度还需要一次完整下载观察
- **atomcode 失联**：41 分钟 0% CPU 后按规则释放，其排队的卡由二狗接手
- **CEF 换核 P1 剩余**：IPC 桥（`shift://`）、DevTools / 截图、指纹实测（JA4/HTTP2）——都需高哥拍板优先级
