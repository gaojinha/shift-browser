## 一、现状盘点

### 1.1 开放 API 入口（两条通道）

| 通道 | 实现 | 鉴权 | 位置 |
|---|---|---|---|
| Unix 域套接字 `api.sock` | `api.rs:99` bind + `api.rs:131` chmod 0600 | **无 token**，靠文件权限（注释 `api.rs:1-4` 明示此设计） | `src-tauri/src/api.rs`；MCP 进程连法 `bin/mcp_server.rs:15` |
| HTTP `127.0.0.1|0.0.0.0:19701` | 手写解析（无 axum/tiny_http），`http.rs:84` bind | 全端点要求凭据（Bearer / ticket / 表单 token） | `src-tauri/src/api/http.rs`；默认端口 `http.rs:33` |

HTTP 端点（`http.rs:164-334`）：

| 端点 | 用途 | 凭据校验点 |
|---|---|---|
| `POST /v1/chat/completions` | 模型网关 | `http.rs:192,195` |
| `POST /api` | JSON 命令端点（58 条命令） | `http.rs:317` |
| 其余 path | 状态面板 dashboard（`api/dashboard.rs` 生成 HTML） | `http.rs:260-262` 三轨：Bearer / `?ticket=` 一次性门票 / POST 表单 token |

命令面：`api/handlers/mod.rs:40-131` HANDLERS 表共 58 条（capabilities/list、tabs 系列、read_page/extract/screenshot、action/click|fill|scroll|…、eval、get_setting、audit/reads|egress 等）。
token 专项命令（不在 HTTP 面）：`rotate_api_token`（`dashboard.rs:102`，注册 `lib.rs:282`）、`create_dashboard_ticket`（`dashboard.rs:121`，`lib.rs:283`）。

### 1.2 鉴权机制

- token 生成/落盘：`auth.rs:15` `ensure_token`（vault 同目录 `api-token` 文件，0600 原子写 `auth.rs:39`）；`auth.rs:30` 双 uuid 拼 64hex。**不进 settings 表**。
- 运行期：`auth.rs:58` `ApiTokenShared(Arc<RwLock<String>>)`，每请求读，轮换热生效。
- 校验：`http/util.rs:28` `bearer_token_ok` + `auth.rs:170` `ct_eq` 常数时间比较（防时序侧信道）。逐请求手写校验，非框架 middleware。
- 限速：`auth.rs:104` `LoginGuard`（非 loopback 才计数 `auth.rs:124`；429 闸门 `http.rs:171-186`）。
- 门票：`auth.rs:63` `DashboardTickets`（TTL 5 分钟、一次即焚；单测 `auth_tests.rs:136`）。
- **未发现无鉴权 HTTP 端点**。

### 1.3 只读模式（黑名单式，单源判定 + 三处闸门）

- 判定单源：`auth.rs:201-215` `is_readonly` —— 直查 DB `settings.api_readonly`；**查询失败/键缺失按未开启（fail-open）**，注释自述"只读是用户显式开启的约束"。
- 写命令单源：`capabilities/registry.rs:69-71` `is_write` = Risk==Write（`core.rs:14-18`），写命令登记于 `table_write.rs`。
- 三处闸门（同口径）：① sock 主闸门 `api.rs:174-180`；② HTTP 网关 `http.rs:198-208`；③ 凭据/掩码键整项拒绝 `handlers/data.rs:128-134,146-151`。
- eval 专项：`handlers/page.rs:32-40`，`api_allow_eval == 'true'` 才放行（默认关 `contracts.rs:105`）；MCP 不暴露 eval（`mcp_server.rs:18-19`）。

### 1.4 白名单（判定单源已并口径 ✅）

- 唯一实现：`auth.rs:222` `ip_allowed`（精确 IP / CIDR / 带尾点旧式段前缀；IPv4-mapped v6 归一化；非法条目忽略并告警，P2-3 加固注释 `auth.rs:216-221`）。
- 三个使用点：① HTTP 连接级准入 `http.rs:100-108`；② 导航守卫 `net_guard.rs:50-56`（复用 `api::auth::ip_allowed`，`net_guard.rs:55`）；③ open_and_read 守卫 `open_read.rs:34-49`（查库刷新 `net_guard::set_allowlist`）。
- 私有地址判定单源：`ai/ssrf.rs:33,56,151`；net_guard/llmstxt/feed 均转发复用（`net_guard.rs:17-19`、`llmstxt.rs:198,206`、`feed.rs:68`）——符合"一份实现"铁律。
- LAN 绑定策略：`http.rs:57-61` **绑 0.0.0.0 必须配非空白名单，否则拒绝 LAN 退回 127.0.0.1**；明文无 TLS 已知限制有醒目警告（`http.rs:68-74`）。

### 1.5 前端设置面与契约

七个 api_* 键（allow_eval / readonly / agent_actions / http_port / bind_lan / allowed_ips / model_gateway）契约定义于 `contracts.rs:105-111`（唯一来源），UI 在 `ApiSection.vue`（对应关系：eval→`:80`、readonly→`:91`、agent_actions→`:102`、port→`:115`、bind_lan→`:126`、allowlist→`:138`、gateway→`:151`）。token 管理入口：ticket `ApiSection.vue:26`、轮换 `:46`。

### 1.6 既有测试

- `req_tests.rs` 7（HTTP 解析鲁棒性）、`fuzz_tests.rs` 3（含 CIDR fuzz）。

- **缺口：无端到端 HTTP 401/403 集成测试**（现有全是单元级）。

### 1.7 铁律对齐检查

## 二、矩阵草案（主体 × 资源 × 动作）

### 2.1 主体（Principal）

| # | 主体 | 准入链 | 现状标识 |
|---|---|---|---|
| P1 | `sock`（MCP 进程） | Unix socket 文件 0600 | 无 token、无身份标签 |
| P2 | `loopback-http`（本机 curl/脚本） | Bearer token（+LoginGuard 豁免） | 无身份标签 |
| P3 | `lan-http`（局域网客户端） | Bearer token + IP 白名单 + LoginGuard 限速 | 无身份标签（与 P2 同权） |
| P4 | `dashboard`（状态面板） | Bearer / 一次性 ticket / 表单 token 三轨 | 无身份标签 |
| P5 | `internal`（Tauri invoke 前端） | 不经 API 层 | 不在矩阵范围（标注排除） |

### 2.2 资源 × 动作 × 控制点（现状映射）

动作沿用既有 Risk 二分（Read/Write，`capabilities/core.rs:14-18`），矩阵再加一格 **Execute**（eval 类，现有专项开关兜住）：

| 资源 | 动作 | 代表命令/端点 | P1 sock | P2 loopback | P3 lan | P4 dashboard | 现有控制点 |
|---|---|---|---|---|---|---|---|
| tabs | read | list_tabs / active_tab / search | ✅ | ✅ | ✅ | ✅（面板只读视图） | token |
| tabs | write | new_tab / close_tab / navigate / pin / mute / switch | ✅（readonly 拦） | ✅（readonly 拦） | ✅（readonly 拦） | ✅ | readonly 闸门① |
| page-content | read | read_page / extract / screenshot / read_selection | ✅ | ✅ | ✅ | 面板部分 | token |
| page-interaction | execute | action/click,fill,hover,key,type,back,dismiss | ✅（agent_actions 拦） | ✅（同） | ✅（同） | — | `api_agent_actions`（`actions.rs:17,136`，**粗粒度**） |
| page-interaction | read | action/scroll,find,wait_for | ✅ | ✅ | ✅ | — | **被 agent_actions 一并拦（Gap-3）** |
| js-exec | execute | eval | ✅（allow_eval 拦） | ✅（同） | ✅（同） | — | `api_allow_eval` + readonly 双闸 |
| data | read | history/bookmarks/downloads/sessions/groups/spaces/userscripts/get_setting | ✅ | ✅ | ✅ | 部分 | token；凭据键掩码 `data.rs` |
| data | write | settings 写（set_setting 类） | ✅（readonly 拦） | ✅ | ✅ | — | readonly 闸门③（凭据键整拒） |
| ai-gateway | execute | POST /v1/chat/completions | —（sock 不走 HTTP） | ✅（readonly+gateway 双闸） | ✅（同） | — | `api_model_gateway`（`dashboard.rs:133,139`）+ readonly 闸门② |
| dashboard-admin | write | rotate_api_token / create_dashboard_ticket | — | ✅ | ✅ | ticket 轨仅开面板 | token 本身即凭据 |
| audit | read | audit/reads / audit/egress | ✅ | ✅ | ✅ | 面板视图 | token |
| 未知命令 | — | 不在 HANDLERS | 拒（无 handler） | 拒 | 拒 | 拒 | handlers 查表 |
| 未登记 Risk | — | handler 存在但 capabilities 无 Risk | **✅ 不受 readonly 拦（Gap-2）** | 同 | 同 | 同 | 无 |

### 2.3 矩阵揭示的 Gap（按严重度排序）

- **Gap-1 无主体粒度**：P2/P3/P4 拿到 token 后权限完全一致；LAN 主体无法降权（如禁 eval/写）。矩阵落地后可实现"按主体差异化"。
- **Gap-2 未登记命令 fail-open**：handler 在但 capabilities 无 Risk 条目 → `is_write` 返回 false → readonly 拦不住。与 AGENTS.md「防护默认 deny」相悖，需拍板 fail-closed。
- **Gap-3 agent_actions 粗粒度**：`action/scroll|find|wait_for` 属读侧语义，与 `click/fill` 同被一键拦；矩阵化后应按 Risk 拆细。
- **Gap-4 sock 无 token**：0600 天然鉴权成立但无纵深；P1 无身份标签，审计无法区分"哪个客户端"。
- **Gap-5 无 401/403 端到端集成测试**：闸门逻辑全靠单测拼图，矩阵验收「全绿」需要补集成口径。
- （已知接受项，不列 Gap：LAN 明文无 TLS——`http.rs:68-74` 已记录为架构限制。）

## 三、拆包建议（4 个必做 + 1 个可选，单件小包原则）

> 排序原则：先立"单一判定源"（铁律），再收 fail-open，再拆粒度，最后补集成验收。每包独立可交、可回滚，总量对齐 R4-3 三人日。

### 包 A：矩阵判定单源 `can(principal, cmd)`（基座，~1 人日）

- **范围**：在 `capabilities/registry.rs` 旁新增 `matrix.rs`（或并入）：`can(principal: Principal, cmd: &str) -> Decision`，把 readonly 闸门、agent_actions、allow_eval、model_gateway 四个离散判定**收敛为一份实现**； Principal 枚举 = `Sock | LoopbackHttp | LanHttp | Dashboard`（从连接属性推导，http.rs accept 处打标，sock 固定 Sock）。三处现有闸门（`api.rs:174`、`http.rs:198`、`actions.rs:136`）改为调 `can()`，判定逻辑不动、行为零变化。
- **验收**：现有全部单测不红；新增 `matrix` 单测（每 Principal × 每命令类 × 开关组合）；contracts 无新键。
- **依赖**：无。**风险最低，先做。**

### 包 B：fail-closed 收口（Gap-2，~0.5 人日）

- **范围**：未登记 Risk 的命令在 `can()` 里默认拒（readonly 开启时）；`is_write` 语义不动（只影响矩阵判定）；补 HANDLERS 与 registry 的**一致性测试**（每条 handler 必须有 Risk 条目，防再漏登记）。
- **验收**：一致性测试全绿；人为去掉一条 Risk 条目的变异测试应被测试抓红。
- **依赖**：包 A。
- ⚠️ **前置决策 D-1**（见第四节），不拍板不能动工。

### 包 C：page-interaction 粒度拆细（Gap-3，~0.5 人日）

- **范围**：`action/scroll|find|wait_for`（及 back？需逐条定性）在 registry 中降为 Read；`click|fill|hover|key|type|dismiss` 保持 Write/Execute。`api_agent_actions` 只拦后者；`is_readonly` 语义不变（Write 全拦）。
- **验收**：MCP 工具 schema 投影（`registry.rs` `tool_defs`）同步更新；`mcp_server.rs` 集成路径手测 scroll/find 可用而 click 仍按开关拦。
- **依赖**：包 A。
- ⚠️ **行为变化**：`agent_actions=false` 时 scroll/find 从"拒"变"通"，**前置决策 D-3**。

### 包 D：主体差异化 + 审计 + 集成验收（Gap-1/4/5，~1 人日）

- **范围**：
  1. `can()` 支持 per-Principal 覆盖档位（settings 新键，如 `api_lan_profile = full|nowrite|readonly`，默认 full 保持现状）；
  2. 鉴权拒绝事件入 audit（现有 `audit/reads|egress` 通道扩展，拒绝原因带 principal+cmd）；
  3. 补 401/403/429 HTTP 集成测试（真 socket 起服务打端点，对齐 Gap-5）。
- **验收**：升级方案口径「矩阵全绿」= 集成测试断言矩阵每格预期值；LAN 降权档位端到端可验证。
- **依赖**：包 A（B/C 建议先行）。⚠️ 前置决策 D-2、D-5。

### 包 E（可选）：dashboard 凭据三轨并轨（~0.5 人日）

- **范围**：Bearer/ticket/表单 token 三轨统一为一个 `Credential` 判定入口（现在分散在 `http.rs:260-262`）；ticket 语义不动。纯收口，无行为变化。
- **依赖**：包 A 之后的任意时点，可并入包 D。

### 拆包依赖图

```
A（单源基座） ──> B（fail-closed，需 D-1 拍板）
   │──────> C（粒度拆细，需 D-3 拍板）
   │──────> D（差异化+审计+集成，需 D-2/D-5）
   └──────> E（可选收口）
```

R4-3 剩余两件（KDF 并发测试、命令录制回放）不在本稿，建议协调器另行派单，不与矩阵包交叉。

## 四、决策点（需高哥拍板，单独列出）

| # | 决策 | 选项与影响 | 本席建议 |
|---|---|---|---|
| **D-1** | **未登记命令 fail-open → fail-closed？** | 现状：handler 在、capabilities 无 Risk → readonly 拦不住（安全洞但无实际案例）。改 fail-closed：更安全，但若有人加 handler 忘登 Risk 会被静默拒，排障成本+1 | **改 fail-closed** + 包 B 的一致性测试兜底（漏登记会在 CI 红而不是线上静默） |
| **D-2** | **LAN 主体要不要独立降权档位？** | 现状 P3 与 P2 同权。加 `api_lan_profile` 三档（full/nowrite/readonly）：多一个 settings 键 + 契约 + UI；不加则矩阵只做"记录现状"不做"差异化" | **加**（矩阵的核心价值就是主体差异化，否则只是把现状表格化）；档位默认 full，行为零变化 |
| **D-3** | **agent_actions 拆细后，scroll/find/wait_for 默认放开？** | 行为变化：现有用户若依赖"关 agent_actions = 全锁交互"的心智，放开读侧交互超出预期 | **放开，但**在 CHANGELOG/回执显著注明 + 保留一键全锁路径（readonly 仍拦全部写） |
| **D-4** | **sock 通道要不要加 token（纵深防御）？** | 0600 已是合理边界；加 token 需同步改 `mcp_server.rs` 握手，破坏现有客户端 | **不加**（威胁模型内收益小、兼容成本实打实），仅给 P1 补审计身份标签（并入包 D-2） |
| **D-5** | **矩阵配置形态**：继续离散 settings 键 vs 一份 JSON 矩阵配置 | JSON 一步到位但违背"contracts.rs 唯一来源"现状，且 UI 要重做；离散键 + `can()` 单源可达成同等效果 | **离散键 + 单源 `can()`**（本稿包 A/C/D 均按此设计）；JSON 留作远期 |

## 五、验收口径（对齐升级方案「矩阵全绿」）

1. 包 D 集成测试：真 socket 起 HTTP 服务，断言 每主体×每资源×每动作 的 401/403/200；

4. 回执注明：行为变化点（仅 D-3）、真机验证缺项。
