# 世界导航页重设计方案

> 2026-10-28 · 依据：taste-skill v2（app screen / list 跑道）+ hallmark Floor
> 现状文件：`src-tauri/resources/newtab/world-nav.html`（301 行，单文件）
> 数据：`src-tauri/resources/worldnav.json`（32 类 / 721 条）
> Before 证据：`.taste-skill/before-worldnav/`（inspect 报告 + 6 张截图）

---

## 一、结论先行

这次不是换皮，是三件事一起改：

1. **撤掉编造指标**。评分（4.3 等）、用户规模（亿级/百万级）、访问速度（快/慢）三类数据没有任何来源，721 条里 173 条评分同为 4.3，是原项目搬来的展示性数据。按 hallmark Floor「不编造指标」，全部撤下，换成真实信号：站数、域名、收藏、最近访问。
2. **卡片墙改成目录**。721 个站用 220px 卡片平铺，本质是同质卡片墙，扫不动、比不了、一屏看不了几个。改成「32 类索引（一屏看完）+ 分类内行列表（一屏 12–14 行）」。
3. **搜索改成真全库**。现在 placeholder 写「搜索 721 个网站」，代码只在当前分类的 `cat.sites` 里过滤（`world-nav.html:218-228`），实际最多只搜到 22–40 条。改成跨 32 类全库搜索，结果带分类和计数。

配套修掉：无 h1、emoji 当图标、星级对比度 1.7:1、12px 文字占 52%、卡片不是链接键盘不可达、手机端 160px 侧栏不折叠。

**工作量**：P0 半天（可用版），P1 3–4 小时（常用/最近 + 收藏闭环），P2 按需。

### 2.2 代码事实

- 单文件 301 行，数据用 `include_str!` 内嵌（`newtab.rs:43-51`），**离线可用**，这个底子要保留。
- 搜索：`sites = cat.sites.slice()` 之后才 `filter(keyword)`，**只搜当前分类**。
- 站点卡片是 `<div class="site-card">`，只有星标和分类是 `<button>`；**Tab 键到不了卡片，Enter 打不开**。
- 收藏存 `localStorage['sb_user_favs']`，与启动页共享，这个机制保留。
- 排序：分类内按 JSON 原始顺序，无任何依据；搜索无排序。
- 打开方式：`window.open(url, '_blank')`，新标签打开，行为正确。

| 项 | 数值 | 说明 |
|---|---|---|
| 总条目 | 721 | 32 类 |
| 唯一 URL | 671 | **50 条重复**（支付宝、知乎、Airbnb、Booking 等跨类重复） |
| 唯一域名 | 656 | |
| 评分取值 | 3.1–4.8，**173 条都是 4.3** | 编造分布特征，非真实评分 |
| 规模取值 | 仅「亿级 / 千万级 / 百万级」三档 | 无法核实 |
| 速度取值 | 仅「快 / 一般 / 慢」三档 | 无法核实 |

## 三、定位：这个页面回答什么问题

**屏幕的一个问题**：*「我要去哪个站？」*

**一个发现**：*721 个站里，你真正会用到的可能不到 30 个。*

这句话决定结构：第一屏先给「你会用的」（搜索 + 收藏 + 常用），再给「全世界的索引」（32 类目录）。不是反过来。

**三个任务，按频率排**：

| 任务 | 占比 | 入口 |
|---|---|---|
| 我知道去哪，直接搜/点 | ~70% | 搜索框、收藏、地址栏 |
| 我想逛逛，看看有什么 | ~25% | 32 类索引 |
| 我要把一个站留住 | ~5% | 行尾星标 |

**与启动页的分工**：启动页是「出发」（搜索 + 常用 + 继续上次），世界导航是「地图」（全量目录 + 分类）。两页共用品牌蓝和收藏 key，不重复堆功能。

**不做**：不做资讯流、不做每日推荐、不做站点评分、不做用户登录。

## 四、设计方向

### 4.1 抽到的风格

`draw.mjs --app --kind workspace --screens list --theme dark` 抽出两个：`true-black-flat`、`data-terminal`。选 **`true-black-flat`**（seed `130469942`）。

理由：世界导航是「夜间、短时、浏览型」界面，不是长时间盯盘的监控台。true-black-flat 的规则（亮度分层、无边框无阴影、颜色只给数据）正好治现在的毛病——卡片描边 + 星级 + emoji 的「模板感」。

**保留它的 move**：地面 → 卡片 → 嵌套面板靠亮度分三步；导航选中只靠文字由 `#b4b4b4` 变 `#fff`；主按钮用反色（白底黑字），不用彩色填充。

### 4.2 品牌映射（`--keep palette` 的等效处理）

抽到的是 lime `#c6f24e`，跟 Shift 品牌蓝冲突，按 skill 的「existing brand」规则换成品牌色：

| 角色 | sheet 原值 | 本项目取值 | 说明 |
|---|---|---|---|
| ground | `#000000` | `#0b0d10` | 冷调近黑，向启动页的深蓝靠但不做渐变 |
| surface | `#111111` | `#14171c` | 卡片/行悬停面 |
| raised | `#2a2a2a` | `#1e2228` | 嵌套面板、输入框 |
| border | `#1a1a1a` | `#23272e` | 仅控件需要 |
| text | `#ffffff` | `#f2f4f7` | |
| muted | `#b4b4b4` | `#b0b6bf` | 次级文字 |
| faint | `#949494` | `#8b919a` | 元信息（仍 ≥4.5:1） |
| accent | `#c6f24e` | `#5b8cff` | 启动页品牌蓝，只用于数据/选中/星标 |
| accent-soft | — | `rgba(91,140,255,0.14)` | 选中分类的底 |

**颜色预算 ≤3%**：accent 只出现在「当前分类标记、收藏星、搜索匹配高亮、焦点环」四处，不上按钮、不上导航底色。

### 4.3 字体：系统栈，不引外链

sheet 给的是 Inter。但世界导航是**离线内置页**，引 Google Fonts 会在断网时退化、在 CEF 里多一次网络等待，违背这个页面的第一约束。因此：

```css
--font: "PingFang SC", "Microsoft YaHei", -apple-system, "Segoe UI", system-ui, sans-serif;
```

这是可陈述的重绘理由（离线硬约束），记录在此。数字统一 `font-variant-numeric: tabular-nums`（站数、计数）。

### 4.4 签名元素：32 类索引

这个产品独有、且是真实数据的东西：**32 个分类和各自的站数**。

做法：把 32 类排成 3 列 × 11 行的「报纸索引」，每行 = 类名 + 站数 + 一句描述。一屏能看完整个「世界」的结构——现在的侧栏要滚 3 屏才看得完。

- 站数是真实计数（`sites.length`），不是编的。
- 行悬停时整行提亮一档（亮度分层，不加边框）。
- 点击整行进分类详情。
- 手机端变单列 32 行，随页面滚动，不做折叠面板。

这不是装饰图形，是导航本体。

## 五、信息架构

```
#/                      首页（搜索 + 收藏 + 32 类索引）
#/c/<id>                分类详情（行列表）
#/c/<id>?q=<kw>         分类内搜索
#/?q=<kw>               全库搜索结果
```

数据来源三层：

| 数据 | 来源 | 状态 |
|---|---|---|
| 32 类 / 721 站（名称、URL、描述） | `worldnav.json` 内嵌 | 已有 |
| 收藏 | `localStorage['sb_user_favs']` | 已有，与启动页共享 |
| 常用 / 最近访问 | 宿主注入 `__WORLD_CONTEXT__`（`history` top 8） | **新增，P1** |

没有宿主注入时（直接开文件），常用区降级为收藏，页面不报错。

### 6.4 平板 768 与手机 390

- 顶栏 48px：左「世界导航」，右「搜索」图标 + 「菜单」。搜索框在手机上折叠成图标，点开变整行（sticky）。
- 内容左右 16px；收藏一行改为 2 行 4 列，或横向滚动一行（`overflow-x: auto`，不撑破页面）。
- 32 类索引变**单列 32 行**，行高 48，随页滚动。
- 分类详情行变两行：名称 + 域名（12px），描述省略；星标固定右侧 44×44 命中区。
- 触控目标 ≥44px；`html/body { overflow-x: clip }`。

## 七、视觉系统

### 7.1 Tokens

```css
:root {
  /* 地面与面 */
  --ground: #0b0d10;
  --surface: #14171c;
  --raised: #1e2228;
  --active: #262b33;
  --border: #23272e;      /* 只给输入框/按钮 */

  --text: #f2f4f7;
  --muted: #b0b6bf;

  /* 品牌 */
  --accent: #5b8cff;
  --accent-soft: rgba(91,140,255,.14);

  --font: "PingFang SC","Microsoft YaHei",-apple-system,"Segoe UI",system-ui,sans-serif;
  --fs-h1: 24px; --fs-h2: 20px; --fs-section: 15px;
  --fs-body: 14px; --fs-meta: 12px;
  --sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px;
  --sp-5: 24px; --sp-6: 32px; --sp-7: 48px;

  --row: 52px; --nav-row: 44px;
}
```

字号五档封顶：24 / 20 / 15 / 14 / 12。

### 7.2 组件规格

| 组件 | 规格 |
|---|---|
| 顶栏 | 48px，无边框，与地面同色；滚动时内容从下方过，不加线 |
| 搜索框 | 48px 高，`--raised` 底，focus 时 1px accent 边 + 2px 外扩焦点环；左侧无放大镜 emoji，用 CSS 画或纯文字占位 |
| 分类索引行 | 44px，`--surface` 底，圆角 12，悬停升到 `--active`；类名 14/500，站数 12 右对齐 faint，描述 12 截断 |
| 站点行 | 52px，默认透明，悬停 `--surface`；行尾星标 32×32 |
| 收藏星 | 文字 `☆/★` 是 emoji 边缘，改用内联 SVG 星（1.5px 描边），`aria-pressed` |
| 主按钮 | 反色：`#f2f4f7` 底 + `#0b0d10` 字，36px 高，圆角 8；全页最多一个（「添加收藏」） |
| 焦点环 | `:focus-visible` 2px `--accent`，offset 2px，即时出现 |
| 动效 | 只有 120ms 的 background/opacity；`prefers-reduced-motion` 全关 |

**禁止**：emoji、渐变、阴影、玻璃/backdrop blur、1px 装饰细线、彩色图标块、星级评分、假指标、大圆角胶囊按钮。

### 7.3 图标策略

- 分类**不用图标**，纯文字（32 个 emoji 是现在最大的「模板感」来源）。
- 站点行用 28px 首字块：中文取首字，英文取首字母，域名哈希只决定**亮度档**（三档灰），不引入色相。
- 不做 favicon 外链（离线优先）；P2 再考虑本地缓存。

## 九、交互与状态

### 9.1 搜索

- 输入防抖 120ms；空串回到首页态。
- 全库匹配，结果上限 100；排序：名称前缀 → 名称包含 → 域名 → 描述。
- `Enter` 打开第一条；`Esc` 清空并回到首页；`/` 从任意位置聚焦搜索框（输入框内不劫持）。
- 搜索时 URL 同步 `#/?q=`，刷新/返回可恢复。
- 结果行显示所属分类，跨类重复的显示「+2 类」。

### 9.2 键盘与语义

- 站点行是 `<a href>`，不是 div；`Tab` 可达，`Enter` 打开；新标签打开（`target="_blank" rel="noopener"`）。
- 分类索引行是 `<a href="#/c/...">`。
- 页面唯一 `h1`「世界导航」；分类详情 `h2`；区标题 `h2`。
- 收藏按钮 `aria-pressed` + `aria-label="收藏 知乎"`。
- 跳转后焦点管理：进分类详情，焦点移到 `h2`；返回，焦点回原分类行。

### 9.3 收藏

- 与启动页共享 `sb_user_favs`，结构 `{name,url,icon}` 不变，避免破坏现有联动。
- 星标即时切换，`localStorage` 写入失败时回滚并提示一行。
- 「添加收藏」弹窗保留，字段：名称、网址；图标字段撤掉（emoji 输入没有意义），存 `icon:''` 兼容旧数据。

### 9.4 性能

- 首屏只渲染 32 类索引（32 行）+ 收藏（≤8），不渲染 721 行。
- 搜索/分类详情按需渲染，单次最多 100 行。
- 目标：打开到可交互 < 100ms（数据内嵌，无网络请求）。

## 十二、风险与取舍

1. **撤评分会不会显得信息少？**
   会少一列，但补上真实的三样：站数（分类行）、域名（行内）、收藏状态。信息密度从「重复的假数据」换成「可操作的真数据」，扫视效率反而高。
2. **32 类索引一屏 32 行会不会太密？**
   3 列 × 11 行、行高 44、字号 14/12，密度与「报纸索引」相当，是刻意的目录形态；不是卡片墙。390px 下单列 32 行，靠搜索优先解决长滚动。
3. **离线字体与 sheet 的 Inter 冲突**：已按「品牌/环境硬约束」重绘，记录在此；不引外链字体。
4. **721 行 DOM 性能**：首屏不渲染全量；搜索/分类按需，上限 100 行。
5. **与启动页视觉不统一**：本方案先在世界导航落地「纯黑 + 品牌蓝」；启动页现有渐变/玻璃/紫蓝按钮与新页并排会割裂。建议下一步把启动页收口到同一套 tokens（单独任务，不在本次范围）。
6. **数据清理误删风险**：P0 只做「界面不读」，不动 JSON；P1 的重复/错配清单人工确认后再改。
