## 〇、为什么学 Brave（一句话）

全行业唯一"**小团队 + 开源 + 紧跟 Chromium 上游 + 做出真差异化**"的完整样板——它的每个维度都值得单独对照一遍。

借鉴三档：**A 直接借鉴** / **B 改造借鉴** / **C 不借鉴（说明理由）**。

## 一、技术底座与架构

**Brave 做法**：
- **patch-stack 模式**：不 fork，维护 brave-core 补丁层；`sync` 脚本自动跟 Chromium 升版重贴补丁；冲突有标准流程（`Conflict-resolved patches from Chromium XXX to YYY`、`pnpm run update_patches`）——升版是**日常流水线**而非大事件
- 移除 Google 服务依赖（"What Brave removes from Chromium"有公开清单），隐私改造以补丁形式记录在案
- 上游组件原样保留（沙箱/crashpad/MEI 等），自有功能全部以"加层"实现——本机物证

**我们现状**：Tauri + WebKitGTK"借引擎做外壳"，路线同构；对 WebKit 无补丁层（纯应用层）。
**借鉴（A）**：① 若未来需 patch WebKitGTK（如视频闪烁类修复下沉），直接采用 Brave 的"补丁层 + 自动 rebase + 冲突记录"方法论；② 建立"上游升版例行流水线"意识——升 WebKit/系统依赖应为常态，有 checklist 与回滚预案。

## 二、性能工程

**Brave 做法**（语言包实证）：
- **Memory Saver**：不活跃标签自动释放内存，回来自动恢复（"frees up memory from inactive tabs...automatically become active again"）
- **Energy Saver**：限后台活动与视觉特效（平滑滚动、视频帧率）
- **预加载**（含隐私版：站点请求预加载走 Brave 服务器隐藏身份）
- 后台行为控制（关窗后是否继续运行后台应用）

**我们现状**：标签休眠体系已有（设置项：标签休眠时长/阈值）✅
**借鉴（B）**：① 对照补"能耗模式"评估（笔记本场景）；② 预加载的"隐私中转"设计思路可评估（低优先）；③ 把"休眠恢复体验"打磨成卖点（当前已有基础，缺宣传点）。

## 三、安全工程

**Brave 做法**：
- Chromium 全量安全基座（沙箱、site isolation、crashpad）+ 及时跟上游打安全补丁（升版流水线是安全生命线）
- **HackerOne 漏洞赏金**（agentic 漏洞双倍悬赏）+ 主动安全研究（prompt injection 系列、漏洞负责任披露）
- Safe Browsing（隐私化：经隐私服务器隐 IP 再查）+ 增强保护选项

**我们现状**：加固指纹已达标（PIE/NX/RELRO）；缺"符号剥离/独立调试文件"发布纪律（见 Chrome 对比文档）。
**借鉴**：① （已在 Chrome 对比文档 P0）发布物最小化；② （B）建立轻量漏洞响应流程（哪怕人少：报告入口 + 定级 + 修复时限 + 披露原则）；③ （C 参考）赏金制度暂不适用，记入长期。

## 四、隐私工程（Brave 的王牌）

**Brave 做法**：
- **Shields**：广告/追踪/指纹三线拦截 + 分级（Standard/Aggressive）+ 站点级开关 + 降盾救援 + 报修闭环
- **farbling**：per-session + per-eTLD+1 种子确定性随机化（同站稳定、跨站跨会话变化）；已在《Brave分析》详解
- **Tor 私密窗口**、WebRTC IP 策略、DNS 隐私、`Sec-GPC` 请求头（法规先行）
- Cookie 分区、`Forget me on close`、指纹类别明细（Audio/WebGL/WebGPU/Screen…）

**我们现状**：拦截+清参+隐私注入已有计数（StatusBar 战绩）；反指纹档位在设置；GPC 已有；盾面板交互缺（详见设计稿 F1）。
**借鉴（A）**：设计稿 F1 盾面板直接对标 Brave 新形态（集成站点信息）；farbling 语用照抄（会话+域种子）。

## 五、AI 与智能化（2026 主战场）

**Brave 做法**：
- **Leo**：内置助手 + **Skills**（快捷技能）+ 记忆功能 + 模型可选
- **Agentic browsing**（2026-05 全通道）：隔离 profile/双模型/手动调用/全程可见——护栏体系完整（详见《Brave分析》）
- **AI Mode**：标签页问答（"Ask questions about this tab"）、AI 历史搜索（`@history`）、**AI 生成主题**（风格/情绪自选）
- **Brave Translate**：自研隐私翻译（108 语言；Lingvanex 托管自有基础设施；不存内容、删 IP）
- On-Device AI 选项；"站点可请求打开 AI"（`Sites can ask to open Leo AI chat`）

**我们现状**：AISidebar + 随手问 + CommandPalette + WebMCP 布局；翻译面板已有（引擎方案待对照）。
**借鉴**：① （A）技能化（设计稿 F6）；② （A）"AI 主题生成"是新潮玩法，我们 NTP 已有壁纸体系，可低成本跟一个"AI 壁纸/主题"；③ （B）翻译走"隐私优先"路线对照（Brave 供应商托管方案 vs 我们现方案——**建议专项对比后定**）；④ （A）护栏清单自检（已在《Brave分析》列 P0）。

## 六、功能体系 →（详见设计稿，此处只列全清单）

盾面板 / NTP 增强 / 侧边栏面板（书签·阅读列表·Playlist·News）/ 垂直标签·树状标签 / 容器 / AI 技能 / 隐私门禁 / 引导 / 阅读模式 / 设置复查。
**不抄**：Rewards、Wallet、VPN、Talk、News、Email aliases、Playlist（战略取舍，见设计稿"不借鉴清单"）。

## 七、界面布局与信息架构 →（详见设计稿）

重点：盾进地址栏站点区（一站式）、站点信息归并、主菜单分组复查。**新增借鉴**：Brave 的"**Resume your journey**"（历史恢复入口）、**分享面板**（QR/投屏/send to assistant）、**标签搜索**（Tab search）。

## 八、视觉与主题系统（★新维度）

**Brave 做法**（语言包实证）：
- **几十套官方配色**（Default Brave/灰系/午夜蓝/暖色/冷色/各种深浅变体…）+ 自定义 Color picker + Hue 滑杆
- **AI 生成主题**（2026：输入风格/情绪生成主题，含历史管理）
- **Ultra dark** 主题、跟随系统/设备色、组织强制主题（企业）
- 字号/行距/密度/圆角等外观微调项丰富

**我们现状**：tokens.css 体系完善（圆角/字号/层级等原语），主题色/自定义壁纸/动态背景已有。
**借鉴（B）**：① 官方配色库扩充（低成本高观感——直接对标色板）；② "AI 壁纸/主题"评估（联动 AI 能力）；③ 深色模式打磨（Ultra dark 级）。

## 九、交互与效率

**Brave 做法**：完整快捷键体系（全菜单键盘可达）；Quick commands；拖拽（标签/书签）；QR 分享；"Send tab to self"；读屏键盘焦点测试基础设施（a11y label 全覆盖）。
**我们现状**：CommandPalette 已有；快捷键体系已有部分（需对照盘点）。
**借鉴（A）**：对照 Brave 快捷键全表做一次"快捷键矩阵盘点"，补齐高频缺口（成本低）。

## 十、无障碍 a11y

**Brave 做法**：Chrome 系全量键盘可达 + a11y label 传统；**Live Caption**（离线实时字幕）；**Caret browsing**（F7 光标浏览）；阅读模式的**全套阅读辅助**（朗读/语音速度/高亮跟读/字号/行距/字距/对比度/焦点框/低对比主题）；"Focus inactive popup"等细节；但社区公认其"读文本"等仍缺失（非领先者，是 Chrome 基线水平）。
**我们现状**：R4-6 a11y 专项进行中（审计+补验+修复包），axe 10 场景零违规达成——**起点已好**。
**借鉴（B）**：① 阅读模式辅助功能包（对标 Brave 阅读辅助清单，正好可用于我们阅读模式 UI 补全）；② Live Caption 类"新能力"评估（如果媒体体验是卖点）；③ **反向机会**：Brave a11y 只是基线，我们若把 a11y 做深（读屏体验、键盘全流程）可成差异化**卖点**。

## 十一、国际化 i18n

**Brave 做法**：108 语言；翻译引擎自研路线（隐私牌）；本地化资源体积管理（locales 80MB 独立包）；组织区域策略（组织可管语言/快捷键/NTP）。
**我们现状**：R4-5 i18n 拆包进行中（清单 614 行/语言包按节拆分懒加载）。
**借鉴（B）**：① 我们 i18n 架构（按节懒加载）比 Brave 的整包更先进——**保持并宣传**；② 翻译引擎"隐私优先"对照（同五-③）；③ 多语言 QA 流程参考（伪本地化测试——**建议引入**）。

## 十二、设置与策略体系

**Brave 做法**：设置分类完整（外观/隐私安全/Shields 全局/内容过滤/数据/同步/性能/Web3/系统）；**Group Policy 企业体系全套**（组织强制扩展、主题、快捷键、NTP、代理、证书——"Managed by your organization"）；"Review key controls"复查机制。
**我们现状**：SettingsDialog 4 组 10 分区已成型；无企业策略能力。
**借鉴**：① （A）"关键控制复查"增强（设计稿 F10）；② （C→长期）企业策略——暂不适用，记入路线参考；③ （B）设置项对照 Brave 缺项盘点（如"本地历史保留期限"这类我们是否有）。

## 十三、同步与身份

**Brave 做法**：**Sync chain**（无中心账号依赖，链式设备同步，密钥在用户手中）；Brave Account（自有账号体系，去 Google 化）；"数据主权"叙事。
**我们现状**：无同步体系。
**借鉴（B/C）**：同步是"要不要做、何时做"的战略题——建议**列入产品路线讨论**（账密/书签同步是用户留存关键；Brave 的"链式密钥"模式比中心化账号更贴合我们隐私定位，可作为设计参考）。本期仅立案，不上工期。

## 十四、更新与分发

**Brave 做法**：四通道（Release/Beta/Dev/Nightly）；Linux 多包形（deb/rpm/**Flatpak**/snap）；自动更新 + "Relaunch to finish updating"；WebView 与浏览器同包分发（Chromium 特性）。
**我们现状**：deb 打包（5.8.3 已装）；更新机制待盘点（有无自动更新？）。
**借鉴（B)**：① 评估"稳定/测试"双通道（内测朋友的体验通道——他们已有 beta 用户场景吗？）；② Flatpak 分发评估（跨发行版覆盖，Livestream 用户福音）；③ 更新提示 UI 对标（"Nearly up to date!"文案体系）。

## 十五、扩展与生态

**Brave 做法**：Chrome 扩展商店兼容（桌面 + Android 部分）+ 自建精选；Web Discovery Project（匿名搜索信号众筹）；Wayback、Talk、独立搜索索引。
**我们现状**：extensions 体系（userscripts + 自定义扩展 + 扩展管理 UI）；WebMCP 布局（ADR 已有）。
**借鉴**：① （A）扩展兼容性是硬需求——对照我们 extensions 能力盘一次"常用扩展可用性"测试；② （B）"Web Discovery"类众筹数据的隐私产品思路——低优先记档；③ （A）WebMCP 继续按 ADR 推进（我们在"站点主动接入 AI"上甚至有先行优势）。

## 十六、测试与质量工程

**Brave 做法**（公开信息有限，谨慎标注）：CI 全量构建矩阵；Nightly 通道即"持续性灰度"；patch 冲突用测试兜底（改 patch 跑全量）。公开证据有限，不完全掌握。
**我们现状**：测试体系扎实（vitest/clippy/jsdom/axe/a11y 快照/看护器/watchdog/自检）。
**借鉴（B）**：**"Nightly 式内部试用通道"**——我们已有 nightly 打包节奏（这次 5.8.3 的一体化构建安装流程），可正式化为"内部通道=先行验证"，与十四-①合并。

## 十七、开源治理与社区

**Brave 做法**：brave-core 开源（patch 全公开可审计）；安全研究博客系列（prompt injection 等——**用研究建立信任**）；透明报告；社区论坛活跃；HackerOne。
**我们现状**：开源状态（GitHub 镜像刚推、公开仓库在 gaojinha/shift-browser）；社区无。
**借鉴（B）**：① 安全/技术博客习惯（把我们的分析文档式研究对外发布——"透明建立信任"的长期资产；至少先内部沉淀）；② 开源边界设计（开源哪部分、留哪部分——future 决策，先记档）。

## 十八、品牌与增长

**Brave 做法**：
- 标语："**Privacy. By Default.**"；"Experience the web without being watched"
- **Reviewer's Guide**（给评测者的完整材料包——媒体友好的教科书做法）
- 对比页（vs Chrome/FF/Edge/Safari 逐项对比表——数据化差异化）
- Onboarding 引导（主题/导入/诊断选择，温和不胁迫）
- 增长机制：默认浏览器引导流程、NTP 广告（不抄）

**我们现状**：品牌语体系待建立；无对比页/材料包。
**借鉴（A/B）**：① （A）**做一份"Shift vs Brave/Chrome"对比页模板**（我们的 AI 原生 + MCP + 轻量是对比利器）；② （B）Reviewer's Guide 式材料包（未来推广时现成）；③ （A）onboarding 收尾文案对标"Privacy by Default"级别的承诺感（设计稿 F8 已列）。

## 十九、商业模式与合规

**Brave 做法**：隐私不靠卖数据——靠搜索广告（Brave Ads/隐私广告）+ Rewards（BAT 激励）+ 高级服务（VPN 等）；GPC 法规先行（2027 强制前就支持）；CCPA/GDPR 合规叙事。
**我们现状**：无商业化功能；GPC 已支持 ✅。
**借鉴**：① （C）Rewards/VPN 等商业模式不抄（战略不匹配）；② （B）**合规先行意识**：GPC 已先走一步，继续跟踪（如 2027 法规变化对浏览器要求）；③ 记档："隐私承诺"是产品资产，商业化应避开数据路径。
