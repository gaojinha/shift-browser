## 二、语言包结构设计

### 2.1 命名空间（section）划分方案

按**设置节 + 功能域**拆分，每个 section 对应一个可独立懒加载的 locales 文件：

```
src/i18n/
├── index.ts                          # 骨架（现有，不动）
├── i18n.test.ts                      # 防漂移测试（现有，不动）
└── locales/
    ├── zh-CN.ts                      # 入口（现有，聚合各节）
    ├── en.ts                         # 入口（现有，聚合各节）
    ├── progress.ts                   # TranslateProgress 进度文案（现有，抽离）
    ├── update.ts                     # 更新 toast 文案（现有，抽离）
    # ── 新增 ─────────────────────────────────────────────
    ├── navigation.ts                 # 导航栏/标签栏（AddressBar + TabBar + VerticalTabBar + StatusBar + BookmarksBar + SpaceSwitcher）
    ├── dialogs.ts                    # 对话框族（Bookmarks/Passwords/Userscripts/History/Downloads/Groups/Session/Certificates）
    ├── translate.ts                  # TranslatePanel + TranslateProgress 迁移后统一在此
    ├── command-palette.ts            # CommandPalette
    ├── settings-general.ts           # GeneralSection
    ├── settings-appearance.ts        # AppearanceSection
    ├── settings-ai.ts                # AiSection
    ├── settings-privacy.ts           # PrivacySection
    ├── settings-data.ts              # DataSection
    ├── settings-mcp.ts               # McpSection
    ├── settings-extensions.ts        # ExtensionsSection
    └── ui.ts                         # 通用 UI 文案（UiSwitch toggle、SettingCard placeholder 等）
```

### 2.2 Key 路径命名规范

采用 `section.component.key` 三段式（section 为上述文件名去掉后缀）：

```typescript
// 示例：navigation.address-bar.back
navigation: {
  'address-bar': {
    back: '后退',
    forward: '前进',
    refresh: '刷新',
    home: '主页',
    addressLabel: '地址栏',
    searchPlaceholder: '输入网址或搜索...',
    // ...
  },
  'tab-bar': {
    close: '关闭标签',
    newTab: '新建标签',
    // ...
  },
  'status-bar': {
    // ...
  },
  bookmarks: {
    // ...
  },
}
```

### 2.3 懒加载策略（对接 T-008 框架）

**Phase 1（当前骨架）**：全量导入（现有 `messages: {'zh-CN': zhCN, en}` 不动），保证 `t()` 全量可用，测试先行。

**Phase 2（R4-5 完整版）**：按需懒加载。在 `index.ts` 引入 `defineLocaleMessage` + `vue-i18n` 的 `locale` 动态注册 API：

```typescript
// 示例（Phase 2 设计，本轮不实现）
async function loadLocale(name: string, path: string): Promise<void> {
  const mod = await import(/* webpackChunkName: "locale-[request]" */ path)
  i18n.global.setLocaleMessage(name, mod.default)
}
// 在 SettingsDialog 打开时预加载 settings-* 各节
// 在 AddressBar 挂载时不加载（已在首屏）
```

**本轮（Phase 1）只做全量合并入 `zh-CN.ts` / `en.ts`**，结构先落地，懒加载留接口。

## 三、批次划分（全量迁移 N 包）

> 排序原则：优先级由高到低（用户感知面 > 设置面 > 次要面）；每包独立可交、可回滚；批次间串行依赖最小。

### 包 A：浏览器核心导航链（最高优先级，~2 人日）

- **范围**：`AddressBar.vue`（29 处）+ `TabBar.vue`（18 处）+ `VerticalTabBar.vue`（14 处）+ `StatusBar.vue`（10 处）+ `BookmarksBar.vue`（7 处）+ `SpaceSwitcher.vue`（6 处）。
- **合计**：~84 处硬编码字符串 + 约 15 处模板文本。
- **依赖**：无。**先做**（用户每次打开都看到）。
- **验收**：
  1. `vue-tsc --noEmit` 零错误；
  2. `npx vitest run src/i18n/i18n.test.ts` 全绿（键集一致性）；
  3. 各组件新增 `*.test.ts`，断言主要文案走 `t()` 后的值（中文/英文双语）。
- **风险**：`AddressBar` 中 `readerTip` 动态文本（来自 Rust backend）需单独处理——**不在本次迁移范围**，标记为 `TODO`，后续批次单独收口。

### 包 B：对话框族（高优先级，~1.5 人日）

- **范围**：`BookmarksDialog.vue`（14 处）+ `PasswordsDialog.vue`（5 处）+ `UserscriptsDialog.vue`（6 处）+ `HistoryDialog.vue`（4 处）+ `DownloadsDialog.vue`（1 处）+ `GroupsDialog.vue`（4 处）+ `SessionDialog.vue`（5 处）+ `CertificatesDialog.vue`（1 处）。
- **合计**：~40 处硬编码字符串。
- **依赖**：包 A 完成后（对话框不阻塞主导航体验）。
- **验收**：同上；`UiDialog title` 属 props 传入，需在每个调用方（包 A 中）同步改。

### 包 C：功能面板（中优先级，~0.5 人日）

- **范围**：`TranslatePanel.vue`（7 处）+ `CommandPalette.vue`（4 处）+ `AISidebar.vue`（3 处）+ `TranslateProgress.vue`（已有，微调整合到 `translate.ts` 节）。
- **合计**：~14 处。
- **依赖**：无。可与包 A/B 并行（但建议串行避免冲突）。
- **验收**：`TranslateProgress` 迁移后整合进 `locales/translate.ts`（与 `progress.ts` 合并决策见第四节）。

### 包 D：设置节迁移（中优先级，~2 人日）

- **范围**：`GeneralSection.vue`（9 处）+ `AppearanceSection.vue`（10 处）+ `AiSection.vue`（3+7 处）+ `PrivacySection.vue`（13+15 处）+ `DataSection.vue`（5+4 处）+ `McpSection.vue`（5+2 处）+ `ExtensionsSection.vue`（1 处）+ `ApiSection.vue`（1 处）+ `ui/SettingCard.vue`/`SegControl.vue`/`PrivacyDataCard.vue`/`AutomationCard.vue`（共 5 处）。
- **合计**：~77 处 + 约 30 处模板文本。
- **依赖**：包 A（`SettingsDialog.vue` 本身无硬编码，但导航链完成后 `t()` API 稳定）。
- **验收**：键集一致性全绿；各子节组件迁移后双语截图可人工核对。

### 包 E：收尾 + 全局补漏（低优先级，~0.5 人日）

- **范围**：`ui/UiSwitch.vue`（1 处）、`AppToast.vue`（toast 文案集中化）、`CertWarning.vue`、其余散落 `title`/`aria-label`（经 grep 确认遗漏处）。
- **验收**：`grep -rE 'title="[^"]{3,}"|aria-label="[^"]{3,}"' src/ --include="*.vue" | grep -v test | grep -v node_modules` 返回 0 条（除动态绑定外）。

    │                  │
    └──> B（对话框）    └──> E（收尾）
         │
         └──> C（功能面板，可并行）

## 四、关键决策点（需高哥拍板）

| # | 决策 | 选项与影响 | 本席建议 |
|---|---|---|---|
| **D-1** | **`progress.ts` + `translate.ts` 是否合并？** | 合并（`translate.ts`）：语义清晰（翻译进度属于翻译功能），但 `update.ts` 保持独立。分离（各自独立）：粒度更细，懒加载更精准。 | **合并**（`translate.ts` 覆盖 `progress.*` + `translate.*` 所有键），`update.ts` 保留独立（更新 toast 是独立生命周期）。 |
| **D-2** | **`readerTip` 动态文本是否纳入本次迁移？** | 纳入：需 Rust backend 也 i18n，改动面大，超出本轮范围。排除：标记 `TODO`，后续批次单独处理。 | **排除**（标记 TODO）。`readerTip` 来自 Rust backend（`llmstxt.rs` 返回），需在后端也做 i18n 支持才能完整迁移，是独立大活。 |
| **D-3** | **`UiDialog title` prop 的迁移策略？** | 策略 A：每个调用方改 `title="书签管理器" → title="$t('dialogs.bookmarks.title')"`，键设在 `locales/dialogs.ts`。策略 B：在 `UiDialog` 内部用默认值兜底，调用方按需传。 | **策略 A**（键集一致性强，便于防漂移测试捕捉遗漏）。 |
| **D-4** | **懒加载 Phase 2 何时落地？** | 现在落地（本轮增加动态 import 脚手架）。延后（本轮只做全量合并，Phase 2 另行派单）。 | **延后**（本轮只做全量合并 + 懒加载脚手架预留接口，不实际接入 `defineAsyncComponent`）。 |
| **D-5** | **设置节语言包是合入单一 `settings.ts` 还是按节拆文件？** | 合入（`locales/settings.ts`）：键路径长但文件少，维护简单。拆分（`settings-general.ts` 等）：粒度细，与包 D 分节一一对应，但文件多。 | **按节拆分**（`settings-general.ts` 等），与包 D 的拆包边界一致，便于分批验收。 |
