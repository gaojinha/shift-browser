# 从浏览器导入——独立模块设计方案 v3

> 日期：2026-10-18 ｜ 作者：王二狗 ｜ 状态：**设计稿，P0 已完成，待派单落地**
>
> **版本演进**（别再照旧版做）：
> - **v1**：误把 Chrome 判成"空的"（只读 `Default/Bookmarks` 和 `Login Data`），且思路是"全部塞进快捷访问"——**作废**。
> - **v2**：修正 Chrome 数据源（密码在 `Login Data For Account`，书签在 `AccountBookmarks`），但仍按"整合进快捷访问"设计——**作废**。
> - **v3（本版）**：高哥明确——**不整合**，要一个**独立的导入模块**；入口在**启动页侧栏**；**密码和书签分开**，各给一个"从浏览器导入"按钮；导入后**各归各位**（密码→密码库，书签→书签栏/书签管理器）；**快捷访问这期不做**。

---

## 0. 一句话

在启动页侧栏加一个"导入"图标 → 打开**导入模块**；模块里**密码块**和**书签块**各有一个「从浏览器导入」按钮，扫描本机 Chrome/Brave → 解密 → 分别写进**密码管理器**和**书签管理器**。导入模块只当搬运工，不当储物间。

### 3.3 加密可解（P0 实测）

| 浏览器 | keyring label | 实测 |
|---|---|---|
| Chrome | `Chrome Safe Storage` | **63/63 成功** |
| Brave | `Brave Safe Storage` | **20/20 成功** |

算法（Chromium `os_crypt_linux.cc` 原文 + 实测）：
1. 密钥密码 = keyring 条目**值本身**（24 字符 base64 串，**不 base64 解码**）
2. `key = PBKDF2-HMAC-SHA1(password, salt="saltysalt", iterations=1, dklen=16)`
3. 密文去 3 字节 `v11`/`v10` 前缀 → **AES-128-CBC**，IV=16 空格（0x20）
4. PKCS7 去填充 → 明文

> ⚠️ **前提**：当前 Linux 会话已解锁 keyring。
> ⚠️ **安全事实**：v11 可解 ⇒ 同一会话内能读 keyring 的进程都能还原密码（Chromium Linux 固有弱点）→ **"明文零落盘"是硬要求**。

## 4. 模块设计

### 4.1 入口：启动页侧栏新图标（照抄 AI 链路）

1. **`resources/newtab/index.html` `#iconBar`**：在 `#aiBtn` 前插一个按钮
   ```html
   <button class="icon-btn" id="importBtn" title="从浏览器导入" aria-label="从浏览器导入">
     <svg …/><!-- 下载入仓箭头风格图标 -->
   </button>
   ```
2. **同文件 JS（1527 行 `aiBtn` 处理旁）**：
   ```js
   document.getElementById('importBtn').addEventListener('click', function () {
     window.__TAURI_INTERNALS__.invoke('open_import_from_newtab').catch(function () {})
   })
   ```
3. **`src-tauri/src/newtab.rs`**：加命令
   ```rust
   /// 启动页侧栏「导入」图标 → 通知主界面打开导入模块
   #[tauri::command]
   pub fn open_import_from_newtab(app: AppHandle) {
       let _ = app.emit(EVENTS::OPEN_IMPORT_FROM_NEWTAB, ());
   }
   ```
   并在 `lib.rs` 的 `generate_handler!` 注册。
4. **`src-tauri/src/contracts.rs`**：新增常量 `OPEN_IMPORT_FROM_NEWTAB = "open-import-from-newtab"`，加入常量表 → **跑 `cargo test --lib ts_export`** 重生成 `src/constants.ts`，同步改单测期望值。
5. **`src/App.vue`**：`onEvent(EVENTS.OPEN_IMPORT_FROM_NEWTAB, () => showImport.value = true)`；`showImport` 进 `ref` 与"打开面板集合"（对齐 174/179 行现有 `passwords`/`bookmarks` 写法）；模板挂 `<ImportModule :show="showImport" @close="showImport = false" />`；Esc 关闭分支（457/465 行写法）同样补一条。

### 4.2 模块主体：`ImportModule.vue`（新建）

> 复用 `UiDialog.vue` 体系，跟 `PasswordsDialog` 同一套外壳与生命周期。

```
┌─ 从浏览器导入 ────────────────────────────────┐
│ ① 已发现的浏览器（只读扫描，不含明文）          │
│   Chrome 154   书签 120   密码 63   ✔ 可解密   │
│   Brave        书签 127   密码 20   ✔ 可解密   │
│                                                 │
│ ② 密码 ────────────────────────────            │
│   [ 从浏览器导入密码 ]  ← 独立按钮               │
│   预览：仅站点+用户名条数（绝不显示密码明文）     │
│                                                 │
│ ③ 书签 ────────────────────────────            │
│   [ 从浏览器导入书签 ]  ← 独立按钮               │
│   预览：文件夹层级树 + 总数                      │
│                                                 │
│ 回执：密码 X 条入密码库 / 书签 Y 条入书签管理器   │
└─────────────────────────────────────────────────┘
```

- **两块互不耦合**：可只导书签不导密码，反之亦然。
- **密码预览**：只给"站点 / 用户名 / 条数"；**密码字段一律 `••••`**，不提供"显示明文"。
- **书签预览**：展示文件夹层级树（复用 `BookmarkFolderTree.vue` 的树形样式）+ 总数 + 重复项预估。
- **无需设主密码**：主密钥**首次启动已自动生成**（`app_data/master.key`，权限 600，实测已存在）；导入直接写入即可，**不阻塞、无需用户任何操作**。
- **去重口径**：后端有 `UNIQUE(domain, username)` 索引，导入时按此去重，重复项跳过并在回执里报数。

### 4.3 落点对接

| 块 | 导入后 | 用户在哪看到 |
|---|---|---|
| 密码 | 走 `stores/passwords` → 后端 `save_password` → `loadPasswords()` 刷新 | 密码管理器（`PasswordsDialog`） |
| 书签 | 复用书签写入内核 → 刷新 bookmarks store | **书签栏**（`BookmarksBar`）+ **书签管理器**（`BookmarksDialog`） |

## 5. 后端设计

### 5.1 新模块 `src-tauri/src/import_browser.rs`（新建）

```rust
//! 从本机浏览器导入（只读源 + 解密 + 落库）
//! 安全：源库只读 WAL 快照；明文零落盘；keyring label 硬映射不猜
```

### 5.2 命令

| 命令 | 作用 |
|---|---|
| `open_import_from_newtab` | 启动页侧栏图标 → 主界面开模块 |
| `scan_browser_import()` | 扫多 profile × 多文件源，返回各类型**计数 + 可解密性**（**不含任何明文**） |
| `import_passwords_from_browser(browser)` | 遍历 `Login Data For Account` + `Login Data` → 内存解密 → 写 vault → 返回 `{imported, skipped_empty, failed}` |
| `import_bookmarks_from_browser(browser)` | 遍历书签 5 源合并去重 → 写书签库 → 返回 `{imported, duplicates, failed}` |

### 5.3 核心规则（v1/v2 的错逐条防死）

1. **多源合并，不是二选一**：
   - 书签：`AccountBookmarks` → `Bookmarks.bak` → `Bookmarks` → `EncryptedAccountBookmarks2` → `EncryptedBookmarks2`
   - 密码：`Login Data For Account` → `Login Data`
   - **按 URL（书签）/ 站点+用户名（密码）去重合并**
2. **WAL 快照**：复制 `<file>` + `-wal` + `-shm` 到临时目录再读，读完即删（浏览器运行中必做）。
3. **keyring label 硬映射**：Chrome→`Chrome Safe Storage`，Brave→`Brave Safe Storage`；取不到则该浏览器密码块降级提示"无法解密"，不猜不硬试。
4. **临时目录权限 0700**，导入完成即 `rmtree`，不留解密中间物。
5. **书签 URL 过滤**：拒 `javascript:`/`data:`/`file:`/`blob:`/`vbscript:`（复用 `normalize_quick_site_url` 口径，同一类判定只许一份实现）。

### 5.4 单测（AGENTS.md 契约铁律）

- 多源优先级：`AccountBookmarks` 优先于 `Bookmarks`；全空时兜底加密源。
- WAL 快照：含 `-wal` 数据能读到，只读主库读不到（复现 v1 的坑）。
- 去重：Chrome 120 + Brave 127 合并去重逻辑正确。
- 空密码跳过不写入。
- 危险 scheme 书签被拒。
- `open_import_from_newtab` 事件常量进契约（`ts_export` 守卫）。

## 6. 安全红线

1. **密码明文零落盘、零日志、零回显**；导入完立即清内存；回执只报条数。
2. **源库只读**：导入前后源文件 mtime/hash 不变（验收校验）。
3. **不扫**无数据/测试目录（`brave-anon`、`headless`、`playwright-mcp`）。
4. **用户显式动作**：不静默导入，两个按钮各自独立确认。
5. **不迁** Cookie/登录态/扩展（会话安全红线）。

## 8. 验收标准

**四关口**：`cargo clippy --all-targets` 零警告；`cargo test --lib` 全过；前端 `vitest` 全过；`npm run lint` / `npm run build` / `vue-tsc --noEmit` 过。

**功能**：
- 启动页侧栏出现"导入"图标，点击**打开导入模块**。
- 书签导入：Chrome 120 条 + Brave 127 条全部入库（**不能读到 0**），文件夹层级与源一致；导入后**书签栏和书签管理器都能看到**。
- 密码导入：Chrome 63 条 + Brave 20 条入 vault（6 条空密码跳过）；**回执只报条数，任何界面/日志无明文**；导入后**密码管理器能查到**。
- 两块独立：只导书签不导密码 / 只导密码不导书签，均可。

**安全**：危险 scheme 书签被拒；源库零改动（mtime/hash 校验）；临时目录清理干净。
