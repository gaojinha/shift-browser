## 1. 背景与问题

当前本地开放 API（`src-tauri/src/api.rs` socket）读取页面内容的出口只有两个：

- `screenshot`：返回像素（PNG 落盘），需视觉模型解读——慢、不精确、依赖模型看图能力；
- `eval`：任意 JS，但受 `api_allow_eval` 闸门（默认关）约束，且 MCP Server 完全不暴露。

**缺失一个「只读、结构化、固定行为」的页面读取命令**——这正是 AI / 脚本读网页的主场景。

现有命令集中没有 `get_page_text` / `read_page` 之类的只读文本命令（已在 `api.rs` 核实）。

> **与 `content_snapshot` 的关系**（方案新增说明）：
> 代码库已有 Tauri 命令 `content_snapshot`（`src/content_cmd.rs` + `engine/content.rs` 的 `SNAPSHOT_JS`），
> 从活 DOM 提取 title/text/links/forms/aria，**但它是前端 IPC 专用（`invoke_handler` 注册），本地 socket / MCP 不可达**。
> 本命令不替换 `content_snapshot`，而是：
> 1. 把同类能力开放到本地 API + MCP；
> 2. 提供 8 种模式（`content_snapshot` 只有一种固定快照）；
> 3. 抽取公共 JS 片段（链接/表单遍历）共享，避免两份逻辑漂移。
> 短期：`page_read.js` 独立实现，保证本命令自洽；后续重构再抽公共模块。
> 另注：`content_snapshot` 目前还被 AI agent 的 `snapshot` 动作使用（`agent_cmd.rs`，截 3000 字符喂模型）；
> `read_page` 的 `text` / `elements` 模式语义上就是它的超集，后续可把 agent 侧逐步迁到 `read_page`，届时再落实上述第 3 条的公共 JS 片段抽取。

## 2. 设计原则

| 原则 | 决策 |
|---|---|
| **固定脚本，非任意 JS** | 采集逻辑是编译期嵌入的 `page_read.js`，调用者只能选「模式 + 范围」，不能注入代码 → 风险面 = 读自己已渲染的页面 |
| **风险等级 Read** | 能力上弱于 `screenshot`（文字 < 像素），socket 本就 0600 本地专属 → **不进 eval 闸门、MCP 全量暴露、`api_readonly` 下可用**，与 `screenshot` 同一管理口径（见 §5 安全分析，`html` 模式有额外脱敏） |
| **单一来源** | 只在 `capabilities.rs` 注册一次；MCP bin 零改动（`tools/list` 从浏览器拉 schema、`call_tool` 直通转发——架构红利） |
| **读活 DOM，不重抓 HTTP** | SPA（如闲鱼）重抓拿不到内容，必须读已渲染的 webview DOM |

## 3. 命令定义

```json
{"cmd":"read_page", "mode":"text", "selector":".itemlist", "max_chars":200000}
```

| 参数 | 说明 | 默认 | 硬顶（服务端强制，调用方无法突破） |
|---|---|---|---|
| `mode` | 见下表 8 种 | `text` | — |
| `selector` | CSS 选择器限定范围（只喂给 `querySelector`，不能执行 JS；非法选择器返回错误而非 panic） | 整个 body | 长度 ≤ 1024 字符 |
| `max_chars` | 文本类模式返回上限 | 200,000 | **2,000,000**（2MB） |
| `max_items` | 列表类模式条数上限 | 500 | **5,000** |
| `tab_id` | 一期**只做活动标签**；传入非空值直接报错（不静默忽略） | 活动标签 | — |

> **Rust 侧硬顶**：无论调用方传多大，服务端强制 `min(max_chars, 2_000_000)` / `min(max_items, 5_000)`。
> 若最终响应经数据结构截断后仍超 4MB，**不截断序列化结果**（行式协议中间截断会使客户端 JSON 解析失败，
> 调用方拿到的是解析错误而非"内容过大"），而是放弃响应体，返回 `{"ok":false,"error":"内容过大：请缩小 selector 或调小 max_chars"}`。

### 8 种模式（覆盖「网站上所有能读的」）

| mode | 返回 | 脱敏 / 注意 |
|---|---|---|
| `text` | 可读文本（`innerText`，跳过 `display:none`；压缩空白） | 纯文本，无结构 |
| `elements` | 结构化元素：tag / role / text / href / src / alt / value | 不返回 `type=password` / `type=hidden` 的 value（防密码 / CSRF token 泄露，与 `html` 模式口径一致） |
| `links` | 链接列表（text, href） | href 原样（含 `javascript:`，由调用方判断） |
| `images` | 图片列表（src, alt, w, h） | `data:` / `blob:` 等非 http(s) URL 只返回 `scheme:` 前缀 + 字节长度，不返回 base64 主体 |
| `tables` | 表格 → 二维数组（单元格 `innerText`） | 不包含 `<input>` 的 value |
| `forms` | 表单控件（type, name, id, placeholder, **label**） | **不返回 value**（防密码/CSRF token 泄露）——这是与 `elements` 模式的关键区别 |
| `article` | 正文提取（复用 `readability` 纯解析，作用于当前 DOM 的 `outerHTML`，**不发网络请求**） | **`outerHTML` 中间产物 JS 侧限 ≤4MB**（超限直接返回错误，避免 readability 启动前就出现无界内存/CPU 尖峰）；readability 在 `spawn_blocking` 中执行（CPU 密集） |
| `html` | 原始 HTML（截断） | **脱敏**：移除 `<input type=password/hidden>` 的 `value` 属性、移除 HTML 注释、移除 `<script>`/`<style>` 内容，再截断 |

### 响应格式（统一带元信息）

```json
{"ok":true,"data":{"mode":"tables","url":"https://…","title":"…",
 "truncated":false,"total":42,"returned":42,"tables":[[…]]}}
```

出错时：`{"ok":false,"error":"…"}`（未知 mode / 选择器语法错误 / 超时 / 无活动标签 / tab_id 不支持）。

## 4. 实现（5 个文件）

### `article` 模式实现要点
```
JS: const html = document.documentElement.outerHTML;
    if (html.length > 4_000_000) return JSON.stringify({ error: "页面过大（outerHTML>4MB），请缩小 selector 范围" });
    return JSON.stringify({ html, url: location.href });
Rust: spawn_blocking(move || readability::extractor::extract(&mut html.as_bytes(), &url))
      → tokio::time::timeout(READ_PAGE_SECS, ...)
```
readability 解析是 CPU 密集 blocking，**必须 `spawn_blocking`**（参照 `reader.rs::fetch_and_extract`），不能跑在 async 线程上。

### 引擎层现状（已核实）

- `webkit2gtk = 2.0.2`（features `v2_40`）；
- `engine::webview::eval_js_with(wv, script, cb)` 已提供「执行 JS 并回传字符串」通道（callback 主线程执行，GTK 对象非 Send 问题由现有 `with_webview` 模式解决）；
- crate 未暴露 Atk 可访问性树遍历（代码中零使用），Rust 侧遍历 DOM 无干净 API。

## 5. 安全分析（为什么 Read 等级、不进 eval 闸门是合理的）

1. **无任意代码执行**：调用者唯一自由度是 `mode`（枚举）和 `selector`（字符串，只喂给 `querySelector`，且 `try/catch` 包裹）；采集脚本随二进制编译，外部改不了。
2. **信息面 ≤ screenshot（经脱敏后）**：
   - `text`/`links`/`tables`/`forms`(无 value)/`article`：均为可见文字或结构，信息面 < 像素；
   - `elements`：剥离 password / hidden value 后，剩余字段 ≤ 可见像素；
   - `images`：非 http(s) URL 只留前缀+长度，不泄露 base64 大图；
   - `html`：**额外脱敏**（密码/隐藏 value、注释、script/style 内容），脱敏后信息面 ≈ 可见 DOM 结构，仍 ≤ screenshot。
   - socket 0600 仅本用户可连，用户本人能看见页面。
3. **无网络副作用**：不发请求、不触 SSRF 面（与 `reader.rs` 的重抓路线不同）。
4. **防资源滥用**：JS 侧条数截断（+ `article` 的 `outerHTML` 4MB 前置上限）+ Rust 侧 `max_chars`/`max_items` 硬顶 + 4MB 尺寸检查（超限报错，不截断行式协议）+ `READ_PAGE_SECS` 超时，四层。
5. **日志**：只记 `mode` + 截断标志 + 字符数，不记内容。
6. **不进 eval 闸门**：`eval` 闸门防的是「任意 JS 执行」，本命令脚本固定、不接受代码参数，性质同 `screenshot`（也执行内部 JS 但不进 eval 闸门）。

## 6. 被否决的替代方案

| 方案 | 否决原因 |
|---|---|
| 让用户开 `api_allow_eval` 自己拼 JS | 任意 JS 风险面太大；每次要手动开闸；闲鱼场景已证明摩擦大 |
| webkit2gtk 从 Rust 侧遍历 DOM | 2.0 bindings 无干净的 DOM 遍历 API（JSC 绑定复杂），维护成本高，JS 侧约 200 行就够 |
| Atk 可访问性树 | crate 未暴露 AtkObject 遍历，且表格 / 链接细节丢失 |
| HTTP 重抓 + readability | SPA 读不到（已实测），还有 SSRF 面（`reader.rs` 为此加了整套 SSRF 校验） |
| 直接复用 `content_snapshot` 暴露到 socket | `content_snapshot` 只有一种固定结构、无 mode/selector，无法满足「通读 / 表格 / 正文 / 原始 HTML」多场景；强行扩展会破坏其前端契约 |

## 7. 验证计划

1. `cargo check` + `cargo clippy` + `cargo test`（capabilities 单测：26 工具、写命令基线不变；`page_read.js` 结构断言：含 `JSON.stringify`、含各 mode 分支关键字、含 password value 剥离逻辑）；
2. 真实页面逐模式实测（闲鱼）：`text` / `elements` / `tables` / `images` / `forms` / `article`，对照 `screenshot` 验证内容完整；
3. 安全专项：
   - `forms` 模式在含密码框的登录页，确认返回 JSON 中无密码明文；
   - `elements` 模式在含 hidden input 的页面，确认 hidden 的 value 不返回；
   - `html` 模式确认无 `<!-- -->` 注释、无 `<input type=password value=…>`；
   - `images` 模式对 `data:` 大图，确认只返回前缀+长度；
   - 传 `selector=":not("`（非法），确认返回干净错误而非 panic；
   - 传 `max_chars=100000000`，确认服务端硬顶到 2MB；
4. MCP 握手回归：`shift-browser-mcp` `tools/list` 应为 26 工具、`tools/call read_page` 直通；
5. 前端无改动，不跑前端构建（按项目约定：改 .rs 只跑 cargo 侧）。

## 8. 工作量与风险

- 工作量：1 个 JS 文件（约 250 行，含脱敏逻辑）+ `api.rs` 约 120 行 + `capabilities.rs` 约 30 行 + `contracts.rs` 1 行 + 文档，单会话内可完成并实测。
- 主要风险：
  - 个别站点 DOM 巨大导致 JS 侧遍历耗时 → `READ_PAGE_SECS` 超时兜底 + 截断标志返回，调用者可缩小 `selector` 范围重试；
  - `innerText` 触发 reflow 在超大页偏慢 → 可接受，超时兜底；
  - `html` 脱敏遗漏敏感字段 → 测试专项覆盖（见 §7.3）。
