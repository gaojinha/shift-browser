# B-06 预研：发布物符号剥离 + 独立调试文件（2026-10-15）

> 执行：atomcode · 依据：`docs/Chrome对比-可借鉴工程实践_2026-10-14.md` P0-1 · 纯预研不落代码
> 数据口径：全部为本机 `src-tauri/target/release/` 现产物实测（readelf/stat，2026-10-15 01:30），非估算。

## 一、现状实测（证据）

| 产物 | 体积 | `file` 判定 | `.debug_*` 段 | `.symtab` 段 | 动态符号行 |
|---|---|---|---|---|---|
| shift-browser（主程序） | 35,105 KB | not stripped | 0（已剥） | **1,550 KB** | 871 |
| shift-browser-mcp | 620 KB | not stripped | 0 | 26 KB | 76 |
| libshift_web_extension.so（web 扩展 cdylib） | 480 KB | not stripped | 0 | 27 KB | 78 |
| libshift_browser_lib.so（Tauri lib cdylib） | 2,863 KB | not stripped | 0 | **538 KB** | — |

关键事实：
1. **debuginfo 已经剥了**：`Cargo.toml [profile.release]` 现为 `strip = "debuginfo"`（107-109 行），`.debug_*` 段全为 0。Chrome 对比文档里"8 个 .debug_* 段全带（mcp 组件）"的说法针对的是更早构建，**现状已不成立**（P0-1 的"独立调试文件"目标已半达成——只是没有分离归档，是直接丢弃）。
2. **剩余的是 `.symtab`（完整符号表）**：主程序 67K 条符号在此，占 35MB 里的约 1.5MB（4.4%）。"not stripped" 判定与逆向信息全来自它。
3. **BuildID 已有**（主程序 `6bed28fd…`，GNU build-id 默认生成），debuglink 关联的前置条件已满足。
4. **体积收益上限很小**：全剥主程序只省 ~1.5MB（35MB→33.6MB）。**本项价值主要在"披露面收窄 + 逆向门槛↑"，不在体积**——预研结论需纠正 P0-1 的预期。

## 二、崩溃上报链路影响评估（P0-1 唯一注意点，已细查）

链路现状（`src-tauri/src/app/panic_hook.rs`，P0-4 落地）：
- 全局 panic 钩子 `std::backtrace::Backtrace::force_capture()`，落 stderr / 日志 / 数据目录 `panic.log`——**这是用户侧唯一崩溃证据源，且直接把符号化后的 backtrace 文本写给用户**（无 crashpad 式服务器解析环节）。
- Rust backtrace 的符号化：函数名来自 `.symtab`，文件/行号来自 DWARF（`.debug_*`，已剥 → 现在的 panic.log 本就只有函数名无行号）。
- **推论**：若 `strip = "symbols"`（全剥 symtab），panic.log 的 backtrace 退化为裸地址（`shift-browser+0x1a2b3c`），用户提供的证据无法直接定位函数——**除非**调试文件归档后用 `addr2line`/`llvm-symbolizer` 按 BuildID 离线解析。链路无服务器组件，归档职责完全落在发布流程，**必须先建归档纪律再剥离**（P0-1 第 2 步与本项强绑定，不可只做剥离）。
- 无其他崩溃上报组件（无 crashpad/breakpad，P1-1 已列为独立方向），影响面就这一条链路。

## 三、方案比选

### 方案 A：`strip = "symbols"` + 发布时归档未剥离副本（简单路线）
- 做法：Cargo.toml 改 `strip = "symbols"`；`package-deb.sh` 打包前把 target/release 各产物复制到 `release-artifacts/<version>-<buildid>/` 归档（gitignore，本地或制品库留存）。
- 优点：一行配置 + 一个脚本步骤，`file` 显示 stripped，收益直接。
- 缺点：panic.log 用户证据降级为裸地址（离线可解析但流程变重）；**cdylib 风险见风险清单 R1**。
- 体积收益：主程序 -4.4%，deb 整体约 -2%。

### 方案 B：objcopy 分离 + `.gnu_debuglink`（Chrome 同款路线）——**推荐**
- 做法：打包脚本中 `objcopy --only-keep-debug <bin> <bin>.debug` → `strip <bin>` → `objcopy --add-gnu-debuglink`；`.debug` 文件随 deb 装到 `/usr/lib/debug/…` 或按版本归档。
- 优点：与 Chrome 完全对齐；**开发机装上 debug 文件后 panic backtrace 照常符号化**（Rust backtrace 遵循 debuglink 搜索路径——需按 R2 实测确认）；用户端同样 stripped。
- 缺点：脚本最复杂；`strip="debuginfo"` 已把 DWARF 剥掉，**改走 B 线需同时把 Cargo.toml 改回 `strip = "none"`（或 debug=1）才能分离出有用调试文件**——否则分离出的 .debug 里没有 DWARF，只剩 symtab，行号还原不了。这是方案 B 的隐藏成本：要么接受"调试文件只含符号名"，要么把 release 的 DWARF 重新带上（debuginfo 重新打包进产物，构建时间/归档体积↑，但用户端 deb 不受影响）。
- 体积收益：同 A。

### 方案 C：现状不动，仅说明（保守路线）
- `strip="debuginfo"` 已满足"调试信息不发布"；symtab 残留的披露面有限（函数名列表，无源码路径——Rust symtab 符号含 crate 路径但不含行号）。Chrome 的"1473 行动态符号"是浏览器内核多组件拆分的结果，我们 871 行动态符号**已达标**，差的只是 symtab。
- 何时选它：若高哥认为 panic.log 用户证据的实时符号化价值 > 符号披露收窄，则 C 是理性选择——**这是本预研建议的拍板点**。

### 推荐
**C 起步、A 为第一阶段落地项、B 作为发布工程成熟后的对齐项**：A 的归档纪律（R4）无论如何都该先建（它不依赖剥离决策）；拍板 A 后先在 bench profile 验证 R1，再切 release。

## 四、风险清单（分级）

| # | 级别 | 风险 | 缓解 |
|---|---|---|---|
| R1 | 🟡 高关注 | **cdylib 全剥离兼容性**：Cargo.toml 107 行注释明确记录"不能 strip=true，Web 扩展入口函数找不到、tauri:// 协议失效"（历史实测教训）。理论上 cdylib 导出在 `.dynsym`（全 strip 保留），与该注释矛盾——但当时踩过坑就是踩过坑，**切换前必须在 bench profile 实测扩展加载** | bench_3_thin 实测 → 通过才动 release；deb 装机后验 newtab/翻译可用 |
| R2 | 🟡 中 | 方案 B 的 backtrace 符号化依赖 debuglink 搜索路径，Rust backtrace crate 行为需实测（本机装 debug 文件后抓 panic 样例） | 预研阶段不承诺；实测通过才视为 B 线可行 |
| R3 | 🟢 低 | panic.log 用户证据降级（A 线） | 归档 + addr2line 流程文档化；或保留主程序不剥、只剥 mcp/extension |
| R4 | 🟢 低 | 归档纪律缺失导致崩溃无法回溯 | `package-deb.sh` 加归档步骤（版本+BuildID 目录），先于任何剥离落地 |
| R5 | 🟢 低 | 增量构建误用旧产物 | 剥离/归档脚本内置于打包流程，不手工操作 |

## 五、验收口径（拍板后执行时用）
1. `file` 各产物显示 stripped（无 "not stripped"）；
2. deb 装机：newtab / 翻译 / 扩展加载正常（R1 复验）；
3. 抓一个 panic 样例（或人为触发），按归档副本 + BuildID 可解析出函数名（A 线为离线解析，B 线为装机即解析——按拍板方案定）；
4. 归档目录含 版本+BuildID 命名的四个未剥离副本。

## 六、结论（给拍板人的三句话）
1. "发布调试信息"已在现状解决（strip="debuginfo"），剩余争议只有 symtab：**收益约 -2% 体积 + 披露面收窄，代价是 panic.log 用户证据符号化降级 + cdylib 兼容性需实测**；
2. 无论拍哪条，**归档纪律（R4）建议先行**，它独立成立且零风险；
3. cdylib 剥离有过一次翻车记录（Cargo.toml 注释），任何切 symbols 的动作必须过 bench 实测关。
