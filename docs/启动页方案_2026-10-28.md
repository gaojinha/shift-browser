# 启动页（新标签页）完善方案

> 2026-10-28。当前实现：`src-tauri/src/engine/cef/newtab.rs`（336 行，自包含 HTML，不依赖 Tauri IPC）。

## 一、现状盘点

**已有**：
- 品牌名 + 搜索框（搜索引擎跟设置联动，`settings.search_engine`）
- 快捷站点（`settings.quick_sites` 配置，默认 5 个）
- 最近访问 6 条（`history` 按 `last_visit_at`）
- 快捷键提示
- 深色主题、径向渐变背景

**缺的**（按用户打开新标签页的真实需求排序）：

| 缺口 | 影响 |
|---|---|
| 没有时间/日期 | 每次开新标签想看的第一眼信息 |
| 快捷站点是**静态配置**，不按实际使用频率 | 常用的不在前面，鸡肋 |
| 没有书签入口 | 64 条书签 / 13 个文件夹完全不体现 |
| 没有资讯 | `feed_items` 表 978 条白抓了 |
| 没有「继续上次」 | 50 条会话快照，恢复功能刚做完却没入口 |
| 快捷站点用 emoji | 不如 favicon 直观（但要处理离线） |
| 固定深色 | 不跟系统主题 |
| 搜索框无联想 | 输入时没有历史/书签建议 |

## 二、定位

**一屏解决三件事**：搜（80%）、去常用站（15%）、接着上次干（5%）。
不做门户、不做资讯流瀑布（那是 Edge 的路子，容易变重）。

## 三、方案分档

### P0 · 今天下午做（2–3 小时）

| # | 功能 | 数据来源 | 改动 |
|---|---|---|---|
| 1 | **时间/日期**（大字 + 星期，每分钟刷新） | 页面本地 `Date` | HTML/JS |
| 2 | **常用站点自动排序**：按 `visit_count` 取 top 8，用户固定项置顶 | `history` 聚合 | `load_newtab_settings` 加一条 SQL |

| 5 | **主题跟随系统**（`prefers-color-scheme`，深/浅两套变量） | 页面 `matchMedia` | CSS 变量 |

## 四、技术要点

1. **数据注入沿用现有模式**：`ensure_newtab_html` 生成时查库、注入 JSON。不引 IPC，启动页永远不依赖宿主在线。
2. **性能**：生成 HTML < 50ms（现有 3 条 SQL，加 2 条仍 < 100ms）。
3. **无网络也能用**：favicon 是唯一外链，`onerror` 降级 emoji；资讯/书签/会话全本地。
4. **安全**：URL 一律过 `newtab::quick_sites::is_safe_web_url`（只放行 http/https），注入 JSON 做 `</` 转义（现有做法）。
5. **主题**：CSS 变量 + `prefers-color-scheme`，不引外部主题文件。
6. **刷新时机**：每次开新标签重新生成 HTML（现有行为），保证数据新鲜。

## 五、验收标准

| 项 | 标准 |
|---|---|
| 冷启动渲染 | 打开新标签到可交互 < 100ms |
| 常用站点 | top 8 与实际访问频次一致；固定项在最前 |
| favicon | 有网显示图标；断网 3 秒内降级 emoji，不出现破图 |
| 继续上次 | 点击后标签数与快照一致（复用 `sessrestore`，已测 1/1 → 2 标签） |
| 主题 | 系统切浅色，页面同步变浅，文字对比度 ≥ 4.5:1 |
| 断网 | 除 favicon 与资讯外全部正常 |
| 单测 | `render_newtab_html` 纯函数：空数据 / 有数据 / 转义 三类用例 |

## 七、风险

1. **favicon 外链**：`favicon.im` 是第三方，若不可用需换 `google.com/s2/favicons` 或本地缓存；已设计降级，不影响可用性。
2. **会话恢复的 idx 语义**：`sessrestore` 逐个 `new_tab`，恢复顺序即快照顺序，但活动标签会停在最后一个（现有行为），P0 不改。
3. **常用站点与 `quick_sites` 冲突**：方案是「用户固定项在前 + 自动补足到 8」，固定项为空时全自动——需要在设置页说明这一点。
