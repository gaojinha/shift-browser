## 〇、总纲

### 借鉴三档原则
- **A 直接借鉴**：模式成熟、我们缺失、成本可控 —— 直接排期
- **B 改造借鉴**：方向对，但需适配我们的架构/战略 —— 做改造设计
- **C 不借鉴**：战略不匹配 —— 进"不借鉴清单"并说明理由

### 两条硬约束（先认清）
1. **UI 承载约束**：主界面 Vue 渲染 + webview GTK 叠层（Q-5 在治理中、W2 spike 待决策）。本方案所有"面板/侧边栏/浮层"设计**限定在 Vue 层可实现范围**，不新增 GTK 叠层依赖；涉及 webview 几何的新交互（如标签悬浮预览卡片）标注"依赖 W2 结论"。
2. **在飞工程不打断**：a11y 补验、i18n 拆包（R4-5）、鉴权矩阵（R4-3）进行中。本方案新 UI 文案一律走 i18n 流程；新设置键一律走 `contracts.rs` 契约流程（含 `ts_export` 重生成）。

### 现状先行纠正（写方案前已查明）
当前 shift 并非"没有隐私能力"——已有基础比预期好：
- **StatusBar 已有"🛡 已拦 N · 清参 N"战绩条**（adblock_injections / cleaned_params / privacy_injections 三项计数已在）
- **PrivacySection 已有**浏览防护档位、反指纹、白名单、统计、自测、GPC、拦截规则、外联审计
- **SpaceSwitcher 注释已定位为"上下文隔离容器"**（对标 Brave Containers 的语义已在）
- 缺的是：**站点级盾交互（地址栏盾按钮+面板）**、追随 Brave 新设计的"站点信息一体化"

## 一、功能层借鉴（10 项）

### F1. 隐私盾面板（★ P0，最高优先）【A 档·核心】
**Brave 参考**（文案实证）：
- 盾状态：`Shields UP / DOWN`；计数展示 `$1 trackers, ads, and more blocked`；徽标可选显示拦截数
- **新设计**："Shields 集成到地址栏站点信息（site information），一站式体验"——点击地址栏站点图标打开
- 分项开关：Trackers & ads（Standard/Aggressive/Allow）、Scripts（Blocked/Allowed）、Fingerprinting（Strict）、HTTPS 升级
- 救援引导：`If this site seems broken, try Shields down` + `Report site` 报修
- 模式：Adblock-Only（实验降级模式）、`Forget me when I close this site`
- 面板导航：`Advanced controls` / `Global Shield settings`

**我们现状**：能力全在（见〇节），但没有**站点级、单按钮、即时反馈**的交互层。

**设计方案**：
1. **盾按钮**：地址栏左侧站点图标区增加盾状态点（站点级三态：开/关/豁免），点击展开盾面板（Vue 浮层，`--shadow-pop` + `--z-dropdown` + `--radius-lg` + `--dur` 动效）
2. **面板 MVP（v1，本批可做）**：
   - 顶部战绩行：本页拦截数（新增前端统计 bus，数据源=已有三项计数按页面归集）
   - 站点开关：本页盾开/关（持久化到站点级设置）
   - 分项快速开关：广告拦截（已有 `adblock_enabled`）、追踪参数清洗（已有）、反指纹档位（已有 `隐私防护等级`）
   - 救援引导行："站点显示异常？→ 本页降盾"，一键降盾并 Toast 反馈
3. **面板 v2（后批）**：分类明细（广告/追踪/指纹三类）、报修入口（收集域名+开关状态，生成可复制报告）、`Forget me` 站点级清除
4. **明确不做**（本轮）：Adblock-Only 实验模式——我们拦截引擎本身在升级评估中，暂无此必要

**技术要点**：
- 新组件 `ShieldPanel.vue`；状态入新 store（`stores/shield.ts`）
- 站点级设置：`shields_site_overrides`（JSON，仿 `ua_site_overrides` 模式已存在）；契约铁律流程
- 计数归集：现有三项计数为"本次运行"口径，需新增"本页"口径（前端在导航事件上打点归集；**不依赖 WebKit 侧计数事件**——content_filter 不提供拦截回调，方案不承诺补此项）

**验收**：地址栏盾三态可视；面板开关生效并持久；降盾后本页可恢复；a11y（焦点/读屏标签）+ i18n 全过。

### F2. 新标签页增强（P1）【B 档】
**Brave 参考**：时钟/搜索框/热门站点/Leo 小组件/自定义背景；"Dashboard vs Blank"双模式；NTP 广告（不抄）。
**我们现状**：`shift://newtab` 已存在且设置项丰富（壁纸/动态背景/农历/天气/每日一句/字体/主题色）——**不少维度已超 Brave**。
**设计**：仅补两项——① "热门站点"区（设置已有 `newtab` 相关口径，评估数据源=历史统计）；② **AI 入口小组件**（对标 Leo widget：新标签页直达 AI 侧边栏/"随手问"，联动 F6）。修改点集中在现有 newtab 实现，不重构。

### F3. 侧边栏面板体系（P1）【B 档】
**Brave 参考**：侧边栏四面板（Bookmarks / Reading List / Playlist / News）+ 位置可换 + "自动展开"。
**我们现状**：`AISidebar.vue` 单侧边栏。
**设计**：把侧边栏升级为**面板容器**（`PanelHost`）：
- 一期并入：AI（现有）、书签、历史（`BookmarksDialog/HistoryDialog` 内容组件复用）
- 二期：阅读列表（后端 reader 已具备提取能力，链接收藏+阅读模式打通）
- **不并入**：Playlist（音乐整合战略不匹配）、News（内容服务不做）
- 位置切换（左/右）复用现有布局变量，评估与垂直标签位置的关系

### F4. 垂直标签补强 + 树状标签评估（P1/P2）【B 档】
**Brave 参考**：垂直标签（自动展开、最小宽度档、**卡片预览**、右侧可换）；**树状标签**（标签亲子层级——Brave 独有特色）。
**我们现状**：`VerticalTabBar.vue` 已有。
**设计**：① 补"最小宽度/展开模式"档位（低成本）；② 悬浮卡片预览——**依赖 W2 架构结论**（涉及 webview 几何），先挂起；③ 树状标签：**评估项**（工程中，不与一期冲突），先列入 backlog。

### F5. 容器/空间（P1）【A 档·对齐已有】
**Brave 参考**：Containers（色标、命名、cookie/存储隔离、"Work/Personal"模板）。
**我们现状**：`SpaceSwitcher` 已注释为"上下文隔离容器"。
**设计**：盘点 Space 现有隔离实现（数据层是否真实隔离），对表补：容器色标/图标体系、命名模板、切换时的视觉提示（联动 V2 视觉编码）。**这是"补齐"而非"新建"**。

### F6. AI 集成补强 —— 技能化与站点入口（P1）【B 档】
**Brave 参考**：Leo **Skills**（快捷技能：预设提示词+任务，键盘直达）；**站点可请求打开 AI**（`Sites can ask to open Leo AI chat`）；On-Device AI 选项。
**我们现状**：`AISidebar` + `CommandPalette` + `frontend-prompts.ts`（已有预设话术） + WebMCP 布局（ADR 已有）。
**设计**：
- 把 `frontend-prompts` 升级为**"技能中心"**：卡片列表（名称/图标/快捷键/可自定义），入口=命令面板 + 侧边栏 +（新）NTP 小组件；对标 Leo Skills
- "站点请求打开 AI"：与 **WebMCP ADR** 合流排序（已有文档，按既定节奏）
- On-Device：评估项（记录 backlog，暂无排期）

### F7. 隐私模式视觉 + 应用门禁（P2）【B 档】
**Brave 参考**：隐私窗口/Tor 窗口/AI profile 各有**专属视觉**（"模式要有皮肤"）；**brave.sh 类型的门外思路**（用户自建组件）。
**设计**：① 为 Space/隐私场景设计**视觉编码体系**（色带/图标/边框，见 V2）；② "应用锁/隐私空间"特性评估（brave.sh 思路产品化；可复用 R4-3 KDF 成果）——**待高哥拍板是否立项**。

### F8. 首次启动引导（P2）【A 档·轻量】
**Brave 参考**：`Privacy. By Default.` 标语 → 主题选择 → 导入 → 诊断上报选择 → 完成。
**我们现状**：无引导（grep 无果）。
**设计**：轻量 3 步（欢迎+隐私默认项确认 / 导入书签（已有导入能力？评估）/ 完成提示），Vue 层实现；重点：**a11y 从第一天做**（读屏、键盘全流程）。文案对标 Brave 的引导感（见 V3）。

### F9. 阅读模式体验（P2）【A 档】
**Brave 参考**：Speedreader（自动/手动）、阅读列表。
**我们现状**：后端 `reader/`（fetch+render）已具备；UI 入口与面板缺。
**设计**：地址栏加"阅读模式"按钮（有正文可读时点亮）+ 阅读列表并入 F3 面板（二期内）。

### F10. 设置页"关键控制复查"（P2）【A 档】
**Brave 参考**：`Review key privacy and security controls`——定期主动提示用户复查关键隐私设置（"安全体检"）。
**我们现状**：已有 `SelfCheckSection`（自检分区）！——定位相近。
**设计**：把自检入口的价值显性化（首次运行后 N 天提示一次"复查隐私设置"，文案见 V3）；**不新增分区**，增强 SelfCheck 的触发时机与呈现。

## 二、界面信息架构借鉴

### I1. 盾的位置：进地址栏站点图标（【A 档·架构级小改】）
Brave 已把 Shields 从"工具栏独立按钮"迁入"地址栏站点信息"（"one-stop experience"）。建议我们**直接按新形态设计**（F1 已按此设计），不学旧版独立按钮——省一次迁移。

### I2. 站点信息一体化（P1）【B 档】
现状散件：`PermissionPrompt` / `CertWarning` / 地址栏站点图标。建议**归并为"站点信息中心"**（点击站点图标：连接安全性（证书）/ 权限状态 / 盾状态 / 站点级设置），对标 Brave 一站式。这是信息架构收敛，不做新功能。

### I3. 主菜单结构对照（P2）【B 档】
Brave app menu 分组参考：新建/标签区 → 隐私（盾/隐私窗口/Tor）→ 书签历史 → 缩放打印 → 工具（DevTools/任务管理器）→ 帮助/退出。建议对照我们现有菜单做一次**分组复查**（结合 a11y 键盘走查一起做，不单独立项）。

## 三、UI / 视觉 / 交互细节

### V1. 隐私可视化语言（P1）
- Brave：计数（`$1 blocked`）、状态色（UP 用品牌色/DOWN 灰）、徽标数字可选
- 我们：复用 `tokens.css` 语义色；**克制原则**：计数仅出现在 ①地址栏盾徽标（可关，默认开）、②盾面板、③状态栏（已有）；不做全屏动画庆祝类设计
- 口径统一：所有计数文案统一"已拦 N · 清参 N"格式（对齐 StatusBar 现有格式）

### V2. 模式视觉编码体系（P2）
- Brave：隐私窗口（深色徽标）/ Tor（紫）/ AI 模式（独立样式）——**用户任何时候都知道自己"在哪"**
- 我们：为 Space 定义**色标+图标**（容器化已规划）；为"AI 操作中 / 隐私场景"设计轻量提示（顶栏色带或图标角标）；**原则：不打扰主流程**

### V3. 文案体系（P1·低成本高收益）
Brave 文案特点（从 105KB 提取中归纳）：**引导式**（"If this site seems broken, try Shields down"——给出路不止报错）、**人话**（"Get ready for the best browsing experience"）、**承诺清晰**（"Privacy. By Default."）。
落地：新增 UI 文案遵循此风格；盾相关文案出**对照表**（我们现有文案 vs 建议文案），在 F1 实施时一并处理；全部过 i18n 流程。

### V4. 动效（P2）
对照我们 `--dur/--ease` 现有令牌与 Brave 手感（面板展开、开关切换、卡片浮现），补 2-3 处关键动效规范（写进 tokens 注释级文档，不散落硬编码）。

## 五、不借鉴清单（明确取舍）

| 不抄 | 理由 |
|---|---|
| Rewards / BAT | 加密激励体系，战略与合规不匹配 |
| Wallet / Web3 | 同上 |
| VPN / Talk / News | 服务型产品线，非浏览器本体能力 |
| Email Aliases | Brave 账号生态捆绑 |
| NTP 广告 | 我们不引入广告位 |
| Adblock-Only 实验模式 | 拦截引擎仍在选型，暂不引入降级模式 |
