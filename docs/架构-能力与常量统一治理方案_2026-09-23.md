# 能力与常量统一治理方案

> 规划日期：2026-09-23
> 目标：把散落的**常量 / 技能 / 工具 / 插件**提取为**单一事实来源（SSOT）**，消除重复与漂移，让能力可声明、可发现、可扩展。

---

## 一、为什么要做（现状盘点）

### 1.1 常量：74 个 Rust + 22 个前端，跨端靠"注释约定"同步

**已发现的真实重复（会漂移）**：

| 常量 | 重复位置 | 风险 |
|---|---|---|
| 布局高度 `38/36/26/22` | `engine/layout.rs`（TAB_BAR_HEIGHT 等） ↔ `AISidebar.vue` 硬编码 `38 + 36 + bookmarkH` | 改一侧忘另一侧 → 面板错位（本轮 AI 面板 topOffset 就踩过：116→100） |
| 搜索引擎 URL | 4 处：`AddressBar.vue` SEARCH_URLS、`SettingsDialog.vue` SEARCH_ENGINES、`api.rs:570`、`newtab.rs:194` | 加引擎要改 4 个文件 |
| `DEFAULT_FAVICON` | `TabBar.vue` ↔ `VerticalTabBar.vue`（内容完全一样） | 改一处漏一处 |
| 颜色数组 | `tabs.ts` GROUP_COLORS、`workspaces.ts` SPACE_COLORS、`GroupsDialog.vue` COLORS | 三套各写各的 |
| 翻译引擎/目标语言 | `SettingsDialog.vue` TRANSLATE_ENGINES/TARGETS ↔ `translate.rs` | 前后端对不上会静默失败 |

**根因**：没有"常量中心"，各模块就地定义；跨端（Rust ↔ TS）只能靠注释写"与后端一致"。

### 1.2 工具：同一能力在 3 处各写一遍

| 声明处 | 形式 | 数量 |
|---|---|---|
| `bin/mcp_server.rs::tool_defs()` | JSON Schema 数组 | **25 个** |
| `api.rs` 的 `match cmd { "status" => ... }` | 手写 match 分支 | **30 个** |
| `engine/agent.rs::AGENT_ACTIONS` + `browser_action_tool()` | 常量数组 + JSON Schema | **9 个动作** |

三者号称"同名同参"（README 也这么写），但**没有任何机制保证**——全靠开发者手工对齐。新增一个能力要改 3 处，漏一处就是"定义了工具但调不通"（agent.rs 注释里已记录过这类历史 bug）。

### 1.3 技能：概念缺失，能力散落

项目里没有 `skill` 字样。AI 的"能做什么"实际散在：
- `ai.rs`：对话 / function calling 工具循环
- `agent.rs`：9 个浏览器动作
- `ai.ts` 前端快捷操作：总结页面 / 翻译 / 解释页面
- `reader.rs` / `translate.rs` / `content.rs`：单项能力

**没有统一的能力清单**——AI 自己（和用户）都不知道"这个浏览器一共能做哪些事"。

### 1.4 插件：三种扩展形态，无统一注册

| 形态 | 实现位置 | 注册方式 |
|---|---|---|
| 用户脚本 / 样式注入 | `extensions.rs`（UserContentManager） | 数据库 + 启动注入 |
| 内容过滤（广告拦截） | `extensions/adblock.rs` + `content_filter.rs` | 规则字符串 |
| Web 扩展（网络层拦截） | `resources/libshift_web_extension.so` | 编译期 .so |
| MCP 外部工具 | `engine/mcp.rs`（接入外部 server） | 数据库 mcp_servers 表 |

四者生命周期、启停、审计各管各的。

### 1.5 同类问题全景（本轮系统排查，附证据）

> 除常量外，项目里还有 8 类"**同一事实写多份 / 靠注释约定 / 拼错不报错**"的情况，本质与常量同源，应纳入同一治理管线。

| # | 类别 | 证据（实测） | 后果 |
|---|---|---|---|
| 1 | **设置键名 + 默认值** | 后端 `db/settings.rs::ALLOWED_KEYS` **41 个键** ↔ 前端 `stores/settings.ts::DEFAULT_SETTINGS` **24 个键**；前端注释写着"以下默认值与后端一致（2026-09-19 补齐）" | **19 个键前端无默认值**（`api_readonly`/`api_http_port`/`theme_color`/`wallpaper`/`weather_city`/`net_headers`…）→ `get()` 回退空串 → 设置页/状态栏显示失真（注释提到的老问题只补了一半）；前端若写后端白名单外的键 → 保存被静默拒绝 |
| 2 | **类型契约** | 前端 `src/types/` 8 个文件（tab/bookmark/history/content/download/extension/password/session） ↔ Rust `tabs.rs::Tab`、`db/bookmarks.rs::Bookmark`、`db/history.rs::HistoryEntry`… 手工对齐 + 靠 `#[serde(rename_all)]` 猜 | 后端加字段前端不知道 → 运行时 undefined；改名漏改前端 → 静默失效 |
| 3 | **IPC 事件名** | 后端 `emit("...")` 11 处 ↔ 前端 `listen('...')` 18 处，全是裸字符串 | 拼错不报错，功能静默失灵（排查靠日志考古） |
| 4 | **Tauri 命令名** | 前端 `invoke('...')` 132 处 ↔ 后端 `generate_handler!` 注册 175 项，裸字符串 | 同上；改名漏改一侧 → 运行时才炸 |
| 5 | **超时 / 间隔魔法数字** | Rust `from_secs(6)`×5、`from_secs(120)`×5、`from_secs(60)`×3…；前端 `2000`×3、`150`×3… | 6 秒是什么超时？120 秒管哪条链路？无人知晓，调参靠猜 |
| 6 | **URL scheme / 内部路径** | `"shift://newtab"`×3、`"shift://worldnav"`×2、`"/newtab/"`×4、`"/reader/"`、`"world-nav.html"` 散落 Rust+前端 | 内部页面路由改动要满仓库找字符串 |
| 7 | **快捷键定义** | 前端 `App.vue` keydown 表（Ctrl+K/L/T/W/R/H/Tab…） ↔ Rust `tabs.rs` GTK 层兜底（F12 / Ctrl+Shift+I，含裸 keycode `0xFFC9`/`0x69`） | **同一条快捷键两处各写一遍**；新增快捷键要同时改两处，漏改就是"网页持焦时失效" |
| 8 | **URL 判断正则** | 前端 `AddressBar.vue::looksLikeUrl`/`isHttps` ↔ Rust `starts_with("http://") \|\| starts_with("https://")` **6+ 处**（lib.rs×2、tabs/util.rs、llmstxt.rs、sync.rs…） | 判断规则不一致 → 前后端对同一 URL 结论不同 |
| 9 | **颜色数组** | `tabs.ts::GROUP_COLORS`、`workspaces.ts::SPACE_COLORS`、`GroupsDialog.vue::COLORS` | 三套各写各的，主题调整要改三处 |

**统一手段**：以上 1/2/3/4/5/6 类全部走**同一条生成管线**——「**Rust 侧单一来源 → `build.rs` 生成前端 TS 契约层**」（详见 3.5）。

## 二、目标架构

```
                    ┌──────────────────────────────┐
                    │   capabilities/registry.rs   │  ← 单一事实来源
                    │  （能力声明：id/参数/风险/实现） │
                    └───────────┬──────────────────┘
                                │ 代码生成 / 运行时读取
        ┌───────────────┬───────┴───────┬────────────────┐
        ▼               ▼               ▼                ▼
   MCP tool_defs   开放 API 分发    Agent 动作表    前端命令面板
   (25 工具)       (30 命令)       (9 动作)        (Ctrl+K)

   constants.rs  ──(build.rs 生成)──▶  src/constants.ts
   （Rust 常量中心）                    （前端常量镜像）
```

**四条主线**：
1. **常量中心**：Rust `constants.rs` 为源，`build.rs` 生成前端 `src/constants.ts`
2. **工具注册表**：`capabilities/registry.rs` 单一声明，运行时派生 MCP / API / Agent 三视图
3. **技能清单**：`capabilities/skills.rs` 声明 AI 技能（动作 + 内置能力），供 AI 自省与前端展示
4. **插件体系**：`capabilities/plugins.rs` 统一注册扩展形态（脚本/样式/过滤/WebExt/MCP）

**跨端生成**：`src-tauri/build.rs` 把上述常量序列化写入 `../src/constants.ts`：

### 3.2 工具注册表（Phase 2，核心）

**单一声明**：`src-tauri/src/capabilities/registry.rs`

```rust
/// 一个可被外部调用的能力（= MCP 工具 = 开放 API 命令 = 可选 Agent 动作）
pub struct Capability {
    /// 唯一 id（同时作为 MCP 工具名 / API cmd）
    pub id: &'static str,
    /// 人类可读描述（MCP description / API 文档 / 前端命令面板）
    pub desc: &'static str,
    /// 参数 schema（JSON Schema，MCP 直接用；API 用于校验；前端用于表单）
    pub params: fn() -> serde_json::Value,
    /// 风险等级：Read / Write / Dangerous（决定 MCP 是否暴露、API 只读闸门、是否需要确认）
    pub risk: Risk,
    /// 是否暴露给 MCP（eval / tool_call 为 false）
    pub mcp_exposed: bool,
    /// 实现（在浏览器进程内执行）
    pub handler: fn(&CapabilityCtx, &serde_json::Value) -> Result<serde_json::Value, String>,
}

pub fn all() -> &'static [Capability] { /* inventory/宏收集 */ }
```

**三视图派生**（零重复）：

```rust
// bin/mcp_server.rs —— 不再手写 tool_defs()
fn tool_defs() -> Vec<Value> {
    registry::all().iter()
        .filter(|c| c.mcp_exposed)
        .map(|c| json!({
            "name": c.id,
            "description": c.desc,
            "inputSchema": (c.params)(),
        }))
        .collect()
}

// api.rs —— 不再手写 match cmd
match registry::find(cmd) {
    Some(cap) if !readonly_violation(cap, readonly) => (cap.handler)(&ctx, &params),
    Some(_) => err("只读模式：该命令需要写权限"),
    None => err(format!("未知命令: {}", cmd)),
}

// agent.rs —— 动作表从 registry 过滤 risk==Agent 生成
pub fn browser_action_tool() -> Value {
    let actions: Vec<&str> = registry::all().iter()
        .filter(|c| c.risk == Risk::Agent)
        .map(|c| c.id).collect();
    json!({ "enum": actions, /* ... */ })
}
```

**收益**：新增能力 = 在 registry 加一条 → MCP / API / Agent / 前端命令面板**同时可用**，不可能漂移。

**注意**：MCP Server 是**独立二进制**（`bin/mcp_server.rs`），它连浏览器 socket 转发，**不含 registry**。两种方案：
- **A（推荐）**：MCP Server 启动时向浏览器请求 `capabilities/list`，用返回的 schema 动态构建 `tools/list` → 零编译期耦合
- **B**：把 registry 抽成独立 crate，两个 bin 共用（改动大）

选 A：浏览器 API 新增 `capabilities/list` 命令（本身也在 registry 里，自举）。

### 3.3 技能清单（Phase 3）

**定位**：技能 = **面向 AI 与用户的能力叙事**（比"工具"更高一层，可组合）。

```rust
// capabilities/skills.rs
pub struct Skill {
    pub id: &'static str,           // "summarize_page"
    pub name: &'static str,         // "总结当前页"
    pub desc: &'static str,
    /// 该技能用到哪些能力（Capability.id）
    pub uses: &'static [&'static str],
    /// 前端快捷入口（可选）
    pub ui_entry: Option<UiEntry>,

pub const SKILLS: &[Skill] = &[
    Skill { id: "summarize_page", name: "总结当前页", uses: &["read_page", "ai_chat"], ui_entry: ... },
    Skill { id: "translate_page",  name: "翻译当前页", uses: &["read_page", "translate"], ... },
    Skill { id: "explain_page",    name: "解释当前页", uses: &["read_page", "ai_chat"], ... },
    Skill { id: "reader_mode",     name: "阅读模式",   uses: &["extract_article"], ... },
    // ...

```

**用途**：
1. 新增 API `skills/list` → 前端快捷操作按钮**由数据驱动**（不再硬编码在 `ai.ts`）
2. 注入 AI system prompt 的"能力自述"（AI 知道自己能做什么）
3. 设置页/AI 面板展示"技能清单"

### 3.4 插件体系（Phase 4）

**统一注册**：`capabilities/plugins.rs`

```rust
pub enum PluginKind { UserScript, UserStyle, ContentFilter, WebExtension, McpServer }

pub struct Plugin {
    pub id: String,
    pub kind: PluginKind,
    pub name: String,
    pub enabled: bool,
    /// 生命周期钩子
    pub hooks: PluginHooks,
}

pub struct PluginHooks {
    pub on_startup: Option<fn(&AppHandle, &Db)>,       // 启动注入
    pub on_page_load: Option<fn(&AppHandle, &str)>,    // 页面加载（按 URL 匹配）
    pub on_rule_change: Option<fn(&AppHandle)>,        // 规则热更新
}
```

**统一能力**：
- 统一启停：`plugins::set_enabled(id, bool)` → 各形态走各自实现
- 统一审计：注入/拦截事件写入现有 `tool_audit_log`（复用审计表）
- 统一发现：`plugins/list` 返回全部（前端设置页一个列表看全）

**迁移**：现有四套各自为政的注册逻辑（extensions.rs 的 inject_on_startup、adblock 规则加载、WebExt .so 加载、mcp_servers 表）分别包一层 `Plugin` 适配器，不改底层实现。

### 3.5 契约与键名统一（同一条生成管线）

**核心机制**：Rust 为单一来源，`build.rs` 生成 `src/contracts.ts`——与常量**同一条管线**（1.5 节 8 类问题一次解决）。

```rust
// src-tauri/src/contracts.rs —— 全部"跨端契约"集中于此
/// 设置键 + 默认值 + 类型（唯一来源：后端白名单与前端默认值都从这生成）
pub const SETTINGS: &[SettingDef] = &[

/// IPC 事件名（后端 emit / 前端 listen 共用，拼错编译期就报）
pub mod events {

/// 内部 URL scheme / 路由（shift:// 唯一来源）
pub mod urls {

    pub const NEWTAB_MARKER: &str = "/newtab/";
    pub fn is_internal(u: &str) -> bool { /* … */ }

/// 超时 / 间隔（带语义命名，杜绝裸数字）
pub mod timeout {
    pub const MCP_REQUEST_SECS: u64 = 30;      // MCP JSON-RPC 单次超时

    // …（Rust 21 处 + 前端 10 处裸数字逐步替换）

/// 快捷键表（单一来源：前端 keydown 与 Rust GTK 兜底都从这里取）
pub const SHORTCUTS: &[Shortcut] = &[
    Shortcut { id: "devtools",        keys: "F12,Ctrl+Shift+I", gtk_fallback: true  },
    Shortcut { id: "command_palette", keys: "Ctrl+K",           gtk_fallback: false },
```

**生成的 `src/contracts.ts`**（与 `constants.ts` 合并为一份生成物）：

```ts
// 自动生成，请勿手改（源：src-tauri/src/constants.rs + contracts.rs）
export const SETTINGS_SCHEMA = { homepage: { default: 'newtab', kind: 'str' }, … } as const
export const DEFAULT_SETTINGS: Record<string, string> =
  Object.fromEntries(Object.entries(SETTINGS_SCHEMA).map(([k, v]) => [k, v.default]))
export const EVENTS    = { TABS_UPDATED: 'tabs-updated', … } as const
export const URLS      = { NEWTAB: 'shift://newtab', … } as const
export const TIMEOUT   = { MCP_REQUEST_SECS: 30, … } as const
export const SHORTCUTS = [ … ] as const
```

**迁移动作**：
1. `db/settings.rs::ALLOWED_KEYS` 改为从 `contracts::SETTINGS` 派生（`is_allowed(key)` 查表）→ 白名单与默认值**天然一致**
2. 前端 `DEFAULT_SETTINGS` 删除手写 → import 生成物 → **1.5 节第 1 项的 19 个缺失键自动补齐**
3. 前端 `listen('xxx')` 改用 `EVENTS.XXX`；`emit` 侧同样改用常量
4. 快捷键：前端 keydown 表遍历 `SHORTCUTS`；Rust GTK 兜底表同源生成 → 消除"两处各写一遍"
5. 超时裸数字替换为 `timeout::XXX` / `TIMEOUT.XXX`
6. URL scheme / 内部路径改用 `urls::XXX` / `URLS.XXX`

**类型契约（进阶）**：引入 `ts-rs` 或 `typeshare`，Rust struct 加 `#[derive(TS)]`，`build.rs` 生成 `src/types/generated/*.ts`；手工 `types/*.ts` 逐步替换（可保留手写 interface 做过渡期兼容）。

## 四、分阶段实施

| 批次 | 内容 | 风险 | 预估 | 验收 |

## 五、风险与取舍

| 风险 | 缓解 |
|---|---|
| registry 里 `fn` 指针 + 闭包捕获复杂 ctx，可能绕不过借用检查 | 用 `CapabilityCtx`（含 `&AppHandle`、`&TabManager`）传参，handler 签名统一为 `fn(&Ctx, &Value) -> Result<Value, String>`（现有 API 分支逻辑几乎可直接搬） |
| MCP Server 独立二进制拿不到 registry | 选方案 A（运行时向浏览器要 `capabilities/list`），保持零编译耦合 |
| 一次性重构面太大 | 分 P1→P4，每批可独立交付、可回滚；`layout.rs` 等保留 `pub use` 兼容层 |
| build.rs 生成 TS 增加构建复杂度 | 只在 `cargo build` 时写文件；生成物进 `.gitignore` 并由 `npm run build` 前检查存在性（缺失则报错提示先 `cargo build`） |
| 常量"收敛"后前端反而要 import 一堆 | 前端只 import 需要的模块（`import { LAYOUT } from '@/constants'`），tree-shaking 无压力 |

---

## 六、建议起点

**先做 P1**（常量 + 契约生成管线）——收益立竿见影、风险最低，且为后续所有批次铺路（registry 的参数 schema、skills 的入口、plugins 的键名都依赖这层）。

P1 拆成两小步，可分别验收：

**P1-a（常量）**：
1. `AISidebar.vue` 的 `38 + 36` 改为生成物里的 `LAYOUT.tabBar + LAYOUT.addressBar`
2. 4 处搜索引擎 URL 收敛为 1 处；`DEFAULT_FAVICON`/颜色数组收敛
3. 跑全量测试 + 打包部署，确认 AI 面板 topOffset、地址栏、新标签页搜索行为不变

**P1-b（契约）**：
1. `contracts.rs` 声明 41 个设置键（含默认值）→ 生成 `DEFAULT_SETTINGS` → **补齐 19 个缺失键**
2. 事件名 / 内部 URL / 超时 / 快捷键表迁移
3. 重点回归：设置页各项显示正常（不再有空串失真）、快捷键（网页持焦时 F12 等）仍生效
