## C-9 缓存命中（✅ 通过，铁证）

**方法**：隔离实例（含 C-9/C-11 代码）unix socket 调 `{"cmd":"translate"}` 同一文本两次。

| 调用 | 耗时 | 结果 |
|------|------|------|
| CALL1（缓存 miss → google 引擎） | **1496ms** | 敏捷的棕色狐狸跳过了懒狗 |
| CALL2（缓存命中 → 本地 DB） | **5ms** | 同上 |

- **300× 提速**，CALL2 的 5ms 为纯本地（HMAC 计算 + DB 查询），排除网络抖动
- 落盘证据：临时库 `translate_memory` 出现 `model=engine:google:zh-CN` 行，
  `source_hash=574ec682…`（HMAC-SHA256，**原文不落明文**，C-11 口径），`target=敏捷的棕色狐狸跳过了懒狗`，`hits=1`
- `translate.key` 首次使用**自动创建**：44 字节（base64×32B），**权限 0600**
- 对照实验（旧版真机实例，bing 引擎）同文本 4 调：2474 / 529 / 1427 / 322ms——无稳定低值，
  纯引擎网络抖动；真机库 `engine:*` 行 0 条。两模式行为差异**恰好证明**缓存生效与否的区别
- 单测锁：`cargo test --lib translate` 15 passed（记忆读写/超限裁剪/大批分块/engine 命名空间）
- 接线核查：native `/text`、`/batch`（proto/shift/protocol.rs L172-179）与 Tauri 命令
  `translate_text`（translate.rs L554→L574）均走 `translate_text_cached` + `hmac_key`

**旧版为何 0 落盘**：`strings /usr/bin/shift-browser | grep -c "记忆命中" = 0`——安装版二进制
（10-14 构建）不含 C-9 特征串（C-9 于 10-15 14:55 合入）。`hmac_key` 为缺失即建，
真实库无 translate.key 是旧版从未跑过该逻辑，**非 bug**。

## F-9 反指纹模式持久化（✅ 库层 + 契约层；UI 层未验）

- **真实库证据**：`privacy_fp_mode = uniform`——正是 F-9 审计时的原始 bug 场景值
  （库里有 uniform、旧版 UI 恒显「加噪」）。新版下该值可被 UI 读回并生效
- 契约层（bug 根因）：`privacy_fp_mode` 已登记 SETTINGS 且 `is_allowed=true` / `is_internal=false`
  （通用可读写），由 lib_tests 两个测试锁死（`internal_keys_must_be_declared_in_settings`、
  `dedicated_keys_are_registered_in_contract`）
- 代码路径：`set_privacy_fp_mode` upsert + `get_privacy_fp_mode` 读回 + adblock 注入
  `window.__SHIFT_FP_MODE__`（adblock.rs L142-144）
- 隔离实例日志：「隐私防护已注入（标准档 standard）」「指纹补齐注入成功」——新版注入链正常
- 未验：设置页切换/显示 UI（截图通道死 + API 无 settings 写命令）。**建议真机升级后人工点验**：
  设置-隐私 → 反指纹模式应显示「统一化」（库值 uniform），切换不再报「设置保存失败」

## 关键发现（本次 e2e 附带）

1. **真机在跑 10-14 旧版二进制**（/usr/bin/shift-browser，10-14 21:52 构建）：
   10-15 合入的 C-8 / C-9 / C-11 / F-9 / F-14 等功能**真机均未生效**。
   F-29 的「补验」价值正在于此——验的不是代码，是真机与代码库的版本差。
   **建议：真机升级到 ≥5.8.3 并重启**（升级后上述各项真机行为即自动生效）
2. **opencode 模型 agnes-2.5-flash 被供应商拒绝**：消息 `error=APIError "Subscription request not
   allowed"` → 真机「随手问 / 网页汉化」当前不可用。webzh_live 4 例失败全源于此（环境问题，
   非代码 bug；`prompt_async` 返回 204 受理正常，模型处理阶段报错）
3. **webzh_live 2 个性能类用例假绿**：`live_并发提速对比` / `live_批大小对单批耗时影响`
   不断言「拿到译文」，模型停摆时解析 0/N 仍 ok。建议补「至少一条译文非空」断言
4. **ask_once 空串当成功**（webqa.rs L864-936）：done 事件到达但 0 个 delta 时返回 `Ok("")`，
   调用方拿空串去解析才报错。建议空串直接报「模型无输出」
5. 好发现：HTTP 端口被占时开放 API **优雅降级到 unix socket**（os error 98 → socket 照常服务），
   多实例共存路径稳健
