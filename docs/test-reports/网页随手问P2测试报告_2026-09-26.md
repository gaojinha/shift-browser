## 一、P2 交付了什么

浏览器只做"手/入口"，大脑是本机 opencode。本层加三条 Tauri 命令：

| 命令 | 作用 |
|---|---|
| `opencode_probe` | 连通性探测：凭据可用性、模型、agent 列表、隐私档。不回显凭据 |
| `opencode_ask` | 发起问答（流式）。建/复用 session → 开 SSE → `prompt_async` → 过滤本 session 的 assistant 增量 → 收尾 |
| `opencode_cancel` | 停止生成（前端"停止"按钮） |

入参打包成 `AskRequest` 结构体，而非 8 个位置参数。

## 二、接口调研：纠正了三个想当然的认知

**P1 的教训是"别凭记忆写代码"，所以本层每个接口都实打实测。** 结果推翻了三处原以为知道的：

| 原以为 | 实测 |
|---|---|
| 认证用户名是 `opencode` | **3 位自定义值**，且不在浏览器进程环境变量里。硬编码猜错 → 401 两次 |
| 官方有 OpenAPI 规范 | `/openapi.json`、`/doc`、`/spec` 等 **6 个端点全是 SPA 兜底 HTML**（2884 字节非 JSON）。**没有真规范可查** |
| 传 `system` 字段能改人设 | **被静默忽略**，`agent` 字段才生效 |

实测确认的接口（opencode v1.18.32）：

- `POST /session` → `title` 生效；**`directory` 被静默忽略**（目录锁死在 serve 进程 cwd = 钉钉桥工作区，不可按 session 指定）
- `POST /session/:id/message` → 同步，返回 `{info, parts[]}`
- `POST /session/:id/prompt_async` → **HTTP 204 即返**，0.33s
- `GET /event` → SSE；关键事件 `message.part.delta`（带 `sessionID`/`messageID`/`field`/`delta`）、`session.idle` 收尾
- `agent` 字段 **per-request 生效** → 因此**不必修改 opencode 配置文件**

事件分布实测（一次问答 31 个事件）：
`message.part.delta` / `message.part.updated` / `message.updated` / `session.status` / `session.diff` / `server.connected` / `server.heartbeat` / `session.idle`

**依赖零新增**：`reqwest 0.12`（已开 `stream`）、`futures-util`、`base64`、`tokio full` 全在。刻意避开 `bytes` crate（RUSTSEC 顾虑）——改用 `AsRef<[u8]>` 泛型约束绕开。

## 三、三个设计决定

### 1. 凭据零配置自动发现

扫 `/proc` 找命令行含 `opencode` + `serve` 的进程，读其
`OPENCODE_SERVER_USERNAME` / `OPENCODE_SERVER_PASSWORD`。

好处：
- **不落盘**（没往 `contracts.rs` 白名单加任何敏感键，也没改共享契约文件）
- **不进前端**（`Debug` 手工实现不 derive，`{:?}` 只打 `<redacted>`，有单测守着）
- **不必手填密码**

回退路径：若用户显式配置了 `opencode_username` / `opencode_password`，优先用之（走 `settings_cache` 内存缓存，不打库）。

### 2. 默认 agent 用 `plan`

opencode 侧 `plan` 描述为 "Disallows all edit tools"。

**为什么必须钉死只读**：session 的 `directory` 锁死在 serve 进程 cwd（钉钉桥工作区），若不设防，模型可能拿着网页上下文去读写那儿的文件。

### 3. `ensure_agent_exists` 显式拦截（安全发现）

**实测行为**：传不存在的 agent 名（如 `__nope__`），opencode **不报错，直接静默回退到默认 agent**。而默认 agent 是 `build`（**有编辑权限**）。

这等于偷偷把只读边界放宽了。代码里改为：发问前校验 agent 存在，不存在则**拒绝发问**并明确报出风险，不靠运气。单测 + 真机测试各覆盖一条。

## 四、安全与隐私

- **只连 `127.0.0.1:4096`**；`0.0.0.0:4098`（高哥有意对外暴露的实例）**一个字节没碰**
- **网页内容不出本机**：prompt 只发给回环地址
- **隐私档 L2**：固定三件套 = 问题 + 选区/段落 + 页面标题/网址。不带 cookie、不带完整 DOM
- **凭据只在 Rust 内存**：不落盘、不进前端、不写日志（`Debug` 手工实现）
- **prompt 里钉死边界**：末尾显式要求"不要读写任何文件、不要执行任何命令、不要调用工具"

### 遗留风险（已知，未修）

1. **人设串味**：`plan` agent 回答仍带「个人助手」人设（如"高哥，您这甲是啥意思…排八字？"）。`system` 字段被 opencode 忽略，改不了。根治需新建专用 agent（**改用户 opencode 配置，待高哥拍板**）。
2. **session 目录不可控**：落在钉钉桥工作区，靠 prompt 约束 + `plan` 只读兜底。
3. **SSE 全局流**：每问开一条连接，按 `sessionID` 过滤。并发复用**同一** session 时事件可能交错（P2 未做串行化）。每次问新建 session 或按 session 串行可规避。
4. **未见文档的兜底**：不存在的 agent 被静默回退的行为，若 opencode 未来改语义需重测。

## 七、过程中踩的坑（留给下一个）

1. **`Result` 是 enum 不是 trait**，不能当 trait bound 用（`R: std::result::Result<T,E>` 编译失败）。
   正解不是硬凑泛型，而是把纯逻辑（`SseAccumulator`/`fold_event`/`build_prompt`）与 IO 循环（`drive`）分离——
   顺带白拿了可测性。
2. **闭包回调要 `+ Send`**，否则 Tauri 报 "future is not `Send`"。
3. **`lib_tests.rs` 靠手工维护的 `include_str!` 清单**校验"注册命令都有定义"，新文件不登记就红。
4. **`opencode_ask` 参数过多**：clippy 报 9/7。没用 `#[allow]` 糊，而是打包成 `AskRequest` 结构体——
   前端按字段名传，漏字段在调用点暴露而非运行时错位。
5. **先开 SSE 再发 `prompt_async`**：反了会漏掉开头事件。
6. **`/proc` cmdline 是 NUL 分隔的**：匹配要按 `contains("opencode")` + `contains("serve")` 两个独立片段，
   拼成 `"opencode serve"` 反而匹配不到。
