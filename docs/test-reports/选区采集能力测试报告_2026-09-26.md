## 三、查出并修掉的缺陷

### 缺陷 1：休眠标签返回裸 `E_INTERNAL`（已修）

- **发现途径**：跑到真实网页（GitHub）做终态验证时暴露，夹具页全绿但真实页报错。
- **现象**：标签 `hibernated: true` 时返回 `E_INTERNAL "找不到标签 webview"`。
- **危害**：侧边栏会把"标签睡着了"误报成"你没选东西"——用户已选好文字，AI 却说没选。
- **对比**：`read_status` 对同情况给可操作提示，仅本能力是裸报错。
- **修法**：范式对齐 `read_status`——`ok:true` + 机器可判的 `hibernated:true` + 可操作 `hints`；并给脚本 base 补 `hibernated:false`，保证响应形状恒定。
- **复验**：修复后重跑 40 条主功能断言仍 **40/40**；休眠态分支真机触发 **9/9**。

## 四、未覆盖项（如实记录）

| 项 | 说明 | 风险评估 |
|---|---|---|
| **真实鼠标拖选手感** | 选区由夹具页 `Range`+`addRange` 造出，与拖选**同构**（脚本只读 `getSelection()`/`anchorNode`/`isCollapsed`/`toString`，两条路径一致），但**拖拽动作本身**无法自动化模拟 | 低。建议人工随手拖一次确认 |
| **跨源 iframe 内选区** | 设计上同源策略取不到、如实 `has_selection=false` 不谎报，但未造 iframe 用例实测 | 低-中。行为是"取不到"，不会错报内容 |
| **shadow DOM 内选区** | `anchorNode` 归属未专项测 | 低 |
| **性能** | 未测，无数据 | 低。当前实现是单次 DOM 读取 + 一次 eval |

## 五、测试方法学

- **选区构造**：夹具页 `tests/fixtures/selection.html` 按 `?case=` 在 `load` 后用
  `document.createRange()` + `Selection.addRange()` 造出**真实 Selection 对象**。
  采集脚本读到的字段与鼠标拖选完全同构。
- **用例参数化**：none / para / li / td / long / password / ok / quote / pre。
- **标签管理**：全程**单标签复用**（`navigate` 而非 `open_url`），收尾关闭，避免堆标签。
- **休眠态制造**：临时将 `tab_hibernate_minutes` 置 1 分钟 → 重启让预热读到 →
  切走标签使其空闲 → 轮询至 `hibernated:true` → 测完**删除该设置记录**回默认。
  （注意：设置缓存无 TTL，运行中改库不生效，必须重启。）
