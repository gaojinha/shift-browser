# F-CEF-24 CPU 改造 — 拆解与排期（2026-10-28）

> 依据：`docs/F-CEF-24-CPU优化方案_2026-10-27.md`（根因/实验）+ `.ai/outbox/atomcode/20261028-0237-F-CEF-24消息循环预审报告.md`（17 个 thread_local 清单 / 12 个组 A 入口 / 死锁两坑 / API 行号已核）。
> 原则：小步单卡，每卡可独立编译验证，任一卡失败可单行回退。

## 目标

`multi_threaded_message_loop = 1`（CEF 自跑消息循环），主进程 CPU 从 64–85% 降到 ~5.5%，且不出现跨线程 panic / 死锁。

## 四张卡（依赖顺序）

| 卡 | 内容 | 谁 | 依赖 | 验收 |
|---|---|---|---|---|
| **24a** | 新建 `engine/cef/cef_ui.rs`：`cef_ui`（fire-and-forget）/ `cef_ui_call`（同步回传）/ `UiExecutor` trait + `InlineExecutor` 单测（短路、mpsc 回传、顺序） | atomcode | 无 | clippy 0；test 新增 ≥3 用例；不碰现有文件（只加 mod 注册） |
| **24b** | 17 个 `thread_local!` → `Mutex`/`Atomic`：shell.rs 14 + browser.rs 3；100 处 `.with(…)` → `.lock()`；`ACTIVE_TAB` 并入 `TabState{tabs,active}` 同一把锁 | 二狗 | 无（与 24a 并行不同文件） | clippy 双配置 0；test 全过；**行为零变化**（不开 multi_threaded，仍走固定泵） |
| **24c** | 组 A 12 个入口包 `cef_ui`：open / force_show(window.show) / navigate / run_toolbar_js(自身短路) / refresh_tabbar / cef_navigate / cef_close_window / connect_size_allocate / connect_delete_event / create_browser / browser::resize / browser::close | 二狗 | 24a + 24b | clippy 0；真机面板全表回归（仍未开 multi_threaded） |
| **24d** | 翻 `multi_threaded_message_loop = 1` + 去掉固定泵 + 真机回归 + CPU 实测 | 二狗 | 24c | 真机 7 项回归（方案 6.2）+ CPU 读数 |

## 关键纪律（24b/24c 必须守）

1. **锁作用域单表达式**：clone 出句柄/数据立即 drop，绝不持锁调 CEF。
2. **`cef_ui` / `cef_ui_call` 一律在锁外**。
3. **被投闭包内独立 lock**，不捕获外层 guard。
4. **`cef_ui_call` 必须有 `currently_on(ThreadId::UI)` 短路**（否则 CEF 回调链里 post 给自己 = 必死）。
5. 24b 单独提交时 **不开 multi_threaded**，保证行为与现状一致（可单测/真机对照）。

## 回退

24d 出问题：`multi_threaded_message_loop = 0` + 恢复 50ms 泵（单行）。24a~24c 的改动在 0 模式下同样合法（Mutex 单线程无害、cef_ui 短路原地执行）。
