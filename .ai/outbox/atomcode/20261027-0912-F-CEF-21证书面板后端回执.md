## 一、干了啥（逐条对照卡面）

### 1. `db/certificates.rs`
- `list` 改名 **`list_certificates`**（签名 `pub async fn (pool: &SqlitePool) -> Result<Vec<CertRecord>, sqlx::Error>` 原本已存在——派单要求的"抽取"实际是零成本达成：Tauri 命令 `list_certificates` 与 CEF 侧共用这一份 SQL，**零复制**）
- 现有命令**无搜索/过滤参数**（WebKit 侧搜索是客户端 JS 过滤 `records` 数组），故未抽参数化内层函数
- **+3 单测**：
  - `list_certificates_empty_db_returns_empty`：空库空数组（CEF 面板空态依赖）
  - `list_certificates_orders_by_days_then_host`：days_left 升序（+5/+10/+30/+30d 四档，SQL 同钟源）+ 同 days_left 时 host 升序兜底（代码原 ORDER BY 口径，端口不在排序键、不硬造断言）
  - `list_certificates_field_roundtrip`：13 字段全回读 + days_left ∈{65,66} 解码（not_after=now+66d 同钟源，F-66 后不吞错）

### 2. 新建 `engine/cef/certificates_ui.rs`（范式照 `passwords_ui.rs`）
- `init(app)`：OnceLock 缓存 AppHandle
- `certificates_json(app)`：block_on `list_certificates`，**十字段与 WebKit 前端 `CertRecord` 逐一对齐**（host/port/subject/issuer/not_before/not_after/fingerprint_sha256/change_count/last_seen/days_left）；**不输出** chain_json（证书链）、例外详情等敏感/超量字段
- `handle(cmd, arg) -> bool` 三命令：
  - `certpanel|0/1`：留 TODO——shell.rs 加证书面板 setter（同 `set_pw_panel` 模式）后接通（禁改 shell.rs）
  - `certrefresh`：留 TODO——`shell::run_toolbar_js` 是私有函数本模块不可见，接线时经它执行 `window.__shiftCertsRender()`（派单明示"不可见就先留 TODO"）
  - `certdel|<host>:<port>`：**已实现**，走 `certificates::delete`（删除后 DB 减 1）；二次确认在页面侧
- **`certdel` 参数口径 = `host:port`**：certificates 表无自增 id，主键即 (host, port)，这是唯一自然标识；支持 IPv6 括号形 `[::1]:8443` 与裸形 `::1:8443`
- **+2 纯函数单测**：`parse_host_port_forms`（正常/IPv6 两形/畸形 4 类）+ `unknown_cmd_not_handled`（不吞他模块命令）
- **先交付后接线**：二狗接 `shell.rs::handle_action` 与 cef_cmd.rs HTML 内嵌之前整模块无业务引用 → 6 个 dead_code 警告。按代码库惯例（`app.rs`/`shell.rs`/`browser.rs`/`eval_js` 等 20+ 处 `#[allow(dead_code)]` 先例 + `agent_actions.rs` 模块级先例）加**模块级** `#![allow(dead_code)]` 并注释说明；**接线完成后必须删掉这行**（已写进模块注释与下方待接线清单）
