## 🐛 发现一个产品 bug（比 F-56 那个影响更实在，请优先拍板）

**`CertRecord.days_left` 在生产上恒为 `None`，证书面板「剩余天数」列一直显示「—」。**

- 根因（探针实测，非猜测）：`list`/`get`/`expiring_within` 的 SQL 用 `CAST(julianday(not_after) - julianday('now') AS INTEGER) AS days_left`，产出 **INTEGER** 类型列；`row_to_record`（:68-72）却用 `try_get::<Option<f64>, _>("days_left")` 解码，sqlx 0.8.6 报 `ColumnDecode: mismatched types; Rust type Option<f64> (as SQL type REAL) is not compatible with SQL type INTEGER`，`.ok()` 吞掉错误 → 恒 None。探针对照：同列 `try_get::<Option<i64>>` → `Ok(Some(43))`。
- 影响：SQL 侧窗口/排序不受影响（面板顺序是对的），但 `CertificatesDialog.vue:251-256` 的 `v-if="r.days_left !== null"` 永不成立 → **「N 天 / 已过期」徽标从不显示，该列永远「—」**。临期提醒功能等于只有排序、没有数字。
- 修法（一行二选一）：① `row_to_record` 改 `try_get::<Option<i64>, _>`；② SQL 改 `CAST(... AS REAL)`。推荐 ①（julianday 差截断成整天数本来就是字段语义）。
- 本次未改产品代码（测试卡纪律），测试已钉住现状（断言恒 None + 修复指引注释：修完改断言为 `Some(-5)/Some(19|20)/Some(29|30)` 并删注释）。
