## 一、干了啥

F-CEF-18 收口后做第二轮真机复验，发现查找条号显示**双加一** bug：18 条靶页**首查显示 2/18**（应 1/18）。

**根因（1 基转换做了两遍）**：
- Rust 侧 `on_find_result` 有 `let active = active_match_ordinal.saturating_add(1);`（实现时的 0 基→1 基修正，随 `95de1d5` 提交）；
- 工具栏侧 `renderFindCount` 有 `Math.min(active + 1, count)`（二狗收口时的 0 基显示修正，见收口回执「三.1」）。
- 两处 +1 叠加：CEF 回调 ordinal 0（首条）→ Rust +1 → 工具栏 +1 → 显示 2/N。
- **为什么收口验收没暴露**：`ff18-verify.sh` 的靶页只有 1 条匹配，`Math.min(3, 1)` 钳制后恒显示 1/1，加一被完全遮住。本轮改用 18 条真实靶页才暴露。

**修法（1 行，shell.rs `on_find_result`）**：去掉 Rust 侧 `saturating_add(1)`，`active_match_ordinal` 原样透传；1 基转换只留工具栏侧（保留二狗收口加的 `Math.min(active + 1, count)` 及其钳制行为）。ordinal=-1（无匹配）→ 工具栏 min(0, count) → 0/N，只在瞬态出现，正常查找恒有 active。
