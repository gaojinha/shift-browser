# F-CEF-11：把扩展/隐私/广告拦截脚本注入到 CEF 页面

你 F-CEF-10 调研发现的那个缺口，现在开工。

## 缺口复述（你的调研结论）

`extensions.rs::inject_extensions` 走 `app.get_window("main")` + `window.webviews()`，
CEF 独立窗口里没有这些 webview → **CEF 页面现在没有任何扩展脚本/广告拦截/隐私防护/WebMCP/翻译脚本**，
只有 `browser::inject_marker` 注入的标记 + 品牌表。

## 目标（最小可用，别贪多）

让 CEF 页面加载时，把**当前已启用**的注入项送进去：

1. 广告拦截 JS + CSS（`adblock::collect_enabled_items` 的产出）
2. 隐私防护脚本（`PRIVACY_JS` / `STRICT_PRIVACY_JS`，受 `privacy_shield_level` 控制）
3. 用户脚本（`crate::db::userscripts::cached_scripts()`，已是同步缓存）
4. `compat_chrome.js`（受 `compat_chrome_fp` 控制）
5. WebMCP polyfill（`webmcp_on` 为真时）

**上下文前缀变量必须一起注入**（页面脚本依赖）：
`__SHIFT_PRIVACY_WHITELIST__` / `__SHIFT_TRANSLATE_TIMEOUT` / `__SHIFT_FP_MODE__` /
`__SHIFT_SESSION_KEY__` / `__SHIFT_UA_BRANDS__` / `__SHIFT_SITE_OVERRIDES__` / `__SHIFT_GPC_ON__`
—— 这些在 `extensions/adblock.rs` 的 `wl_prefix` 里已经拼好，**别重写一份**，抽成公共函数复用。

## 实现方案（已查证，照这个方向）

- `adblock::collect_enabled_items(&db)` 是 async，产出 `(Vec<(Option<String>, Option<String>)>, bool)`
- CEF 的 `on_load_start` 是**同步**回调，不能 await → **启动时预计算 + 缓存**
  - 在 `cef_cmd::init` 里（或 `open_shell_on_main` 之前）用 `block_on` 算一次，
    拼成一整段 JS 字符串存 `static CEF_INJECT_JS: Mutex<Option<String>>`
  - `on_load_start` 里取缓存，`execute_java_script` 执行
- CSS 注入：`document.head.appendChild(document.createElement('style')).textContent = '...'`
  （CEF 的 execute_java_script 只能跑 JS）
- **顺序**：前缀变量 → 隐私脚本 → adblock → compat → webmcp → 用户脚本
- 与现有 `inject_marker` 合并：brands/标记 + 这一整套，一次执行（别注入两遍）
- 设置变更后不要求热更新（CEF 还是实验阶段），注释里写明"改设置需重开窗口"

## 验收（真机，必须自己跑）

1. 起实例（临时 profile + 端口 9337 避开 atomcode）：
   `SHIFT_CEF_CACHE_DIR=/tmp/cef-ext-xxx SHIFT_CEF_SHELL_URL=https://example.com SHIFT_CEF_DEBUG_PORT=9337 ./target/debug/shift-browser`
2. CDP 求值确认：
   - `__SHIFT_INJECT_OK__ === true`（通道仍在）
   - `navigator.userAgentData.brands` 有三项含 Google Chrome（没被覆盖坏）
   - `window.__shiftPrivacyFeatures` 或 `__shiftNoiseOn` 存在（隐私脚本生效）
   - 广告拦截：找一个已知被拦的域名页面或检查 `ADBLOCK_INJECTIONS` 计数增长
3. 截图 + 报告里贴 CDP 原始输出
