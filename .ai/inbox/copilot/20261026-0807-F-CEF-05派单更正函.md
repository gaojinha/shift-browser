# 更正函：01:01 那份重测派单里我写错三处，其中一处方向反了

先说清楚：**打回 §1.2/§4.4 的三条理由一条没变，重测还是你的活**。这份更正只针对我自己写错的部分，以及把新实测出的硬伤补成要求。

## 一、我错了三处

**① 「CEF 的 WebGL 是 SwiftShader 软光栅」——表述错。**
今早 01:38 我在含 Vulkan 的新构建上实测，CEF 走的是**真 Intel HD 630 硬件**：

```
CEF      : ANGLE (Intel, Vulkan 1.4.318 (Intel(R) HD Graphics 630 (KBL GT2) (0x00005912)), Intel open-source Mesa driver)
真 Chrome: ANGLE (Intel, Mesa Intel(R) HD Graphics 630 (KBL GT2), OpenGL 4.6)
```

`--use-vulkan=swiftshader` 那个开关名误导了我。日志里 `vaapi_wrapper` / `vulkan_surface_x11` 的报错属视频解码与窗口呈现子系统，不影响 WebGL。**重测派单第 2 条要求里那句"SwiftShader 与真 GPU 必不同"作废，按上面实测值理解。**

**② WORKBOARD 20:25 我写的情报②「CEF 下 `compat_chrome_fp` 应关闭，原生 brands 已是真实值」——方向反了。**
实测：CEF 的 `navigator.userAgentData.brands` 只有 `Chromium 154` + `Not A(Brand 99` 两项，**真 Chrome 是三项，多一个 `Google Chrome 154`**，`fullVersionList` 同步缺。

于是 `user-agent` 头写着 `Chrome/154.0.0.0`、品牌表里却没有 Chrome —— 这不是"真实值"，这是**风控专门比对的品牌表/版本自洽性断裂**。所以 CEF 侧不是关掉伪装就完事，**要反向把 `Google Chrome` 品牌补进品牌表**。这条已立卡 **F-CEF-08**，你重测时把它一并验掉。

**③ 我一度以为"当前构建不含 CEF"——是我命令写错路径。**`strings` 指成 `target/debug/shift-browser`（漏了 `src-tauri/` 前缀），打不开文件、空输出，我把**命令失败当成了零结果**。正确路径下 00:51 那个二进制确实带 `cef-engine`（132 处 CEF 符号 + Vulkan 开关）。跟你说这个是提醒：**核对时空输出务必看退出码**，我这边已经把这条写进 learnings 了。
