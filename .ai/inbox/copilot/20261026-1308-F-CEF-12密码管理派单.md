# F-CEF-12：CEF 窗口的密码管理（高哥点名缺的第 3 项）

高哥原话：「原有的密码管理功能没有实现」。主应用有完整密码库（`PasswordsDialog.vue` 214 行 +
`db/passwords.rs`），CEF 窗口里**一个入口都没有**。

## 现状

- 命令已存在：`list_passwords` / `get_password` / `save_password` / `delete_password`（`db/passwords.rs:271-322`）
- 存储：AES-256-GCM + 独立 `master.key`（已存在、600），**无需用户设主密码**
- 前端只有 WebKit 那套 Vue 对话框，CEF 窗口是纯 WebUI（HTML/JS），用不了

## 目标（最小可用）

CEF 工具栏加一个「密码」入口（钥匙图标），点击在**工具栏页内**展开一个面板：

1. 列表：站点 / 用户名（**密码只显示 `••••`，不提供"显示明文"按钮**）
2. 搜索：按域名/用户名过滤（复用 `list_passwords` 后前端过滤即可）
3. 复制密码：点击后调 `get_password_by_id` 拿明文 → 写入剪贴板 → 立即清空内存引用
   （剪贴板在 CEF 里可以用 `navigator.clipboard.writeText`，file:// 可能有权限限制，先试；
   不行就走 Rust 侧写剪贴板）
4. 删除：二次确认后 `delete_password`

**红线**：明文不得进入任何日志、回执、DOM 常驻字段；复制后不清空就是漏洞。

## 实现路径（已查证）

- 工具栏页面（`toolbar.rs` 的 HTML）加面板 DOM + `window.__shiftPasswords(list)` 渲染函数
- 数据来源：**沿用书签那套内嵌方案**（`ensure_toolbar_html` 生成时把 `list_passwords` 的结果
  嵌进 `<script type="application/json">`）——CEF 侧运行时推送实测不可靠（F-CEF-11 踩过）
- 复制/删除需要**页面 → Rust** 的请求：走现有 `console.log('SHIFT_ACT:...')` 桥，
  加 `pwcopy|<id>` / `pwdel|<id>` 两个动作
- **只改 `toolbar.rs` + `cef_cmd.rs` + 新文件**；`shell.rs` 归 atomcode（书签管理在改）

## 验收（真机）

1. 起实例（临时 profile + 空闲端口），CDP 点开面板，确认列表渲染（条数 = 库里条数）
2. 断言 DOM 里**没有任何明文密码**（用 CDP 读 `document.body.innerText` 不含已知密码串）
3. 点复制 → 读剪贴板确认拿到明文；但 DOM/日志里没有
4. 删除一条 → 数据库条数 -1
5. 截图留证
