# 派单：F-CEF-14 下载 —— 独立审查 + 验收脚本（只读，不编译）

高哥点名让二狗少动手。这单：atomcode 做实现收尾，你负责独立审查和准备复验手段，二狗最后拍板验收。

## 背景（一句）

CEF 154 不会因 `Content-Disposition: attachment` 自动下载，会让内容页当二进制渲染。方案：主框架导航挂 `ResourceRequestHandler`，在 `on_resource_response` 见 attachment 就 `start_download` + 取消导航。

**已验证**：手动 `start_download` 下 HTTPS 正常（GitHub zip 362K 落盘）；localhost HTTP 会 `NETWORK_FAILED`（边缘情况）。

## 你要做的两件事

### 1. 代码审查（只读，别改源码）

看 `src-tauri/src/engine/cef/shell.rs` 的 `ShellResourceRequestHandler::on_resource_response`，逐条回答：

- `CefStringUtf16::from(&resp.header_by_name(...)).to_string()` 的**空值/所有权**是否安全？header 不存在时会不会 panic 或读已释放内存？
- 取消导航（`return 1`）之后，标签页的 URL/标题/加载状态会不会残留脏值？`on_loading_state_change` 会不会卡在「加载中」？
- `start_download(url)` 用的是**原请求 URL**：302 跳转（GitHub → codeload）场景下会不会二次请求导致重复下载？大文件（>100MB）会不会一份变两份落盘？
- 只对 `is_navigation != 0` 挂处理器：**iframe 内导航**、`window.open`、POST 表单提交到 attachment 端点，分别会发生什么？
- 误伤风险：`Content-Disposition: inline` / 缺失 / `attachment` 出现在其它 header 值里，会不会被误判？
- 下载失败（磁盘满、权限、断网）时用户看到什么？现在有没有提示？

### 2. 写验收脚本（新建文件，不编译）

放 `scripts/cef-coordinator/fc14-verify.sh`（或 .js，你定），要求**别人拿到就能跑**：

1. 用独立的临时 profile 启动（注意：`SHIFT_CEF_CACHE_DIR` 目前实测没隔离干净，atomcode 在修——脚本里把「怎么判断是否隔离成功」写进去，比如检查内容页 URL 是不是 `SHIFT_CEF_SHELL_URL`）
2. CDP 连工具栏页，触发地址栏导航到 GitHub zip
3. 断言：
   - `~/Downloads/opencode-main.zip` 存在且 >300KB
   - 内容页 URL **仍是原页面**（不是 zip 地址、不是 `chrome-error://`）
   - `.crdownload` 残留文件为 0
4. 再跑一次普通导航 `https://example.com`，断言页面正常加载
5. 输出 PASS/FAIL 明细，退出码非 0 = 失败

**不要**改动 `src-tauri/`、不要跑 `cargo build`（编译窗口归 atomcode，同树并行会互相拖慢）。
