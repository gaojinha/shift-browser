## 三条异议，当天给

### 1【必须改，2 行】`guarded()` 的空 catch 让"注入炸了"和"注入成功"在观测上完全同形
`cef_inject.rs:18-20` 的 `catch (e) {}` 包住了隐私段、adblock JS、**CSS 注入**、compat、WebMCP、每条用户脚本。配两点就出事：
- `window.__SHIFT_INJECT_OK__ = true` 是 `inject_marker` 的**第一行**，跑在你拼的 extra 之前 → **这个靶子证明不了注入包执行过**。你验收清单第 1 项写的就是它，区分度不够。
- `css_injector`（`:23-29`）靠 `document.head || document.documentElement`；`on_load_start` 是 document_start，这俩都可能还是 null → `appendChild` 抛 TypeError → 被空 catch 吞掉 → **广告拦截 CSS 整段静默失效，日志照样打"预计算完成 N 个注入项"**。而 `adblock.rs:125` 是 `items.push((Some(js), Some(ADBLOCK_CSS)))`，CSS 有真实负载，这段必走。

改法：catch 里留痕，别静默。
```js
catch (e) { (window.__SHIFT_INJECT_ERRS__ = window.__SHIFT_INJECT_ERRS__ || []).push('<段名>:' + (e && e.message)); }
```
段名按隐私/adblock/css/compat/webmcp/用户脚本#n 给，CDP 求值 `__SHIFT_INJECT_ERRS__` 一眼定案。不改这个，以后每张注入相关的卡都可能拿到假通过数据。

### 2【必须补上，你的验收清单缺样本前置】
我实测本机 `extensions` 表 **0 行**、`userscripts` 表 **0 行**。你列的靶子里，隐私/adblock/compat 是内置项能证；但**"扩展脚本"和"用户脚本"这两条链路本轮一次都没被行为级证明过**（`userscript_injector` 的通配匹配 + 那串正则转义在 Rust 里套 JS，转义层级最容易错，静态我不敢给你背书）。
验收前先造样本：插一条用户脚本（含 `*` 与具体域名两种 pattern）+ 造一个最小 manifest 目录 `load_extension` 进去，再跑 CDP。造完记得说明"样本是我造的，非用户真实数据"。

### 3【子 frame 不注入这条，别按"实验阶段可接受"糊过去】
你在"需注意 2"承认 `inject_marker` 只打主框架。后果比 UI 重：CF 的 Turnstile 就挂在 `challenges.cloudflare.com` 的**子 iframe**——我上轮核 F-CEF-05 就是靠 `Page.getFrameTree` 递归才发现顶层 `querySelector` 抓不到的挑战框。隐私加噪和广告拦截进不了子框，**CEF 在风控 iframe 里的表现会系统性区别于 WebKit**，而 CF 通过率正是 M3 的判据。这条要单独成卡（我报高哥立 F-CEF-12），不要混在注意事项里。
