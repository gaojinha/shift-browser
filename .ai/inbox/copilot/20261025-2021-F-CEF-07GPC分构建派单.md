# F-CEF-07 领单：GPC 分构建默认值（CEF 关 / WebKit 保持）+ 设置页独立开关

**高哥 2026-10-25 拍板**（你 F-CEF-05 报告 §7 的结论直接转实现）。无前置，可与 F-CEF-02（M2，atomcode 在做）并行。

## 为什么改

你实测出来：真 Chrome 154 默认**既不发 `Sec-GPC`、也没有 `navigator.globalPrivacyControl`**；而本项目 `gpc_header` 默认 `true`，每个出网请求发 `Sec-GPC: 1` 且注入该 JS 属性——**这是真 Chrome 没有的特征**。
换核目的是让指纹像真 Chrome，不能自己挂尾巴。

## 目标

1. **CEF 构建默认关**：`gpc_header` 默认 `false`，不发 `Sec-GPC`、不注入 `navigator.globalPrivacyControl`
2. **WebKit 构建保持现状**（默认 `true`，合规表态不丢）
3. **设置页独立开关**：文案注明「开启后与普通 Chrome 行为不同，部分风控站点更易识别」
4. **DNT 不默认发**（现状已不是默认发，确认无回归即可）

## 现状（你上轮已 grep 实查，照这个动）

- `src-tauri/src/contracts.rs:89`、`src/constants.ts:68`：`gpc_header` 默认 `true`
- `src-tauri/src/db/settings.rs:290-299`：无设置时视为开，写入 `Sec-GPC: 1`
- `src-tauri/src/extensions/privacy.rs:167` / `privacy.js`：注入 `navigator.globalPrivacyControl = true`
- 前端设置项：`src/components/settings/PrivacyDataCard.vue`（GPC 开关处）

## 实现要点（先查证再动手，别硬套）

- `contracts.rs` 是唯一来源，改默认值必须跑 `cargo test --lib ts_export` 重生成 `src/constants.ts`，并同步改单测期望值。
- **按构建分流**：`cfg!(feature = "cef-engine")` 是编译期常量，可用于默认值选择；具体写在 contracts 表里还是 settings 取值处，先看 `SETTINGS` 表结构再定，选一处、别造成"两份实现"（守 AGENTS.md 单一判定原则）。
- 前端开关读取的是后端返回的设置值，不要在前端再写一份默认值判断。
