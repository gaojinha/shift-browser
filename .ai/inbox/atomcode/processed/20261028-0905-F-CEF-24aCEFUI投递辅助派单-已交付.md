# 派单：F-CEF-24a CEF UI 线程投递辅助（小步单卡）

## 背景

F-CEF-24（CEF 消息循环 CPU 优化）第一张卡。方案见 `docs/F-CEF-24-拆解与排期_2026-10-28.md`，你的预审报告结论已被采纳。

## 目标（一张小卡，别扩）

新建 `src-tauri/src/engine/cef/cef_ui.rs`，提供把闭包投递到 CEF UI 线程的两个辅助。**只加文件 + mod 注册，不碰任何现有逻辑**。

## 交付

1. **`UiExecutor` trait**（可注入，单测用）：
   ```rust
   pub trait UiExecutor: Send + Sync {
       fn on_ui_thread(&self) -> bool;
       fn post(&self, f: Box<dyn FnOnce() + Send>);
   }
   ```
2. **默认实现 `CefUiExecutor`**：
   - `on_ui_thread()` → `cef::currently_on(cef::ThreadId::UI) == 1`
   - `post(f)` → 用 `wrap_task!` 定义 Task（参照 crate `src/wrapper/message_router.rs:382-400` 的用法），`cef::post_task(cef::ThreadId::UI, Some(&mut task))`
3. **两个公开函数**（内部走 `UiExecutor`，默认 `CefUiExecutor`）：
   - `pub fn cef_ui(f: impl FnOnce() + Send + 'static)` — 已在 UI 线程则**原地执行**，否则 post
   - `pub fn cef_ui_call<R: Send + 'static>(f: impl FnOnce() -> R + Send + 'static) -> R` — 已在 UI 线程则原地执行返回；否则 `mpsc::channel` 投递 + `recv()` 等结果
4. **单测（用 `InlineExecutor` / stub executor，脱离真 CEF）**：
   - 短路：`on_ui_thread()==true` → 断言原地执行、`post` 调用次数 0
   - 回传：`cef_ui_call` 返回正确值
   - 顺序：连续 post 两个任务，执行顺序不变
   - 至少 3 个用例
5. `mod.rs` 注册 `pub mod cef_ui;`

## 死锁铁律（写进模块文档注释）

`cef_ui_call` 的 `currently_on(ThreadId::UI)` 短路是**正确性前提**，不是优化——CEF 回调链里调它若不自短路，会 post 给自己、自己的循环被自己阻塞，必死锁。
