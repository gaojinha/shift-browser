# F-CEF-13：CEF 书签栏的管理能力（高哥点名缺的第 2 项）

高哥原话：「标签栏是把所有标签放了上去，没有做目录收藏和管理」——
现在书签栏只能看（64 条真实书签）、只能点开，**不能增删改、不能按文件夹分层**。

## 现状

- 书签栏数据已接主应用库（`ensure_toolbar_html` 内嵌 `bookmarks` 表，见 `a358f16`）
- 命令齐全：`create_bookmark` / `update_bookmark` / `delete_bookmark` /
  `create_bookmark_folder` / `delete_bookmark_folder` / `search_bookmarks`
- `bookmarks` 表有 `folder_id`，`bookmark_folders` 表有层级

## 目标（最小可用，别做全套管理器）

1. **右键菜单**（书签栏空白处 + 书签项上）：
   - 书签项：打开 / 编辑（改名/改 URL）/ 删除
   - 空白处：新建书签 / 新建文件夹
2. **文件夹下拉**：文件夹里的书签收进一个下拉（点击文件夹名展开），不要平铺 64 条
3. 增删改后**立即刷新书签栏**（重新查库 → 重推内嵌？运行时推送不可靠，
   改成：操作后 `reload` 工具栏页面 —— 页面重载会重新生成 HTML 吗？不会，
   HTML 是生成时写死的。**所以要在页面内做局部刷新**：操作成功后页面向 Rust 请求最新列表，
   Rust 返回后前端重渲染，**不动 HTML 文件**。
   → 需要新增一个页面→Rust→页面的往返通道（现在 console 桥是单向的）。
   **建议**：`console.log('SHIFT_ACT:bmreload')` → Rust 收到后 `execute_java_script`
   调 `window.__shiftBookmarks(list)`（书签这场的推送时机问题在 F-CEF-11 已解决，
   只要是在**用户主动操作后**推，页面肯定已加载，可靠）。

## 实现路径

- UI 在 `toolbar.rs` 的 HTML 里（右键菜单 + 文件夹下拉）
- 动作走 `console.log('SHIFT_ACT:...')`：`bmadd|`、`bmedit|<id>`、`bmdel|<id>`、
  `bmnewfolder|`、`bmreload`
- Rust 侧在 `shell.rs` 的 `handle_action` 里接（这是你的文件，copilot 不碰）
- 增删改调 `db::bookmarks` 的现成命令（注意：那些是 `#[tauri::command]` async 函数，
  在 CEF 回调里要 `block_on`）

## 验收（真机）

1. 右键书签 → 删除 → 数据库条数 -1、书签栏少一条（不用重开窗口）
2. 右键空白 → 新建书签 → 条数 +1、书签栏出现新条目
3. 文件夹下拉能展开、只显示该文件夹内的书签
4. 截图 + CDP 数据留证
