## 静态就能定性的三条硬伤（不等真机也成立）

### A【最重要：`guarded()` 空 catch 会把失败全吞掉，验收存在"假通过"结构】
`cef_inject.rs:18-20`
```rust
fn guarded(js: &str) -> String { format!("try {{\n{js}\n}} catch (e) {{}}\n") }
```
隐私段、adblock JS、**CSS 注入**、compat、WebMCP、每条用户脚本全被它包着，异常**不留痕、不打日志**。
配合两点就出事：
1. `window.__SHIFT_INJECT_OK__ = true` 是 `inject_marker` 的**第一行**，跑在它拼进去的 extra 之前 → **`inject_ok` 为 true 证明不了注入包执行过**。而它验收清单第 1 项就是这个，**靶子区分度不足**。
2. `css_injector`（`:23-29`）依赖 `document.head || document.documentElement`；`on_load_start` 是 document_start 时机，此时两者都可能还是 null → `appendChild` 抛 TypeError → 被空 catch 吞 → **广告拦截 CSS 整段静默失效**，而日志照样打"预计算完成 N 个注入项"。
   这条不是杞人忧天：`items.push((Some(js), Some(ADBLOCK_CSS)))` 说明 **CSS 有真实负载**，必走 `css_injector`。
   真机探针我特意收 `style_count` / `style_len_head` / `style_snippets`，就是为把这件事钉死。
**修法（2 行的事）**：catch 里 `window.__SHIFT_INJECT_ERRS__=(window.__SHIFT_INJECT_ERRS__||[]).concat('<段名>:'+e.message)`，CDP 一求值就露馅。否则"注入了"和"注入炸了"在观测上完全同形。

### B【adblock 的 MutationObserver 必然不挂 —— 但这是既有缺口，不记它账上】
`resources/js/adblock.js:48` `if (document.body) { observer.observe(...) }`，全文**无** `DOMContentLoaded`/`readyState` 兜底（我 grep 过整个 `resources/js/`）。document_start 下 body 必为 null → 动态内容不再拦（首次 `hideByText()` 仍跑一次，:39）。
我核过 WebKit 路径同源（也是 `collect_enabled_items` 的产出 + documentStart 注入）→ **不是 CEF 引入的回归**。但若要补，**必须两侧一起补**，否则 WebKit/CEF 行为口径漂移——我们整条线现在吃的就是"CEF ≥ 同口径真 Chrome"这个判定，口径漂不得。

### C【子 frame 无注入 → 直接影响 M3 的 Cloudflare 通过率口径】
它自己在"需注意 2"承认：`inject_marker` 只打主框架，子 frame 不注入。
这条的后果比 UI 层面重：CF 的 Turnstile 挑战就挂在 `challenges.cloudflare.com` 的**子 iframe**里（我上轮就是靠 `Page.getFrameTree` 递归才发现顶层 querySelector 抓不到的挑战框）。**隐私加噪/广告拦截脚本进不了子框，CEF 在风控 iframe 里的表现会系统性区别于 WebKit 路径**，而 CF 通过率正是 M3 的关口。建议：并入 F-CEF-11 的第二阶段或单独立卡，别混在"实验阶段可接受"里糊过去。
