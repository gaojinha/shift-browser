## 二、硬伤

### 硬伤 1：「全程未出现 Turnstile iframe」与自己的原始数据矛盾
- §4.4 局限 3 与 meta 第 8 行都写「本轮无任何一次出现 Turnstile iframe」。
- 实测 `cf-raw.json`：**17/36 次访问加载了 `challenges.cloudflare.com/cdn-cgi/challenge-platform/...` 的 Document**（cef 9/18、chrome 8/18），nodeseek/nowsecure/indeed 的正常页也出现。
- `has_cf_iframe` 恒 0 是因为探针只在**顶层 document** 里 `querySelector('iframe[...]')`，CF 挑战框在嵌套 frame 中，根本探不到。
- **这是把"看不见"写成"没有"**。"可点过"中档 0 次观察这句不成立，须改为"探针无能力观测，本轮未覆盖"。修法：`Page.getFrameTree` + 遍历各 frame。

### 硬伤 2：`verdict_final` 用了词表外标签，数据与结论不自洽
- meta 声明词表只有 `pass / turnstile_or_challenge_shown / hard_block_or_stuck`。
- 实际 `verdict_final` 出现第 4 个值 `hard_block`（1 处）。
- 后果：**任何人拿脚本按声明词表自动统计，chrome indeed 会被算成 2/3、合计 12/18**（二狗第一次就中了这个，17/18 vs 12/18）。结论正确性依赖读者"人脑补"一处订正 → 不可复现。
- 修法：标签统一为 `hard_block_or_stuck`，订正理由写进 `verdict_note`。

### 硬伤 3（最重）：窗口内有第二个 CEF 实例并发，且 CEF 用的是应用真实持久化 profile
- `journalctl` 铁证：**10:26:54 `shift-cef-atom3.service` Started**，正落在测试窗口 10:20:49–10:33 中段（atomcode 在跑 F-CEF-03）。
- CEF 进程命令行（当日实测）：`--user-data-dir=/home/gao/.cache/com.shiftbrowser.app/cef` → **CEF 侧不是独立临时 profile，是应用真实 profile**；`Default/Cookies` mtime 10:42。meta 只给 Chrome 写了独立 profile，CEF 没写。
- 二进制**在窗口内被重编**：`target/debug/shift-browser` mtime 由 00:51 → 10:25（526018792 → 526033024 字节），10:51 又编一次。meta 却声明"被测=00:51 构建 HEAD 4269ea5"，无从自证。
- 风险方向明确：**profile 里若残留昨天的 `cf_clearance`，会让 CEF 侧带上历史信誉**，而 linux.do 的差距（5/6 vs 2/6）恰恰是本轮唯一的大差异来源。`Network.clearBrowserCookies` 在 CEF 上是否真生效**至今没人验证过**（二狗本轮想做，撞上 atomcode 实例占用，让行未做）。

## 三、二狗的统计更正（对数据有利，但同样要限定）

- 按 `verdict_final` 语义口径：CEF 17/18 vs Chrome 11/18。
- **配对（同站同轮 18 对）：双过 11｜只 CEF 过 6｜只 Chrome 过 0｜双挂 1** —— 严格包含关系，比"合计"更有说服力。
- McNemar 精确二项 **p = 0.031**；合计 Fisher **p = 0.041**。原报告写"不能当统计显著"偏保守。
- 但必须同时钉死三条限定：① 同站重复访问**非独立样本**，p 值只作粗略参考；② 海外 LAX 出口，**国内口径未取得**；③ 硬伤 3 的污染未排除前，方向性优势可能部分来自 cookie 历史而非引擎。
- 局限 2 里"不排除 IP 信誉漂移"可以**降级**：交错设计下两侧在同一分钟级窗口交替，后半程（10:27 后）CEF 8/9、Chrome 3/9，漂移是共同变量，不构成偏袒某一侧的机制。

## 四、判定与要求

- 本轮：**⚠️ 有条件通过**。CF 对照方法与数据可继续用，但 §4.4 三处措辞必须订正，且**不得据此判定 M3 的 CF 关口成立**（关口 = 「CEF ≥ 同口径真 Chrome」，需国内口径 + 无污染复采）。
- 待补：① frame 遍历探针重采；② 词表统一；③ `clearBrowserCookies` 生效性实验（CEF 侧）；④ CEF 用独立临时 profile 重跑一轮；⑤ §1.2 指纹五项/brands 重采（仍欠）。
- 流程铁律新增（已写 WORKBOARD）：**CF 实站采样期间锁定排他**——单一 CEF 实例、禁并发起实例、采样前后各记一次被测二进制 mtime/HEAD，写进 meta。两个 agent 共用脏工作区与共用 `target/` 是当前最大的数据可信度威胁。
